## **ЭКЗАМЕНАЦИОННЫЙ ОТВЕТ: Протокол FTP (File Transfer Protocol)**

## **1. ОПРЕДЕЛЕНИЕ И НАЗНАЧЕНИЕ FTP**

**FTP (File Transfer Protocol)** — это протокол прикладного уровня для передачи файлов. FTP используется для обмена файлами между компьютерами в сети, обеспечивая надежную и эффективную передачу данных по протоколу TCP.

## **Основные характеристики FTP**

|Характеристика|Описание|
|---|---|
|**Уровень сети**|Протокол прикладного уровня|
|**Порт для команд**|Порт 21|
|**Порт для передачи данных**|Порт 20|
|**Транспортный протокол**|TCP (протокол надежной доставки)|
|**Архитектура**|Клиент-серверная[timeweb][1]|
|**Безопасность**|Небезопасен из-за отсутствия шифрования|
|**Применение**|Передача файлов по сети, обновление веб-сайтов, резервное копирование|

---

## **2. АРХИТЕКТУРА FTP**

## **Двухканальная архитектура**

FTP отличается от других протоколов (например, HTTP) своей **двухканальной архитектурой**:[sky][2]

1. **Канал управления (Control Channel)**

 - Порт 21

 - Используется для отправки команд и получения ответов

 - Остается открытым на протяжении всей сессии[timeweb][1]

 - Постоянное соединение TCP

2. **Канал данных (Data Channel)**

 - Порт 20 (в активном режиме)

 - Порты > 1024 (в пассивном режиме)

 - Используется для передачи файлов

 - Открывается и закрывается для каждой операции передачи

## **Преимущество двухканальной архитектуры**

Разделение управления и передачи данных позволяет управлять процессом передачи независимо от самих данных.[sky][2]

## **3. РЕЖИМЫ РАБОТЫ FTP**

FTP работает в двух основных режимах, различающихся направлением инициирования соединения для передачи данных:[wikipedia+1][3]

## **АКТИВНЫЙ РЕЖИМ (Active Mode)**

**Принцип работы**:[vps+1][4]

1. Клиент подключается к серверу на **порт 21** (управляющее соединение)

2. Клиент создает временный порт в диапазоне **1024-65535** для приема данных

3. Клиент отправляет серверу команду **PORT N+1**, указывая:

 - Свой IP-адрес

 - Номер порта для передачи данных

4. **Сервер инициирует соединение** с клиентом на указанный порт с **порта 20**

5. Происходит передача файлов

**Диаграмма активного режима**:[vps][4]

```
Клиент Сервер
 ↓ ↓
 +----(управление, порт 21)---→ :21
 ←----(ответ)---------------←
 ↑ (слушает порт 1037)
 | +----← (соединение данных, порт 20)
 | ↓ (порт 1037)
 +----(данные)---->

```

**Проблемы активного режима**:[vps+1][4]

- Если клиент находится за брандмауэром или NAT, входящие соединения от сервера блокируются

- Невозможна передача файлов через некоторые файрволы

- Требует открытия входящих портов на клиентской стороне

---

## **ПАССИВНЫЙ РЕЖИМ (Passive Mode)**

**Принцип работы**:[interface31+1][5]

1. Клиент подключается к серверу на **порт 21** (управляющее соединение)

2. Клиент отправляет серверу команду **PASV**

3. **Сервер отвечает** с указанием:

 - Своего IP-адреса

 - Номера порта для передачи данных (обычно в диапазоне 1024-65535)

4. **Клиент инициирует соединение** с сервером на указанный порт

5. Происходит передача файлов

**Диаграмма пассивного режима**:[vps][4]

```text
Клиент Сервер
 ↓ ↓
 +----(управление, порт 21)---→ :21
 ←----(ответ)---------------←
 |
 +----(соединение данных)---→ :2024
 ←----(данные)---------------←

```

**Преимущества пассивного режима**:[interface31+1][5]

- Все соединения инициирует клиент

- Клиент может находиться за NAT и брандмауэром

- Клиент не требует выделенного IP-адреса

- **Основной режим работы FTP в современных условиях**[interface31][5]

## **Сравнение режимов**

|Аспект|Активный режим|Пассивный режим|
|---|---|---|
|**Инициатор соединения данных**|Сервер|Клиент|
|**Порт сервера для данных**|Порт 20|Случайный (> 1024)|
|**Требует NAT/брандмауэр**|Нет|Да|
|**Клиент за брандмауэром**|Проблематично|Работает|
|**Современное использование**|Редко|Часто|

---

## **4. РЕЖИМЫ ПЕРЕДАЧИ ДАННЫХ**

FTP поддерживает несколько режимов передачи данных:[wikipedia][3]

|Режим|Описание|
|---|---|
|**Поточный режим (Stream Mode)**|Данные посылаются в виде непрерывного потока; TCP выполняет всю обработку; индикатор конца файла не требуется[wikipedia][3]|
|**Блочный режим (Block Mode)**|FTP разбивает данные на блоки (блок заголовка, количество байт, поле данных) и передает их TCP[wikipedia][3]|
|**Сжатый режим (Compressed Mode)**|Данные сжимаются перед передачей для уменьшения объема|

## **5. ОСНОВНЫЕ КОМАНДЫ FTP**

Клиент отправляет команды на сервер через канал управления:[timeweb+1][1]

|Команда|Назначение|
|---|---|
|**USER**|Отправка имени пользователя|
|**PASS**|Отправка пароля|
|**PWD**|Вывод текущего каталога на сервере|
|**CWD**|Изменение текущего каталога|
|**LIST**|Вывод списка файлов в текущем каталоге|
|**RETR**|Загрузка файла с сервера|
|**STOR**|Загрузка файла на сервер|
|**DELE**|Удаление файла на сервере|
|**MKD**|Создание нового каталога|
|**RMD**|Удаление каталога|
|**PASV**|Переход в пассивный режим|
|**PORT**|Указание активного режима и порта|
|**QUIT**|Завершение сессии|

## **6. ПРОЦЕСС РАБОТЫ FTP**

Типичная сессия FTP включает следующие этапы:[timeweb+1][1]

1. **Подключение** — клиент подключается к серверу на порт 21

2. **Аутентификация** — отправка логина (USER) и пароля (PASS)

 - Возможен анонимный доступ (login: anonymous, password: email)

3. **Навигация** — просмотр и изменение каталогов (PWD, CWD, LIST)

4. **Установка параметров** — выбор режима передачи (бинарный/текстовый)

5. **Открытие соединения данных** — активный или пассивный режим

6. **Передача файла** — загрузка (RETR) или скачивание (STOR)

7. **Закрытие соединения данных** — разрыв соединения

8. **Повторение шагов 4-7** — для других файлов при необходимости

9. **Завершение сессии** — команда QUIT

## **7. БЕЗОПАСНОСТЬ FTP**

## **Проблемы безопасности FTP**

**FTP является небезопасным протоколом** по следующим причинам:

|Проблема|Описание|
|---|---|
|**Отсутствие шифрования**|Данные передаются в открытом виде[robotdreams][6]|
|**Видимые учетные данные**|Логин и пароль передаются в открытом виде[seo][7]|
|**Уязвимость MITM**|Возможна атака "Man-in-the-Middle" — перехват трафика[robotdreams][6]|
|**Отсутствие аутентификации**|Нет верификации подлинности сервера[seo][7]|
|**Целостность данных**|Нет проверки целостности передаваемых данных|

## **8. БЕЗОПАСНЫЕ АЛЬТЕРНАТИВЫ FTP**

## **FTPS (FTP + SSL/TLS)**

**Определение:** FTP с протоколом безопасности SSL/TLS[seo][7]

|Характеристика|Описание|
|---|---|
|**Шифрование**|Использует SSL/TLS для защиты данных[seo][7]|
|**Сертификаты**|Требует сертификат безопасности[seo][7]|
|**Порты**|Обычно порт 990 (FTPS) или 21 с STARTTLS|
|**Архитектура**|Два потока (управляющий и данные)[robotdreams][6]|
|**Скорость**|Может быть быстрее SFTP благодаря двум потокам[robotdreams][6]|
|**Использование**|Только где нет поддержки SSH[robotdreams][6]|

**Преимущества FTPS:**

- Сохраняет архитектуру FTP

- Добавляет шифрование

**Недостатки FTPS:**

- Сложнее в настройке, чем SFTP

- Сейчас редко используется[robotdreams][6]

---

## **SFTP (SSH File Transfer Protocol)**

**Определение:** Защищённая версия FTP, работающая по протоколу SSH[hostragons+1][8]

|Характеристика|Описание|
|---|---|
|**Шифрование**|Шифрует все данные и команды по умолчанию[hostragons][8]|
|**Аутентификация**|Поддерживает пароли и ключи SSH[hostragons][8]|
|**Архитектура**|Один поток (в отличие от FTP с двумя потоками)[robotdreams][6]|
|**Безопасность**|Гибче с точки зрения поддерживаемых шифров[robotdreams][6]|
|**Порт**|Обычно порт 22 (как SSH)|
|**Целостность данных**|Гарантирует целостность и конфиденциальность[hostragons][8]|

**Преимущества SFTP:**

- **Шифрование по умолчанию** — все данные, включая пароли, защищены[hostragons][8]

- Защита от MITM атак[hostragons][8]

- Более гибкая с точки зрения шифров

- Современный стандарт для передачи файлов[hostragons][8]

**Недостатки SFTP:**

- Немного медленнее, чем FTPS, благодаря одному потоку[robotdreams][6]

## **Сравнение FTP, FTPS и SFTP**

|Аспект|FTP|FTPS|SFTP|
|---|---|---|---|
|**Шифрование**|Нет|Да (SSL/TLS)|Да (SSH)|
|**Защита данных**|Отсутствует|Наличествует|Наличествует|
|**Аутентификация**|Пароль (открыто)|Пароль + сертификат|Пароль + SSH ключи|
|**Безопасность**|Низкая|Средняя|Высокая|
|**Скорость**|Быстро|Быстрее|Немного медленнее|
|**Современность**|Устарел|Редко используется|Рекомендуется|
|**Порты**|21, 20|990|22|

## **9. ИСПОЛЬЗОВАНИЕ FTP**

**Где используется FTP:**

- Загрузка веб-сайтов на хостинг

- Резервное копирование файлов

- Обмен большими файлами между компьютерами

- Управление файловой структурой сервера

- Программное обеспечение для синхронизации файлов

**Где НЕ рекомендуется использовать FTP:**

- Передача конфиденциальных данных

- Доступ через публичные сети (интернет)

- Системы с высокими требованиями безопасности

**Рекомендация:** Вместо FTP используйте **SFTP** или **FTPS** для защиты данных.[hostragons][8]

## **Заключение**

FTP (File Transfer Protocol) — это классический протокол прикладного уровня для передачи файлов в сети. Он работает по схеме клиент-сервер с использованием двух каналов: управляющего (порт 21) и канала данных (порт 20). FTP поддерживает два режима работы: активный и пассивный, причем пассивный режим предпочтителен в современных сетях из-за его совместимости с NAT и брандмауэрами.

Однако **FTP небезопасен** из-за отсутствия шифрования, поэтому в настоящее время рекомендуется использовать его безопасные альтернативы: **SFTP** (более безопасная, современная) или **FTPS** (реже используется). Для критичных операций с передачей данных следует выбирать SFTP, который обеспечивает полное шифрование и надежную аутентификацию.
