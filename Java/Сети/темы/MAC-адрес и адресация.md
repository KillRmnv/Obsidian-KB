# MAC-адрес. Адресация на канальном уровне

## Связанные темы

- [[Канальный уровень модели OSI]]

**MAC-адрес (Media Access Control address)** — это уникальный **физический адрес** сетевого устройства, работающий на **канальном уровне (Layer 2)** модели OSI.[baeldung+1][1]

MAC-адрес используется для идентификации устройств в пределах **одного локального сегмента сети** (LAN) и обеспечивает доставку кадров Ethernet между непосредственно соединенными узлами.

---

## 1. Структура MAC-адреса

## 1.1. Общие характеристики[secureideas+2][2]

**Размер:** 48 бит (6 байт)[synchronet+1][3]

**Запись:** Обычно записывается в **шестнадцатеричном формате**, разделенным:

- **Двоеточием:** 00:1A:2B:3C:4D:5E (стандарт Unix/Linux)[synchronet][3]

- **Дефисом:** 00-1A-2B-3C-4D-5E (стандарт Windows)[synchronet][3]

- **Точкой:** 0011.2233.4455 (формат Cisco)[synchronet][3]

Все три формата представляют один и тот же MAC-адрес.

## 1.2. Две части MAC-адреса[linkedin+3][4]

MAC-адрес состоит из двух частей по 24 бита (3 байта) каждая:

## 1) OUI (Organizationally Unique Identifier)[wikipedia+3][5]

**OUI** — первые 3 байта (24 бита) MAC-адреса.[secureideas+1][2]

**Назначение:** Уникальный идентификатор организации, которая изготовила сетевую карту.[secureideas+1][2]

**Кто выдает:** IEEE (Institute of Electrical and Electronics Engineers).[linkedin+2][4]

**Пример:**[secureideas+1][2]

- MAC-адрес: **A0:91:A2**:01:02:03

- OUI: **A0:91:A2** (принадлежит компании OnePlus)[secureideas][2]

- Другие примеры OUI:

 - **FC:A6:67** — Apple (iPhone, MacBook)[synchronet][3]

 - **00:17:10** — Cisco (маршрутизаторы, коммутаторы)[synchronet][3]

 - **38:2C:4A** — Samsung (смартфоны, телевизоры)[synchronet][3]

**Польза OUI:** Позволяет идентифицировать производителя устройства по MAC-адресу, что полезно для:

- Инвентаризации сети.[secureideas][2]

- Обнаружения несанкционированных устройств.[secureideas][2]

- Диагностики проблем.[secureideas][2]

## 2) NIC-specific / Device Identifier (Идентификатор устройства)[linkedin+1][4]

**Вторая часть** — последние 3 байта (24 бита) MAC-адреса.[linkedin+1][4]

**Назначение:** Уникальный серийный номер, назначаемый **производителем** конкретному сетевому интерфейсу.[linkedin+1][4]

**Пример:**

- MAC-адрес: A0:91:A2:**01:02:03**

- Device Identifier: **01:02:03**

**Комбинация OUI + Device ID** обеспечивает глобальную уникальность каждого MAC-адреса в мире.[linkedin+1][4]

## 1.3. Специальные биты первого октета[networkacademy+3][6]

Первый байт (октет) MAC-адреса содержит два важных бита, определяющих тип адреса:

text

`Первый байт (8 бит): [b7 b6 b5 b4 b3 b2 b1 b0] ↑ ↑ MSB LSB`

## Бит 0 (LSB) — I/G бит (Individual/Group)[reddit+1][7]

**Least Significant Bit (LSB)** — младший (самый правый) бит первого октета.

**Назначение:** Определяет, является ли адрес **индивидуальным (unicast)** или **групповым (multicast/broadcast)**.[networkacademy+1][6]

- **Бит 0 = 0:** **Unicast** (индивидуальный адрес) — кадр предназначен **одному** устройству.[reddit+1][7]

- **Бит 0 = 1:** **Multicast/Broadcast** (групповой адрес) — кадр предназначен **группе** устройств или **всем** устройствам.[networkacademy+1][6]

**Пример:**

- MAC **4A**:30:10:19:10:1A

 - 4A в двоичном: **0100 1010**

 - LSB (бит 0) = **0** → Unicast

- MAC **4B**:30:10:19:10:1A

 - 4B в двоичном: **0100 1011**

 - LSB (бит 0) = **1** → Multicast

## Бит 1 — U/L бит (Universal/Local)[packetsdropped.wordpress+2][8]

**Second bit** — второй бит первого октета.[baeldung+2][1]

**Назначение:** Определяет, является ли адрес **универсальным (заводским)** или **локально назначенным (измененным)**.[packetsdropped.wordpress+2][8]

- **Бит 1 = 0:** **Universally Administered Address (UAA)** — адрес, назначенный производителем (BIA — Burned-In Address).[baeldung+2][1]

- **Бит 1 = 1:** **Locally Administered Address (LAA)** — адрес изменен программно администратором или операционной системой.[reddit+2][7]

**Применение LAA:**[packetsdropped.wordpress][8]

- Изменение MAC-адреса для влияния на хеширование в LACP (Link Aggregation).

- Создание схемы MAC-адресов для упрощения идентификации трафика.

- Обход ограничений провайдера (MAC-фильтрация).

## 2. Типы MAC-адресов

Согласно лекции и стандартам IEEE, существуют три типа MAC-адресов:+1​[networkacademy][6]

## 2.1. Unicast (Одноадресная рассылка)[networkacademy][6]

**Определение:** Кадр предназначен **одному конкретному** получателю.[networkacademy][6]

**Признак:** Бит 0 первого октета = **0**.[networkacademy][6]

**Пример:** 00:1A:2B:3C:4D:5E

**Поведение сети:**[networkacademy][6]

- **Коммутатор (L2 switch):** Пересылает кадр **только в порт**, где находится устройство с данным MAC-адресом (согласно таблице MAC-адресов).[networkacademy][6]

- Если MAC неизвестен коммутатору, выполняется **flooding** (рассылка во все порты, кроме источника).[networkacademy][6]

- **Маршрутизатор (L3):** Пересылает пакет согласно таблице маршрутизации.[networkacademy][6]

**Применение:** Обычная передача данных между двумя устройствами (например, компьютер → сервер).[networkacademy][6]

---

## 2.2. Multicast (Многоадресная рассылка)[networkacademy][6]

**Определение:** Кадр предназначен **группе устройств**, зарегистрированных для получения определенного потока данных.[networkacademy][6]

**Признак:** Бит 0 первого октета = **1**.[networkacademy][6]

**Назначение из лекции:**
Несколько устройств хотят получить одну и ту же информацию (видеопоток, аудиопоток). Отправитель посылает только **одну копию** данных на multicast-адрес вместо отправки отдельных копий каждому устройству (экономия пропускной способности).

## Структура Multicast MAC-адресов[reddit+1][7]

**Для IPv4:**

- Начинается с **01-00-5E**[reddit][7]

- Остальная часть (последние 23 бита) формируется преобразованием IPv4 multicast-адреса (224.0.0.0–239.255.255.255).

- **Диапазон:** 01:00:5E:00:00:00 — 01:00:5E:7F:FF:FF[networkacademy][6]

**Для IPv6:**

- Начинается с **33-33-00**

- Остальная часть (последние 24 бита) формируется преобразованием IPv6 multicast-адреса.

- **Диапазон:** 33:33:00:00:00:00 — 33:33:FF:FF:FF:FF[networkacademy][6]

**Важно:**

- Multicast MAC-адрес может использоваться **только как адрес назначения**.

- Если коммутатор обнаружит multicast-адрес в поле **Source MAC**, такой кадр будет **отброшен**.

**Поведение сети:**[networkacademy][6]

- **Коммутатор:** Обрабатывает multicast-трафик на основе протоколов управления multicast (IGMP Snooping, MLD).[networkacademy][6]

- Без специальной настройки коммутатор может рассылать multicast как broadcast (flooding).[networkacademy][6]

**Применение:**

- IPTV (потоковое видео).

- Видеоконференции.

- Протоколы маршрутизации (OSPF, EIGRP).

- Обнаружение сервисов (mDNS, SSDP).

---

## 2.3. Broadcast (Широковещательная рассылка)+1​[networkacademy][6]

**Определение:** Кадр предназначен **всем устройствам** в локальной сети.[networkacademy][6]

**MAC-адрес широковещания:** **FF:FF:FF:FF:FF:FF**+1​[networkacademy][6]

Состоит из **всех единиц** (в двоичном виде: 1111 1111:1111 1111:1111 1111:1111 1111:1111 1111:1111 1111).

**Признак:** Все биты = 1 (технически бит 0 первого октета также = 1, что делает его подтипом multicast).[networkacademy][6]

**Поведение сети:**[networkacademy][6]

- **Коммутатор:** Пересылает broadcast-кадр **во все порты** в пределах одного VLAN, кроме порта-источника.[study-ccna+1][9]

- **Маршрутизатор:** **Не пересылает** broadcast-кадры между подсетями (разделяет broadcast-домены).[baeldung+1][10]

**Применение:**[networkacademy][6]

- **ARP-запросы** (Address Resolution Protocol) — поиск MAC-адреса по известному IP.

- **DHCP Discovery** — поиск DHCP-сервера.

- **NetBIOS Name Resolution** (устаревшее).

**Проблема:** Избыточные broadcast-кадры создают **broadcast storm** (широковещательный шторм), который может перегрузить сеть.

|Тип|MAC-адрес (пример)|Бит 0 (LSB)|Получатели|Как обрабатывает коммутатор|
|---|---|---|---|---|
|**Unicast**|00:1A:2B:3C:4D:5E|0|Одно устройство|Пересылает в конкретный порт (или flooding, если MAC неизвестен)|
|**Multicast (IPv4)**|01:00:5E:7F:00:01|1|Группа устройств|Обрабатывает через IGMP Snooping или flooding|

|**Broadcast**|FF:FF:FF:FF:FF:FF|1 (все биты = 1)|Все устройства в VLAN|Пересылает во все порты (кроме источника)|

## 4. Роль MAC-адресов в сети

## 4.1. Взаимодействие с IP-адресами

**IP-адрес (Layer 3)** и **MAC-адрес (Layer 2)** выполняют разные функции:

- **IP-адрес:** Используется для **логической адресации** и **маршрутизации между сетями** (end-to-end доставка).

- **MAC-адрес:** Используется для **физической доставки** кадра в пределах одного локального сегмента (hop-by-hop доставка).

## 4.2. ARP (Address Resolution Protocol)

**Назначение:** Определяет **MAC-адрес** по известному **IP-адресу**.

**Процесс:**

1. Устройство А хочет отправить данные устройству Б (знает IP Б, но не знает MAC Б).

2. А отправляет **ARP-запрос** (broadcast): "Кто имеет IP-адрес X.X.X.X? Сообщите мне ваш MAC."

3. Устройство Б отвечает **ARP-ответом** (unicast): "Это мой IP, мой MAC — YY:YY:YY:YY:YY:YY."

4. А сохраняет запись в **ARP-таблице** (кеш) и отправляет кадр с MAC-адресом Б.

## 5. MAC-адреса в работе коммутатора

Согласно лекции, коммутатор строит **таблицу MAC-адресов** (CAM-таблицу):

|№ порта|MAC-адрес устройства|VLAN|
|---|---|---|
|1|00:1A:2B:3C:4D:5E|1|
|2|00:1F:3A:4B:5C:6D|1|
|3|00:2E:4F:5A:6B:7C|2|

**Процесс обучения (MAC learning):**

1. Коммутатор получает кадр на порту X.

2. Смотрит **Source MAC** в кадре.

3. Если этот MAC отсутствует в таблице, добавляет запись: "MAC → порт X".

4. Смотрит **Destination MAC** в кадре:

 - Если MAC есть в таблице → пересылает кадр в соответствующий порт (**фильтрация**).

 - Если MAC неизвестен → **flooding** (рассылка во все порты, кроме источника).

---

## Заключение

**MAC-адрес** — это фундаментальная концепция канального уровня, обеспечивающая физическую адресацию в локальных сетях. Понимание структуры MAC-адреса (OUI + Device ID), типов адресов (unicast, multicast, broadcast) и специальных битов (I/G, U/L) критически важно для администрирования сетей, диагностики проблем и понимания работы коммутаторов. Взаимодействие MAC-адресов с IP-адресами через протокол ARP обеспечивает бесшовную работу многоуровневой модели OSI.
