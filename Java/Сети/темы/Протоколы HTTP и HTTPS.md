 ## **ЭКЗАМЕНАЦИОННЫЙ ОТВЕТ: HTTP, HTTPS, методы и версии HTTP**

## **1. ПРОТОКОЛ HTTP (HyperText Transfer Protocol)**

## **Определение и назначение**

HTTP (HyperText Transfer Protocol) — это семейство протоколов запроса/ответа прикладного уровня без учета состояния, которые используют общий интерфейс, расширяемую семантику и самоописательные сообщения для обеспечения гибкого взаимодействия с сетевыми гипертекстовыми информационными системами. Это основной протокол для передачи веб-страниц и данных в интернете.

## **Основные характеристики HTTP**

|Характеристика|Описание|
|---|---|
|**Уровень сети**|Протокол прикладного уровня|
|**Порт**|Порт 80|
|**Модель взаимодействия**|Клиент-серверная архитектура|
|**Транспортный протокол**|TCP (в HTTP/3 используется QUIC)|
|**Состояние**|Протокол без состояния (stateless) — каждый запрос независим|
|**Безопасность**|Данные передаются в открытом виде без шифрования|

## **Принцип работы HTTP**

Клиент-серверное взаимодействие происходит следующим образом:

1. Браузер (HTTP-клиент) инициализирует TCP-соединение с сервером (создает сокет)

2. Сервер принимает TCP-соединение от клиента

3. Браузер и веб-сервер обмениваются сообщениями прикладного уровня

4. TCP-соединение закрывается

## **2. ПРОТОКОЛ HTTPS (HyperText Transfer Protocol Secure)**

## **Определение**

HTTPS (HyperText Transfer Protocol Secure) — это расширение протокола HTTP, объединяющее HTTP и криптографические протоколы SSL/TLS. HTTPS обеспечивает защищенную передачу данных путем шифрования информации между браузером и сервером.[habr][1]

## **Как работает HTTPS**

HTTPS использует следующий механизм защиты:[webtronics+1][2]

1. **Процесс рукопожатия (TLS Handshake)** — проверяется подлинность сервера и согласовываются параметры шифрования[habr][1]

2. **Обмен ключами** — клиент получает публичный ключ сервера и генерирует секретный ключ[webtronics][2]

3. **Шифрование данных** — все данные, включая URL, HTTP-заголовки и тело запроса/ответа, шифруются с использованием симметричного ключа[webtronics][2]

4. **Дешифрование** — получатель расшифровывает данные с помощью того же ключа[webtronics][2]

## **Основные характеристики HTTPS**

|Характеристика|Описание|
|---|---|
|**Порт**|Порт 443|
|**Шифрование**|SSL/TLS протоколы обеспечивают криптографическую защиту|
|**Требование TLS**|Современные браузеры требуют TLS 1.2 или TLS 1.3[proselyte][3]|
|**Аутентификация**|Цифровой сертификат подтверждает подлинность сервера[webtronics][2]|
|**Целостность данных**|Гарантирует, что данные не были изменены во время передачи[webtronics][2]|

## **3. СРАВНЕНИЕ HTTP и HTTPS**

|Аспект|HTTP|HTTPS|
|---|---|---|
|**Безопасность**|Данные передаются в открытом виде[hexlet][4]|Данные зашифрованы с помощью SSL/TLS[webtronics][2]|
|**Шифрование**|Отсутствует[hexlet][4]|Встроенный механизм шифрования[webtronics][2]|
|**Проверка подлинности**|Не предусмотрена[webtronics][2]|Подтверждение подлинности через сертификаты[webtronics][2]|
|**Уязвимость**|Подвергается атакам перехвата MITM (Man-in-the-Middle)[webtronics][2]|Защищен от MITM атак[habr][1]|
|**Порт**|Порт 80|Порт 443[timeweb][5]|
|**Скорость**|Более быстрый[webtronics][2]|Немного медленнее из-за шифрования[webtronics][2]|
|**SEO**|Поисковые системы отдают меньше приоритета|Поисковые системы отдают приоритет HTTPS сайтам[webtronics][2]|
|**Использование**|Не рекомендуется для передачи конфиденциальных данных|Обязателен для передачи паролей, номеров карт[webtronics][2]|

## **Преимущества HTTPS**

- **Конфиденциальность** — все данные зашифрованы, предотвращая их перехват[webtronics][2]

- **Целостность** — гарантирует, что данные не были изменены или подделаны[webtronics][2]

- **Аутентификация** — клиенты могут убедиться в том, что они общаются с настоящим сервером[webtronics][2]

- **Доверие пользователей** — наличие замка в адресной строке повышает доверие к сайту[timeweb][5]

- **SEO-преимущества** — поисковые системы отдают предпочтение HTTPS сайтам[webtronics][2]

## **4. МЕТОДЫ HTTP ЗАПРОСА**

HTTP-методы определяют действие, которое должна выполнить сервер. Существует несколько основных методов, которые поддерживаются в разных версиях HTTP.

## **Методы по версиям HTTP**

**HTTP/0.9:**

- **GET** — запрос ресурса

**HTTP/1.0:**

- **GET** — запрос ресурса

- **POST** — отправка данных на сервер

- **HEAD** — получение заголовков GET без тела сообщения

**HTTP/1.1, HTTP/2, HTTP/3:**

- **GET** — запрос ресурса

- **POST** — отправка данных на сервер

- **HEAD** — получение заголовков без тела

- **PUT** — создание или замена ресурса по указанному URL

- **DELETE** — удаление ресурса

- **OPTIONS** — запрос списка ожидаемых методов сервера

- **TRACE** — для диагностики

- **CONNECT** — создание TCP-туннеля

- **PATCH** — частичное изменение ресурса

## **Детальное описание основных методов**

**GET-запрос**

- Используется для запроса данных с сервера

- Данные передаются в URL, видны в адресной строке[hexlet][6]

- Безопасен, идемпотентен (повторные запросы дают одинаковый результат)

- Не должен содержать тело сообщения

- Кэшируется браузером

**POST-запрос**

- Используется для отправки данных на сервер

- Данные передаются в теле сообщения (не видны в URL)[hexlet][6]

- Не кэшируется по умолчанию

- Может менять состояние сервера

- Не идемпотентен (повторные запросы могут дать разные результаты)

**PUT-запрос**

- Используется для создания или замены ресурса по указанному URL

- Идемпотентен — повторное выполнение не меняет результат[hexlet][6]

- Требует полное тело ресурса для замены

**DELETE-запрос**

- Используется для удаления ресурса

- Идемпотентен — повторное удаление уже удаленного ресурса не меняет состояние системы[sky+1][7]

- Обычно возвращает код состояния 204 (No Content)[sky][7]

- При повторном запросе может вернуть 404 (Not Found)[nodul][8]

**PATCH-запрос**

- Используется для частичного изменения ресурса

- Отличается от PUT тем, что требует только измененные поля, а не полный ресурс[hexlet][6]

**HEAD-запрос**

- Аналогичен GET, но сервер возвращает только заголовки без тела сообщения

- Используется для проверки существования ресурса или получения метаинформации

**OPTIONS-запрос**

- Запрашивает список ожидаемых методов сервера

- Позволяет клиенту узнать, какие операции поддерживает сервер

## **5. ВЕРСИИ HTTP**

## **HTTP/0.9**

- Первая версия HTTP (1991)

- Поддерживал только метод GET

- Очень простая структура

- Сейчас полностью устарел

## **HTTP/1.0**

- Выпущена в 1996 году

- Добавлены методы POST и HEAD

- Каждый запрос требует отдельного TCP-соединения

- Отсутствует кэширование

- Требует 2 RTT на один объект

- Медленная для современных приложений

## **HTTP/1.1**

- Выпущена в 1997/1999 годах[proselyte][3]

- Основная версия интернета в течение 20+ лет[proselyte][3]

- Добавлены методы PUT, DELETE, OPTIONS, TRACE, CONNECT, PATCH

- **Постоянные соединения** — одно соединение может использоваться для нескольких объектов

- Требует 1 RTT на один объект

- Текстовый формат сообщений (ASCII)[proselyte][3]

- Множественные TCP-соединения для параллелизма (обычно 4-8 на хост)[proselyte][3]

## **HTTP/2**

- Выпущена в 2015 году[proselyte][3]

- Большое улучшение производительности

- **Ключевые особенности**:[proselyte][3]

|Особенность|Описание|
|---|---|
|**Бинарный фрейминг**|Вместо текстового формата используется бинарный для более эффективной обработки[proselyte][3]|
|**Мультиплексирование**|Полное мультиплексирование — несколько потоков запросов/ответов в одном соединении без блокировки друг друга[proselyte][3]|
|**Сжатие заголовков**|Заголовки сжимаются алгоритмом HPACK; повторяющиеся поля передаются как ссылки[proselyte][3]|
|**Server Push**|Сервер может отправить дополнительные ресурсы проактивно без отдельного запроса[proselyte][3]|
|**Приоритизация**|Клиент может присвоить потокам веса и зависимости для оптимизации загрузки[proselyte][3]|
|**Одно TCP-соединение**|Все запросы работают через одно длительное соединение[proselyte][3]|
|**Требование TLS**|Почти всегда используется с TLS/HTTPS; браузеры не поддерживают незашифрованный HTTP/2[proselyte][3]|
|**Требование TLS версии**|Требует TLS 1.2 или TLS 1.3[proselyte][3]|

**Преимущества HTTP/2:**

- Значительное улучшение производительности[proselyte][3]

- Уменьшение задержек при загрузке веб-страниц

- Меньше накладных расходов на установление соединений

**Недостатки HTTP/2:**

- Требует обновления инфраструктуры (прокси, балансировщиков)[proselyte][3]

- Многие старые оптимизации HTTP/1.1 становятся неэффективными[proselyte][3]

## **HTTP/3**

- Выпущена в 2022 году (стандартизирована в RFC 9114)[temofeev][9]

- Используется с протоколом QUIC вместо TCP[temofeev][9]

- **Ключевые улучшения**:[temofeev][9]

 - Одно рукопожатие вместо множественных для установления соединения и шифрования[temofeev][9]

 - Сохранение соединения при изменении сетей (например, при переходе с WiFi на мобильную сеть)[temofeev][9]

 - Не требует повторных рукопожатий при разрыве соединения благодаря уникальному идентификатору соединения[temofeev][9]

 - Улучшенная обработка потери пакетов

## **6. КОДЫ СОСТОЯНИЯ HTTP ОТВЕТА**

Коды состояния указывают на результат обработки HTTP-запроса:

|Группа|Описание|Примеры|
|---|---|---|
|**1xx**|Информационные ответы|-|
|**2xx**|Успешные ответы|200 — успешное выполнение запроса|
|**3xx**|Сообщения о перенаправлении|301, 302 — перенаправление на другой адрес|
|**4xx**|Ошибки клиента|403 — недостаточно прав, 404 — ресурс не найден|
|**5xx**|Ошибки сервера|500 — общая ошибка сервера, 505 — версия HTTP не поддерживается|

## **7. HTTP-СОЕДИНЕНИЯ**

Существуют два типа HTTP-соединений:

## **Постоянные соединения**

- Через одно соединение клиент-сервер может отправить несколько объектов

- Требует 1 RTT на один объект

- После отправки ответа сервер оставляет соединение открытым

- Клиент отправит запрос как только встретит содержащий ссылку объект

- Более эффективны для загрузки нескольких ресурсов

## **Непостоянные соединения**

- Один объект — одно соединение

- Требуется 2 RTT на один объект

- Нагрузка на ОС для каждого нового соединения

- Браузеры часто открывают параллельные TCP-соединения для извлечения объектов по ссылке

_(RTT — Round Trip Time — время прохождения пути от клиента до сервера и обратно для небольшого пакета)_

## **10. БЕЗОПАСНОСТЬ И SSL/TLS**

**SSL (Secure Socket Layer)**

- Предшественник TLS

- Устарел и больше не рекомендуется использовать

**TLS (Transport Layer Security)**

- Современный стандарт криптографической защиты[webtronics][2]

- Обеспечивает конфиденциальность, целостность и аутентификацию[webtronics][2]

- Версия 1.2 или выше требуется для современных браузеров[proselyte][3]

---

## **Заключение**

HTTP — это основной протокол веб-приложений, который претерпел значительную эволюцию от версии 0.9 к HTTP/3. HTTPS обеспечивает безопасность через шифрование SSL/TLS. Выбор версии HTTP зависит от требований приложения, но HTTP/2 и HTTP/3 предпочтительны для современных веб-приложений благодаря их производительности и встроенным механизмам безопасности.
