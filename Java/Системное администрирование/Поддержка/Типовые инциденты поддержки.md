# Типовые инциденты поддержки

Быстрый справочник «пришёл пользователь — что проверить». Для каждого класса инцидента: первые действия, что почти наверняка причина, когда эскалировать. Подробная теория — в соседних заметках, здесь именно порядок действий на линии.

## Первый контакт: 60 секунд

1. Кто и где (ФИО, кабинет, ПК, учётка).
2. Что не работает и с какого момента; что менялось вчера/сегодня.
3. Один пользователь или несколько (это сразу делит инцидент на «локальный» и «массовый»).
4. Текст ошибки/скриншот.
5. Есть ли обходной путь (другой ПК, веб-версия, печать с другого).
6. Зафиксировать в тикете до начала работ.

## Массовый или локальный?

| Признак | Локальный | Массовый |
|---|---|---|
| Затронут один ПК | да | нет |
| Помогает перезагрузка/переподключение | часто | редко |
| Проблема воспроизводится на другом ПК с той же учёткой | нет | да |
| Проблема у коллег в том же кабинете | нет | вероятно сеть/VLAN |

Массовый инцидент → немедленно эскалировать и сообщить руководителю; не пытаться «починить» по одному пользователю.

## Быстрая таблица

| Симптом | Первые проверки | Частая причина | Эскалация |
|---|---|---|---|
| ПК не включается | питание, кабель, кнопка, БП, POST | БП, кнопка, плата | железо/сервис |
| Нет изображения | кабель, вход монитора, RAM, видео | кабель/режим входа | железо |
| Не грузится Windows | WinRE, `bootrec`, `chkdsk`, точка восстановления | загрузчик, диск, обновление | L2 |
| «Всё тормозит» | Task Manager/Resource Monitor, диск 100%, RAM | HDD, мало RAM, автозапуск, malware | L2 |
| Нет сети | `ipconfig /all`, `ping` шлюза, DNS | DHCP, кабель, профиль, DNS | сеть |
| Нет доступа к папке | `whoami /all`, `icacls`, Effective Access | NTFS vs share, группа | AD/файлы |
| Забыл пароль | подтверждение личности, `net user`/AD | обычная процедура | — |
| Учётка заблокирована | Event 4740, источник | сохранённый старый пароль в телефоне/службе | AD |
| Не печатает | тест-страница, статус, спулер, порт | очередь, offline, драйвер | оргтехника/сервис |
| Печать «кракозябрами» | драйвер, язык (PCL/PS) | неверный драйвер | — |
| Не открывается 1С/CRM | доступность сервера, `Test-NetConnection`, лицензии | сервер/сеть/лицензия | L2/L3 |
| Не работает почта | веб-клиент, `ping`, порты 25/443/993, квота | квота, пароль, сеть | почта |
| Медленный Wi-Fi | канал, драйвер, питание адаптера, число клиентов | помехи, драйвер | сеть |
| Шумит/перегревается | температуры, пыль, кулеры | пыль, высохшая термопаста | железо |
| Синий экран | Event 1001, minidump, драйвер | драйвер, память, диск | L2 |

## Удалённая поддержка

- **RDP** — если есть доступ в сеть и включён RDP; лучше через VPN/шлюз, не «проброс 3389 в интернет».
- **AnyDesk/TeamViewer/RustDesk** — когда сети нет; ID + подтверждение пользователя, сессия только с его согласия.
- Перед подключением: предупредить, попросить закрыть личные документы, зафиксировать, что разрешение получено.
- Во время: не открывать лишние окна, комментировать действия, не менять настройки без объяснения.
- После: отключиться, сообщить результат, обновить тикет.

## Что делать, если проблема «не воспроизводится»

1. Зафиксировать условия: время, ПК, учётка, сеть, что открыто.
2. Попросить скриншот/точный текст ошибки.
3. Проверить журналы за это время (`eventvwr`, `Get-WinEvent -StartTime`).
4. Оставить тикет в `Pending`, договориться о следующем контакте.
5. Если повторится — собрать логи сразу (не «перезагрузил и прошло»).

## Типовые «мелочи», которые ценятся

- Проверить свободное место и дату/время (сбитые часы ломают Kerberos и HTTPS).
- Перезагрузить, а не «закрыть-открыть» (обновления и драйверы).
- Проверить, не заменена ли раскладка/язык, не включён ли фильтр клавиш.
- Уточнить, работает ли то же самое под другой учёткой — сразу отделяет профиль от системы.
- Сохранить копию файла перед правкой конфигурации.
- Не менять два параметра одновременно.

## Чек-лист диагностики

1. Определить масштаб: один пользователь / кабинет / все.
2. Собрать симптомы и воспроизвести.
3. Проверить «слои» по порядку: питание → ОС → сеть → сервис → права.
4. Сравнить с эталоном (другой ПК/учётка).
5. Посмотреть журналы и коды ошибок, а не угадывать.
6. Применить минимальное изменение и проверить результат.
7. Зафиксировать причину и решение в тикете и, если типовое, — в базе знаний.
8. Эскалировать с описанием, если вышли за пределы L1.

## Вопросы на собеседовании

**Как отличить проблему пользователя от проблемы сервиса?** Проверить ту же операцию с другой учётки/ПК; если воспроизводится — сервис/права, если нет — локальное окружение.

**Пользователь говорит «интернета нет», а ping проходит. Что дальше?** Проверить DNS (`nslookup`), прокси, конкретный порт/сайт, браузер; «нет интернета» часто значит «не открывается один сайт».

**Какие действия вы сделаете до переустановки Windows?** Диагностика диска/RAM, `sfc`/`DISM`, безопасный режим, откат обновления/драйвера, точка восстановления, сохранение данных.

**Как безопасно подключиться к чужому ПК?** Только с согласия пользователя, через корпоративный инструмент, с фиксацией в тикете; не запрашивать пароль.

**Что важнее: быстро закрыть заявку или найти причину?** Закрыть инцидент можно обходным путём, но повторяемость требует problem и устранения причины.
