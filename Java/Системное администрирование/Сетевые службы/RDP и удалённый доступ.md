# RDP и удалённый доступ

## Проблема: помогать, не бегая по этажам

В компании 40 сотрудников на пяти этажах. Каждый день кто-то не может войти, у кого-то «не печатает», кому-то нужно поставить программу. Если ходить ногами — полдня в пути, а половина проблем решается за две минуты.

Нужно подключаться к чужому рабочему столу по сети. В Windows это **RDP** (Remote Desktop Protocol).

## Пять условий, без которых не заработает

На собеседовании лучше отвечать не «нужно включить RDP», а перечислить условия. Тогда сразу видно понимание.

| Условие | Что значит | Как проверить |
|---|---|---|
| 1. Служба включена | Windows принимает входящие подключения | `sysdm.cpl` → «Удалённый доступ» |
| 2. Порт открыт | 3389/tcp доходит до машины | `Test-NetConnection pc -Port 3389` |
| 3. У пользователя есть право | он в группе Remote Desktop Users или администратор | `whoami /groups`, `Get-LocalGroupMember` |
| 4. Сеть | клиент видит машину (VPN, маршрут, VLAN) | `ping`, `tracert` |
| 5. Учётка подходит | доменная или локальная, пароль верный | `whoami`, Event 4625 |

Если «не подключается» — почти всегда одно из этих пяти. Дальше просто идём по списку, а не гадаем.

## Включение

Через интерфейс: `sysdm.cpl` → «Удалённый доступ» → разрешить подключения.

Через реестр (когда GUI недоступен):

```text
HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server
  fDenyTSConnections = 0   ← 0 разрешает, 1 запрещает
```

Через PowerShell:

```powershell
Set-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server' -Name fDenyTSConnections -Value 0
Enable-NetFirewallRule -DisplayGroup "Remote Desktop"
Add-LocalGroupMember -Group "Remote Desktop Users" -Member "corp\ivanov"
```

## NLA: почему просят пароль до входа

**Network Level Authentication** — проверка учётных данных **до** того, как пользователь увидит экран входа. Это важно по двум причинам:

- до аутентификации не создаётся полноценная сессия, поэтому меньше риск эксплойтов в самом RDP;
- меньше нагрузка на сервер.

Иногда NLA создаёт проблему: старый клиент или неверные учётные данные — и вместо экрана входа сразу ошибка. На сервере NLA включён по умолчанию, и отключать его ради старого клиента — плохая идея.

## Почему в Windows Pro — только один пользователь

RDP в Windows 10/11 Pro/Enterprise — это **один интерактивный сеанс**. Если подключиться к машине, где уже кто-то работает, его сеанс будет отключён (с предупреждением).

Так сделано лицензионно, а не технически. Чтобы многие пользователи работали одновременно на одном сервере, нужна роль **Remote Desktop Services** с лицензиями RDS CAL и сервером лицензий. На L1 достаточно знать: «многопользовательский RDP — это RDS, отдельные лицензии».

## Сессии: кто занял, кого выбило

Подключился, а машина пишет «превышено число подключений» или «сеанс уже существует»:

```text
query user                 :: кто сейчас в системе
logoff 3                   :: завершить сеанс с ID 3
tscon 3 /dest:console      :: вернуть сеанс на физический экран
```

`tscon ... /dest:console` — полезный приём: пользователь ушёл, оставив заблокированный сеанс, а физическая консоль показывает «занято». Это возвращает сеанс на монитор.

## Что ломается в жизни

**«Credentials did not work».** Либо не та учётка (локальная вместо доменной: `PC01\ivanov` vs `corp\ivanov`), либо истёк пароль, либо учётка заблокирована. Смотреть Event 4625 на целевой машине.

**Чёрный экран после входа.** Чаще всего драйвер видео или зависший `explorer.exe`. Иногда помогает `Ctrl+Alt+End` → Task Manager → перезапуск Explorer.

**«Компьютер недоступен».** Не доходит 3389: файрвол, неверный адрес, нет маршрута, машина выключена. `Test-NetConnection -Port 3389` отделяет «сеть» от «RDP».

**Ping идёт, RDP нет.** Файрвол или служба RDP выключена. Ping — ICMP, он ничего не говорит про 3389.

**«Превышено число подключений».** Остался «висящий» сеанс: `query user`, затем `logoff`. В Pro одновременно может быть только один.

## Безопасность: почему 3389 нельзя в интернет

RDP постоянно сканируется ботами. Открытый в интернет 3389 — это попытки подбора пароля круглосуточно и реальные взломы с шифровальщиками.

Что делают вместо этого:

- доступ только через **VPN** или RDP-шлюз;
- MFA для удалённого доступа;
- ограничение по IP;
- сложные пароли и блокировка;
- отдельный сегмент для админского доступа.

Смена порта с 3389 на другой **не является защитой**: сканеры находят RDP не только по порту. Это можно делать «для шума в логах», но не как меру безопасности.

## Когда RDP не подходит

RDP требует, чтобы клиент **дозвонился** до машины. Если пользователь дома за NAT, без VPN, — RDP не сработает. Тогда используют:

| Инструмент | Когда |
|---|---|
| AnyDesk, TeamViewer, RustDesk | пользователь вне корпоративной сети, нужен быстрый доступ |
| VNC | Linux/смешанная среда, простые задачи |
| RMM-системы | парк машин, инвентаризация и удалённые команды |

Важно: любой такой инструмент — это канал управления чужим компьютером. Подключаться только с согласия пользователя и с фиксацией в заявке.

## Чек-лист диагностики

1. Уточнить: не подключается совсем или подключается и выкидывает?
2. `ping` и `Test-NetConnection pc -Port 3389` — есть ли связь и открыт ли порт.
3. На целевой машине: включён ли удалённый доступ, запущена ли служба, не блокирует ли файрвол.
4. Проверить группу Remote Desktop Users и формат логина (`corp\ivanov`).
5. Посмотреть Event 4625: неверный пароль, заблокирована, нет прав.
6. Если «занято» — `query user`, затем `logoff` или `tscon`.
7. Если подключился, но чёрный экран — перезапустить Explorer, проверить драйвер видео.
8. Проверить, не истёк ли пароль и не отключена ли учётка.

## Вопросы на собеседовании

**Что нужно, чтобы RDP заработал?** Включённая служба, открытый 3389, право пользователя (Remote Desktop Users), сеть до машины и корректные учётные данные.

**Чем отличается RDP в Windows Pro от RDS?** В Pro один интерактивный сеанс; RDS — многопользовательский режим с отдельными лицензиями.

**Что такое NLA?** Аутентификация до создания сеанса; снижает риск атак на RDP и нагрузку.

**Как завершить зависший сеанс?** `query user`, затем `logoff <id>`; вернуть на консоль — `tscon <id> /dest:console`.

**Почему смена порта RDP — не защита?** Сканеры определяют RDP по протоколу, а не только по номеру порта; нужен VPN/шлюз, MFA, ограничения.

**Пользователь вне офиса, VPN нет — как помочь?** AnyDesk/TeamViewer/RustDesk с его согласия, либо настроить VPN — это organisational решение, а не техническая хитрость.

## Что запомнить

1. RDP — 3389/tcp, но одного порта мало: нужны служба, права, сеть, учётка.
2. Pro — один сеанс, RDS — много и с лицензиями.
3. `query user` / `logoff` / `tscon` решают половину «занято/выбило».
4. В интернет 3389 не открывают — только VPN/шлюз.
5. Не путать «нет сети» и «нет RDP»: проверяется порт, а не ping.
