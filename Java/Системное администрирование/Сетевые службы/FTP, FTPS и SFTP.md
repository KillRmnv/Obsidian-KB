# FTP, FTPS и SFTP

## Проблема: передать файл между разными системами

Банк присылает выписку на свой FTP-сервер. 1С выгружает файлы на FTP. Сканер отправляет отсканированные документы по FTP. Производитель оборудования выкладывает прошивки по FTP.

Во всех случаях файл нужно передать между системами, которые ничего не знают друг о друге, — и часто автоматически, без человека.

FTP — один из старейших протоколов для этого. Он простой, но устроен не так, как современные, и именно из-за этого «подключается, а файлов не видно».

## Главная особенность: две связи вместо одной

Когда ты подключаешься по FTP, открываются **два соединения**:

| Соединение | Порт | Что передаёт |
|---|---|---|
| Управляющее | **21/tcp** | команды: логин, список файлов, «загрузи это» |
| Данные | отдельное | сами файлы и листинг каталога |

Вот здесь и корень всех проблем. Управляющее соединение устанавливает **клиент**. А соединение для данных в классическом режиме устанавливает **сервер** — и это ломается на файрволах и NAT.

## Активный режим: сервер звонит клиенту

1. Клиент подключается к серверу на 21 и говорит: «я слушаю порт 50000, стучись ко мне».
2. Сервер сам открывает соединение **с порта 20** на порт клиента.
3. Данные идут.

Проблема: клиент обычно за NAT или файрволом. Снаружи до его порта 50000 никто не дозвонится. Соединение данных не открывается, и клиент видит: «Connected», а дальше — таймаут и пустой список.

Поэтому в реальных сетях активный режим почти не используют.

## Пассивный режим: клиент звонит серверу

1. Клиент подключается к 21 и просит: «переходи в пассивный режим».
2. Сервер отвечает: «я открыл порт 50001, подключайся сюда».
3. Клиент сам открывает соединение данных — то есть ведёт себя как обычный клиент, и NAT ему не мешает.

Проблема переезжает на сервер: теперь **на сервере** должен быть открыт диапазон портов для данных. Если файрвол пускает только 21, управление пройдёт, а данные — нет.

Отсюда классический симптом: **«логин прошёл, а список файлов пустой / таймаут»**. Управляющий канал работает, канал данных — нет. Проверять надо именно диапазон пассивных портов, а не логин с паролем.

Обычно в конфиге задают фиксированный диапазон и открывают его на файрволе:

```ini
pasv_enable=YES
pasv_min_port=50000
pasv_max_port=50100
```

## FTP, FTPS, SFTP: три разных вещи

| Название | Что это | Порт | Пароль защищён? |
|---|---|---|---|
| **FTP** | классический протокол | 21 | **Нет**, логин и пароль идут открытым текстом |
| **FTPS** | FTP + TLS (шифрование поверх FTP) | 21 (явный) или 990 (неявный) | Да |
| **SFTP** | файловая передача **внутри SSH** | 22 | Да |

Главная путаница: **SFTP — это не FTP с шифрованием**. Это отдельный протокол, который работает через SSH. У него другой клиент, другой сервер, другие команды. Общее только назначение — передавать файлы.

Практический вывод: в интернет — только SFTP или FTPS. Чистый FTP допустим внутри доверенной сети или для старого оборудования, которое ничего другого не умеет.

## Коды ответов, которые надо узнавать

| Код | Значение | Что делать |
|---|---|---|
| **220** | сервер готов | норма |
| **230** | вход выполнен | норма |
| **331** | нужен пароль | норма, клиент пришлёт |
| **530** | логин или пароль неверны | проверить учётку, не заблокирована ли |
| **425** | не удалось открыть соединение данных | файрвол/пассивный режим — самая частая проблема |
| **550** | нет доступа или нет такого файла | права, путь, chroot |
| **421** | соединение закрыто (таймаут/лимит) | сеть, лимиты сервера |

## Права и «тюрьма»

FTP-сервер обычно настраивают так, чтобы пользователь после входа не видел всю файловую систему, а только свою папку. Это называется **chroot** — «тюрьма»: корнем для него становится `/srv/ftp/ivanov`.

Зачем: иначе пользователь сможет ходить по `/etc` и читать чужие файлы.

Анонимный FTP (вход без пароля) почти всегда отключают: это открытая дверь для мусора и атак. Если нужен публичный файл — лучше обычный веб-сервер.

## Как выглядит настройка

**Linux, vsftpd** — минимальный конфиг:

```ini
local_enable=YES
write_enable=YES
chroot_local_user=YES
pasv_enable=YES
pasv_min_port=50000
pasv_max_port=50100
ssl_enable=YES
rsa_cert_file=/etc/ssl/certs/vsftpd.pem
```

Затем: `systemctl restart vsftpd`, открыть 21 и 50000–50100 на файрволе, проверить `ftp`/`lftp`/FileZilla.

**Windows** — либо роль IIS FTP в Windows Server, либо FileZilla Server. Логика та же: пользователь, папка, права, пассивные порты, сертификат для FTPS.

**Клиенты**: FileZilla, WinSCP (умеет и FTP, и SFTP), `lftp` в Linux. Для проверки из консоли удобно:

```bash
curl -u user:pass ftp://server/ --list-only
curl -T file.zip -u user:pass ftp://server/upload/
```

## Что ломается в жизни

**«Подключается, но не видит файлы».** Классика: управляющий канал прошёл, данные — нет. Смотреть пассивный режим и диапазон портов на сервере и файрволе.

**«530 Login incorrect».** Неверный пароль, учётка заблокирована, или сервер требует явный FTPS, а клиент пришёл обычным FTP.

**«550 Permission denied».** Права на папку или chroot: пользователь вошёл, но писать в этот каталог не может.

**«Работает из офиса, не работает из дома».** Домашний NAT/файрвол режет пассивные порты; либо сервер за NAT не отдаёт правильный внешний адрес (нужна настройка `pasv_address`/внешнего IP).

**«Сканер не может отправить файл на FTP».** Устройство умеет только FTP, а сервер требует шифрование; либо не поддержан пассивный режим. Решение — отдельный сервис/папка под сканы.

## Чек-лист диагностики

1. Уточнить режим и протокол: FTP, FTPS или SFTP; активный или пассивный.
2. Проверить доступность порта: 21 (FTP/FTPS) или 22 (SFTP).
3. В логе клиента найти код ошибки — он сразу делит проблему на «логин» (530), «данные» (425), «права» (550).
4. Для 425 — проверить диапазон пассивных портов на сервере и в файрволе.
5. Для 530 — проверить учётку и требование TLS.
6. Для 550 — проверить права на каталог и chroot.
7. Проверить, не истёк ли сертификат (FTPS): `openssl s_client -connect server:21 -starttls ftp`.
8. Убедиться, что клиент не «умничает» с активным режимом — принудительно включить passive.

## Вопросы на собеседовании

**Почему FTP плохо работает через NAT?** В активном режиме соединение данных открывает сервер к клиенту, а клиент за NAT недоступен. Поэтому используют пассивный режим, где клиент сам подключается к серверу.

**Чем SFTP отличается от FTPS?** SFTP — передача внутри SSH (порт 22, другой протокол). FTPS — обычный FTP, обёрнутый в TLS (порты 21/990). Это не одно и то же.

**Почему «подключился, а файлов не видно»?** Управляющее соединение на 21 прошло, а соединение данных не открылось: файрвол или пассивные порты.

**Что такое chroot в FTP?** Ограничение видимой файловой системы папкой пользователя; защищает остальные каталоги.

**Почему анонимный FTP отключают?** Открытый доступ без аутентификации: мусор, утечки, использование сервера для распространения файлов.

**Что выбрать для обмена с внешним партнёром?** SFTP (или FTPS, если партнёр требует именно FTP); чистый FTP — только внутри доверенной сети.

## Что запомнить

1. FTP использует два соединения: команды (21) и данные (отдельный порт).
2. Активный режим ломается за NAT, пассивный требует диапазон портов на сервере.
3. «Подключился, но пусто» — почти всегда канал данных, а не пароль.
4. SFTP ≠ FTPS: SSH против TLS поверх FTP.
5. В интернет — только SFTP/FTPS, FTP — для внутренних и старых систем.
