# Bash. Основы скриптов

Скрипт — текстовый файл с командами, которые интерпретатор выполняет строка за строкой. Ниже база для админских задач: запуск, переменные, условия, циклы, перенаправления и cron.

## Шебанг и способы запуска

| Способ | Что происходит |
|---|---|
| `bash script.sh` | Без прав на исполнение; shebang игнорируется |
| `chmod +x script.sh && ./script.sh` | Интерпретатор берётся из shebang |
| `source script.sh` (`. script.sh`) | В текущем shell — меняет переменные и `cd` |
| `sh script.sh` | POSIX sh: `[[ ]]` и массивы сломаются |

Первая строка `#!/usr/bin/env bash` надёжнее `#!/bin/bash`: `env` находит bash в `PATH`.

## Переменные, кавычки, подстановки

| Запись | Смысл |
|---|---|
| `NAME=value` | Присваивание, без пробелов вокруг `=` |
| `"$NAME"` / `'$NAME'` | Подстановка с сохранением пробелов / литерал без подстановок |
| `${NAME:-default}` / `${#NAME}` | Значение по умолчанию / длина строки |
| `$(cmd)` / `$((2+2))` | Вывод команды / арифметика |
| `export NAME` | Передать переменную дочерним процессам |

## Аргументы, коды возврата, строгий режим

| Запись | Смысл |
|---|---|
| `$?` | Код последней команды: 0 — успех |
| `$#` / `$1 … $9` | Количество / позиционные аргументы |
| `"$@"` / `"$*"` / `shift` | Все аргументы словами / одной строкой / сдвиг |

```bash
set -euo pipefail
IFS=$'\n\t'
[[ $# -lt 2 ]] && { echo "usage: $0 <src> <dst>" >&2; exit 2; }
```
`-e` — выход при ошибке (кроме `if`, `&&`, `||`); `-u` — ошибка на незаданную переменную; `-o pipefail` — пайп падает, если упала любая его часть. `IFS` с `\n\t` не даёт `for` разбивать строки по пробелам.

## Ветвления и циклы

| Конструкция | Пример |
|---|---|
| `if/elif/else` | `if [[ -f "$CONF" ]]; then ...; elif [[ -d "$CONF" ]]; then ...; else exit 1; fi` |
| `for` | `for h in web1 web2; do ping -c1 -W1 "$h" &>/dev/null; done` |
| `while` / `until` | `while read -r l; do echo "$l"; done < f` / `until systemctl is-active --quiet nginx; do sleep 1; done` |
| `case` | `case "$1" in start) systemctl start nginx ;; *) exit 1 ;; esac` |

Проверки в `[[ ]]`: `-f` файл, `-d` каталог, `-z` пустая строка, `-n` непустая, `-x` исполняемый, `-eq/-lt/-gt` числа, `=~` regex.

## Функции, массивы, чтение файла

```bash
log() { echo "$(date '+%F %T') $*" | tee -a /var/log/myscript.log; }
count_lines() { local file="$1"; wc -l < "$file"; }   # local не утечёт наружу

servers=(web1 web2 db1)
echo "${servers[0]} ${#servers[@]}"
for s in "${servers[@]}"; do echo "$s"; done

while IFS= read -r line; do          # -r: не интерпретировать \
  [[ -z "$line" ]] && continue       # пропустить пустые
  echo "$line"
done < "$INPUT"
```
`for line in $(cat file)` ломается на пробелах — читать только через `while read`.

## Перенаправления и пайпы

| Запись | Смысл |
|---|---|
| `> file` / `>> file` / `2> err.log` | Перезаписать / дописать stdout / только stderr |
| `2>&1` / `&> file` | stderr туда же, куда stdout / оба потока сразу (bash) |
| `cmd \| tee -a log` | На экран и в файл одновременно |
| `cmd >/dev/null 2>&1` | Полностью подавить вывод |

## trap, getopts и отладка

```bash
trap 'rm -f "$TMP"' EXIT INT TERM
while getopts ":f:v" opt; do case "$opt" in
  f) FILE="$OPTARG" ;; v) VERBOSE=1 ;;
  \?) echo "bad option: -$OPTARG" >&2; exit 2 ;;
esac; done; shift $((OPTIND - 1))
```

| Приём | Назначение |
|---|---|
| `bash -n script.sh` | Только синтаксис, без выполнения |
| `bash -x script.sh` | Трассировка команд (`set -x` внутри) |
| `shellcheck script.sh` | Линтер: кавычки, неиспользуемые переменные, типовые ошибки |

## crontab

```bash
PATH=/usr/local/bin:/usr/bin:/bin
0 3 * * * /opt/scripts/backup.sh >> /var/log/backup.log 2>&1
*/5 * * * * /opt/scripts/check.sh >/dev/null 2>&1
```
Поля: минута, час, день месяца, месяц, день недели; `*/5` — каждые 5 минут, `1-5` — по будням, `@reboot` — при загрузке. В cron минимальное окружение: `PATH` задавать явно, пути абсолютные — иначе «руками работает, в cron нет».

## Хорошие практики

- Идемпотентность: `mkdir -p`, проверка `id`, `systemctl is-active`; lock от параллельного запуска — `flock -n /var/lock/backup.lock script.sh`.
- Логирование с датой, `exit` с осмысленным кодом, ошибки в stderr, кавычки вокруг `"$var"` и `"$@"`.
- Не парсить `ls`; для файлов — `find` и glob, константы и пути в начале файла.

## Чек-лист диагностики

1. `bash -n script.sh` — синтаксис.
2. `bash -x script.sh` — найти первую упавшую команду.
3. Проверить `$?` после подозрительной команды, затем `shellcheck script.sh`.
4. Запустить в чистом окружении, как в cron: `env -i /bin/bash script.sh`.
5. Проверить права на файл и `x` на каталогах пути.
6. Убедиться, что `set -e` не маскирует ожидаемый ненулевой код (`|| true`).

## Вопросы на собеседовании

**Чем `source` отличается от `./script.sh`?**
`source` выполняет код в текущем shell, поэтому переменные и `cd` остаются. `./script.sh` запускает дочерний процесс — изменения теряются.

**Зачем кавычки в `"$@"` и `"$var"`?**
Без кавычек слова разбиваются по `IFS` и раскрываются как glob. `"$@"` передаёт каждый аргумент отдельно, `"$var"` сохраняет пробелы.

**Что делает `set -e` и где он не спасает?**
Прерывает скрипт при ненулевом коде. Не срабатывает в `if`, после `&&`/`||`; без `pipefail` смотрит только на последнюю команду пайпа.

**Почему скрипт работает руками, но не в cron?**
Другой `PATH` и окружение, другой рабочий каталог, меньше прав. Лечится абсолютными путями, явным `PATH` и логом вывода.

**Почему `2>&1 > file` работает не так, как ожидается?**
Порядок важен: `2>&1` привяжет stderr к текущему stdout (терминалу), и только потом stdout уйдёт в файл. Правильно — `> file 2>&1`.
