# Групповые политики (GPO)

## Проблема: одинаковые настройки на сотнях машин

Нужно, чтобы у всех сотрудников:

- пароль был не короче 12 символов и менялся раз в 90 дней;
- на рабочем столе — корпоративные обои;
- при входе автоматически подключался диск `Z:`;
- был запрещён автозапуск с флешек;
- на принтеры стояли одинаковые драйверы.

Сделать это руками на 200 компьютерах — недели работы. А потом приходит новый компьютер, и всё повторяется.

**Групповая политика (GPO)** — это набор настроек, который хранится на контроллере домена и применяется к компьютерам и пользователям автоматически, при каждой загрузке и входе.

## Как это устроено

GPO — объект в AD. Внутри два раздела:

| Раздел | К чему применяется | Пример |
|---|---|---|
| **Computer Configuration** | к компьютеру, до входа пользователя | парольная политика, брандмауэр, запрет USB |
| **User Configuration** | к пользователю, где бы он ни сел | обои, маппинг дисков, настройки браузера |

Если настройка «не применяется», первая причина — её положили не в тот раздел: политику дисков искали в компьютере, а она пользовательская.

GPO привязывается не к человеку, а к **контейнеру**: сайту, домену или OU. Всё, что внутри контейнера, получает настройки.

## Порядок применения: LSDOU

Политики применяются сверху вниз:

```text
L — Local      локальная политика компьютера
S — Site       политика сайта
D — Domain     политика домена
O — OU         политики подразделений (от родительского к дочернему)
```

При конфликте побеждает **последняя применённая**, то есть самая близкая к объекту.

Аналогия: в компании есть общие правила, у отдела — свои, у кабинета — свои. Если правила противоречат, действует то, что заведено на самом низком уровне.

Важно: **несколько GPO на одном OU** применяются в порядке приоритета (Link Order), и нижняя в списке перекрывает верхнюю. Это частая причина «я настроил, а работает по-старому».

## Наследование, Enforced и Block Inheritance

- **Наследование** — политика родительского OU действует и на дочерние. По умолчанию.
- **Enforced** («не переопределять») — политику нельзя перебить ниже. Ставят на критичные вещи: парольная политика, антивирус.
- **Block Inheritance** — контейнер не получает политики сверху. Использовать опасно: вместе с ненужными отключатся и нужные (например, парольная политика).

Если включить Enforced и Block одновременно, побеждает Enforced — специально, чтобы защиту нельзя было отключить снизу.

## Фильтрация: не всем и не всегда

Иногда политику нужно применить не ко всему OU. Три способа:

| Способ | Что ограничивает | Пример |
|---|---|---|
| **Security Filtering** | кому применяется (по группам) | только группе `GG-Developers` |
| **WMI Filter** | на каких машинах (по условиям) | только Windows 11, только ноутбуки |
| **Loopback Processing** | где брать пользовательские настройки | терминальный сервер: настройки пользователя зависят от сервера |

Loopback — самая непонятная штука для новичка. Объяснение: обычно пользовательские настройки «ходят за пользователем». На сервере терминалов нужно наоборот: у всех, кто зашёл на **этот** сервер, одинаковые настройки. Тогда включают loopback.

## Как проверить, что применилось

```text
gpupdate /force        :: перечитать политики (не всегда нужна перезагрузка)
gpresult /r            :: какие GPO применились к пользователю и компьютеру
gpresult /h report.html :: подробный отчёт в файл
rsop.msc               :: итоговая политика (устаревшая оснастка)
```

`gpresult /r` — главный инструмент. В нём видно: какие GPO применены, какие отфильтрованы и почему (нет прав, WMI, пустая группа).

## Почему политика не применилась — топ причин

1. **Не та привязка.** GPO привязан к домену, а компьютер в OU, или наоборот.
2. **Не тот раздел.** Настройка в Computer, а нужна в User.
3. **Security Filtering.** У группы компьютеров нет права Read на GPO (по умолчанию Authenticated Users, но его часто удаляют).
4. **WMI-фильтр** не совпал (другая версия Windows, другой тип устройства).
5. **Loopback** не включён там, где нужен.
6. **Приоритет.** Нижестоящая GPO перекрывает настройку.
7. **Репликация.** GPO создан на одном DC, компьютер проверяется другим; подождать или `repadmin`.
8. **Клиент не перечитал политику.** `gpupdate /force` + перезаход пользователя.
9. **Клиентское расширение (CSE)** не поддерживает настройку на этой версии Windows.

## Типовые политики и где их искать

| Что нужно | Раздел |
|---|---|
| Парольная политика | Computer → Windows Settings → Security Settings → Account Policies |
| Обои, экран блокировки | User → Administrative Templates → Desktop / Control Panel → Personalization |
| Маппинг дисков | User → Preferences → Windows Settings → Drive Maps |
| Принтеры | User → Preferences → Control Panel → Printers |
| Запрет USB-накопителей | Computer → Administrative Templates → System → Removable Storage Access |
| Отключить автозапуск | Computer → Administrative Templates → Windows Components → AutoPlay Policies |
| Правила брандмауэра | Computer → Windows Settings → Security Settings → Windows Firewall |
| Запрет панели управления | User → Administrative Templates → Control Panel |

Preferences (в отличие от Policies) применяются один раз и не «залипают» — их можно изменить пользователю, и они не вернутся обратно.

## Central Store и бэкап

**Central Store** — папка `\\corp.local\SYSVOL\corp.local\Policies\PolicyDefinitions`, куда кладут файлы шаблонов (`.admx`). Нужна, чтобы у всех администраторов был одинаковый набор настроек и не было «у меня этой политики нет».

**Бэкап GPO** — `Backup-GPO` или через GPMC. Политика может быть случайно удалена или изменена; восстановить из бэкапа проще, чем вспоминать, что там было.

## Чек-лист диагностики

1. Понять, какая именно настройка должна работать (точный путь в политике).
2. `gpresult /r` на проблемной машине: применена ли GPO, не отфильтрована ли.
3. Проверить привязку GPO к OU, где находится компьютер/пользователь.
4. Проверить Security Filtering: есть ли у объекта право Read/Apply.
5. Проверить WMI-фильтр и разрядность/версию ОС.
6. Проверить приоритет: не перекрывает ли другая GPO (`gpresult /h`).
7. `gpupdate /force`, перезагрузка/перезаход, затем снова `gpresult`.
8. Проверить репликацию между DC, если GPO создан недавно.
9. Посмотреть журнал `Microsoft-Windows-GroupPolicy/Operational` — там причины отказа.

## Вопросы на собеседовании

**Что такое GPO?** Набор настроек, привязанный к сайту, домену или OU и применяемый к компьютерам и пользователям автоматически.

**В каком порядке применяются политики?** LSDOU: локальная, сайт, домен, OU; побеждает последняя, то есть самая близкая.

**Что такое Enforced и Block Inheritance?** Enforced запрещает перебивать политику ниже, Block Inheritance отключает получение политик сверху; Enforced сильнее.

**Почему политика не применилась?** Не та привязка, не тот раздел, фильтрация, WMI, приоритет, репликация — проверяется `gpresult /r`.

**Чем Policy отличается от Preference?** Policy навязывает настройку и возвращает её обратно, Preference применяется один раз и позволяет пользователю изменить.

**Зачем loopback?** Чтобы на терминальном сервере применялись пользовательские настройки, заданные для этого сервера, а не «привезённые» пользователем.

## Что запомнить

1. GPO — централизованные настройки для контейнера, а не для человека.
2. LSDOU: чем ближе к объекту, тем выше приоритет.
3. Computer и User — разные разделы; половина «не работает» отсюда.
4. `gpresult /r` отвечает на вопрос «почему не применилось».
5. Preferences ≠ Policies.
