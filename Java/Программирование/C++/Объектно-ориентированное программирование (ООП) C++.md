
### 1. Классы, структуры и модификаторы доступа

- **`struct` vs `class`**: Единственное различие — модификатор доступа по умолчанию. В `struct` члены и базовые классы по умолчанию `public`, в `class` — `private`.
    
      
    
- **Модификаторы доступа**:
    
      
    - `public` — доступен из любого места программы.
        
          
        
    - `protected` — доступен внутри самого класса и в производных классах.
        
          
        
    - `private` — доступен только внутри самого класса (и друзьям `friend`).
        
          
        

### 2. Конструкторы и Деструкторы

#### Специальные функции-члены

- **Конструктор по умолчанию (Default Constructor)**: Вызывается при создании объекта без аргументов (`T()`).
    
      
    
- **Конструктор копирования (Copy Constructor)**: Создает копию из существующих lvalue (`T(const T&)`).
    
      
    
- **Конструктор перемещения (Move Constructor, C++11)**: Переносит ресурсы из временного rvalue (`T(T&& noexcept)`).
    
      
    
- **Операторы присваивания**: `T& operator=(const T&)` и `T& operator=(T&& noexcept)`.
    
      
    
- **Деструктор (`~T()`)**: Вызывается при уничтожении объекта. Освобождает ресурсы.
    
      
    

#### Спецификаторы `= default` и `= delete`

- `= default` — явно заставляет компилятор сгенерировать реализацию по умолчанию.
    
      
    
- `= delete` — запрещает вызов функции (например, для создания не копируемых классов).
    
      
    

#### Ключевое слово `explicit`

Предотвращает неявные преобразования типов при вызове конструктора с одним аргументом или операторов приведения.

  

C++

```
class Buffer {
public:
    explicit Buffer(size_t size); // Предотвращает: Buffer b = 100; (неявный static_cast)
};
```

### 3. Rule of 0 / 3 / 5 (Правило Ноля / Трех / Пяти)

Определяет управление ресурсами в классе:

  

- **Rule of 3 (C++03)**: Если классу нужен кастомный _деструктор_, _конструктор копирования_ или _оператор копирующего присваивания_, ему почти наверняка нужны все три.
    
      
    
- **Rule of 5 (C++11)**: Добавление move-семантики. Если вы определяете любой из 3 классических методов, вы должны явно определить или заделегировать все 5:
    
      
    1. Destructor
        
          
        
    2. Copy Constructor
        
          
        
    3. Copy Assignment Operator
        
          
        
    4. Move Constructor
        
          
        
    5. Move Assignment Operator
        
          
        
- **Rule of 0 (Modern C++)**: Проектируйте классы так, чтобы им не нужно было управлять ресурсами вручную. Используйте RAII-обертки (`std::string`, `std::vector`, `std::unique_ptr`). Тогда компилятор правильно сгенерирует все 5 методов автоматически.
    
      
    

### 4. Наследование, Виртуальные функции и vtable

#### Типы наследования

- `public` — сохраняет уровни доступа базового класса (модель отношения «IS-A»).
    
      
    
- `protected` — `public` члены становятся `protected`.
    
      
    
- `private` — все члены базового класса становятся `private` в наследнике.
    
      
    

#### Виртуальные функции и Полиморфизм

Виртуальные функции (`virtual`) обеспечивают **динамический (runtime) полиморфизм**.

  

- **Таблица виртуальных функций (`vtable`)**:
    
      
    - Каждая виртуальная функция делает класс полиморфным. Компилятор создает таблицу указателей на виртуальные функции (`vtable`) для такого класса.
        
          
        
    - Каждый объект полиморфного класса содержит скрытый указатель на эту таблицу — **`vptr`** (увеличивает размер объекта на размер указателя, 8 байт на x64).
        
          
        
    - Вызов `obj->virtualMethod()` превращается в резолв адреса через `vptr -> vtable[index]()`.
        
          
        

```
[Объект в памяти]          [vtable в Read-Only памяти]
+---------------+          +---------------------------+
| vptr   ------>|--------->| &Derived::speak()         |
| data_member   |          | &Derived::type()          |
+---------------+          +---------------------------+
```

- **Чисто виртуальные функции (Pure Virtual Functions)**:
    
    `virtual void draw() = 0;` — делает класс **абстрактным** (нельзя создать экземпляр). Аналог интерфейса в Java.
    
      
    
- **Виртуальный деструктор**:
    
    Если класс имеет хотя бы одну виртуальную функцию или от него планируется наследоваться полиморфно, его деструктор **обязан быть `virtual`**. В противном случае вызов `delete basePtr` на объекте-наследнике приведет к **Undefined Behavior** (деструктор наследника не выполнится).
    
      
    

### 5. Ключевые слова ООП

- **`override` (C++11)**: Гарантирует, что функция переопределяет виртуальную функцию базового класса. Ошибка компиляции, если сигнатуры не совпадают.
    
      
    
- **`final` (C++11)**: Запрещает дальнейшее переопределение виртуальной функции или наследование от класса.
    
      
    
- **`mutable`**: Позволяет изменять поле класса даже внутри `const`-методов (используется для кэшей, мьютексов).
    
      
    
- **`friend`**: Предоставляет внешней функции или другому классу доступ к `private` и `protected` членам.
    

### Пример полиморфной иерархии (Modern C++)

C++

```
#include <iostream>
#include <memory>

class Shape {
public:
    virtual ~Shape() = default; // Обязательный виртуальный деструктор
    virtual void draw() const = 0; // Чисто виртуальный метод
};

class Circle final : public Shape {
public:
    explicit Circle(double radius) : radius_(radius) {}

    void draw() const override {
        std::cout << "Drawing Circle with radius: " << radius_ << '\n';
    }

private:
    double radius_;
};

int main() {
    std::unique_ptr<Shape> shape = std::make_unique<Circle>(5.0);
    shape->draw(); // Динамический вызов через vtable
}
```
