### 1. Классификация контейнеров STL

Все контейнеры STL автоматически управляют памятью (реализуют RAII) и подразделяются на 4 основные группы:

  

#### 1. Последовательные контейнеры (Sequence Containers)

Элементы хранятся в строгом линейном порядке, определяемом пользователем.

  

- **`std::vector<T>`**:
    
      
    - **Устройство:** Динамический непрерывный массив в куче.
        
          
        
    - **Сложность:** Доступ по индексу $O(1)$, вставка/удаление в конец $O(1)$ amortized, вставка в середину $O(N)$.
        
          
        
    - **Особенности:** Самый эффективный контейнер благодаря локальности данных в кэше CPU (cache-friendliness). При превышении `capacity()` выделяет новый блок памяти (обычно $1.5\times$ или $2\times$), копирует/перемещает элементы и освобождает старый блок.
        
          
        
- **`std::array<T, N>` (C++11)**:
    
      
    - **Устройство:** Фиксированный массив на стеке (обертка над C-array). Размер $N$ задается в compile-time.
        
          
        
    - **Сложность:** Доступ $O(1)$, нулевые накладные расходы по памяти.
        
          
        
- **`std::deque<T>` (Double-ended queue)**:
    
      
    - **Устройство:** Двусторонняя очередь, состоящая из набора фиксированных массивов (буферов) и центральной таблицы указателей на них.
        
          
        
    - **Сложность:** Доступ по индексу $O(1)$, быстрая вставка/удаление в начало и конец $O(1)$.
        
          
        
- **`std::list<T>` и `std::forward_list<T>` (C++11)**:
    
      
    - **Устройство:** Двусвязный и односвязный списки соответственно.
        
          
        
    - **Сложность:** Вставка/удаление по известному итератору $O(1)$, случайный доступ $O(N)$. Плохая локальность данных в кэше CPU из-за выделения памяти под каждый узел отдельно.
        
          
        

#### 2. Ассоциативные контейнеры (Ordered Associative)

Хранят данные в отсортированном виде. Релизуются на основе **Красно-черных деревьев (Red-Black Trees)**.

  

- **`std::map<K, V>` / `std::set<T>`**: Уникальные ключи. Сложность поиска, вставки, удаления — **$O(\log N)$**.
    
      
    
- **`std::multimap<K, V>` / `std::multiset<T>`**: Допускают дублирование ключей.
    
      
    

#### 3. Неупорядоченные ассоциативные контейнеры (Unordered Associative, C++11)

Хранят данные на основе **Хеш-таблиц (Hash Tables)** с методом цепочек (chaining) для разрешения коллизий.

  

- **`std::unordered_map<K, V>` / `std::unordered_set<T>`**
    
      
    
- **`std::unordered_multimap` / `std::unordered_multiset`**
    
      
    
- **Сложность:** В среднем Поиск/Вставка/Удаление — **$O(1)$**, в худшем случае (при частых коллизиях) — **$O(N)$**.
    
      
    
- **Требования:** Для ключа $K$ должны быть определены `std::hash<K>` и оператор равенства `operator==`.
    
      
    

#### 4. Адаптеры контейнеров (Container Adapters)

Интерфейсные обертки над последовательными контейнерами:

  

- `std::stack` (по умолчанию использует `std::deque`, LIFO)
    
      
    
- `std::queue` (по умолчанию `std::deque`, FIFO)
    
      
    
- `std::priority_queue` (по умолчанию `std::vector`, куча / max-heap)

### 3. Итераторы и правила инвалидации

**Итераторы** — это абстракция указателей, предоставляющая единый интерфейс для обхода элементов любых контейнеров.

  

#### Категории итераторов (C++20 Concepts):

1. **Input / Output Iterator:** Только однопроходное чтение или запись (`*it`, `++it`).
    
      
    
2. **Forward Iterator:** Многопроходное чтение/запись вперед (`std::forward_list`).
    
      
    
3. **Bidirectional Iterator:** Движение вперед и назад (`++it`, `--it`) (`std::list`, `std::map`, `std::set`).
    
      
    
4. **Random Access Iterator:** Доступ со смещением за $O(1)$ (`it + n`, `it[n]`, `<`) (`std::vector`, `std::deque`).
    
      
    
5. **Contiguous Iterator (C++17):** Гарантирует, что элементы расположены в памяти физически непрерывно (`std::vector`, `std::array`, `std::string`).
    
      
    

#### Правила инвалидации итераторов (Iterator Invalidation Rules)

Инвалидация происходит, когда операция над контейнером делает существующие итераторы, ссылки или указатели невалидными (указывающими на освобожденную или чужую память):

C++

```
std::vector<int> vec = {1, 2, 3};
auto it = vec.begin();

vec.push_back(4); // ОПАСНО: если capacity не хватило, произойдет реалокация!
// *it; -> Undefined Behavior! Итератор 'it' инвалидирован.

// Безопасное удаление элементов в цикле до C++20 (Erase-Remove Idiom):
for (auto iter = vec.begin(); iter != vec.end(); ) {
    if (*iter == 2) {
        iter = vec.erase(iter); // erase возвращает следующий валидный итератор!
    } else {
        ++iter;
    }
}
```
