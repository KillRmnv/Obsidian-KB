### 1. Механизм исключений и гарантии безопасности

#### Базовый синтаксис

Механизм состоит из трех ключевых слов: `try` (блок наблюдения), `throw` (выброс исключения) и `catch` (перехват).

  

C++

```
try {
    // Код, который может выбросить исключение
    throw std::runtime_error("Something went wrong");
} catch (const std::overflow_error& e) {
    // Перехват конкретного типа (более специфичный)
} catch (const std::exception& e) {
    // Перехват базового типа (по ссылке!)
    std::cout << e.what() << '\n';
} catch (...) {
    // Перехват ЛЮБОГО исключения
}
```

> **Правило:** Исключения всегда следует перехватывать **по константной ссылке** (`const std::exception&`), чтобы избежать срезки объектов (object slicing) и лишнего копирования.
> 
>   

#### Разматывание стека (Stack Unwinding)

Когда выбрасывается исключение, среда выполнения раскручивает стек вызовов обратно до ближайшего подходящего блока `catch`.

  

- В процессе разматывания стека для всех локальных объектов **вызываются деструкторы** в порядке, обратном их созданию.
    
      
    
- **Критическое правило:** Деструкторы **никогда не должны выбрасывать исключения**. Если во время разматывания стека из деструктора вылетает еще одно исключение, программа немедленно аварийно завершается вызовом `std::terminate()`.
    
      
    

#### 4 Гарантии безопасности исключений (Exception Safety)

1. **No-fail / No-throw guarantee:** Функция гарантирует, что никогда не выбросит исключение (например, деструкторы, move-конструкторы).
    
      
    
2. **Strong exception safety (Гарантия транзакции):** Если функция завершается из-за исключения, состояние программы остается точно таким же, каким оно было до вызова (операция «все или ничего», часто реализуется через паттерн _Copy-and-Swap_).
    
      
    
3. **Basic exception safety:** Если выброшено исключение, инварианты объектов не нарушены, утечек памяти нет, но состояние объекта может измениться.
    
      
    
4. **No guarantee:** Утечки памяти, нарушение инвариантов, повреждение данных при исключении.
    
      
    

### 2. Спецификатор `noexcept`

Помечает функцию как не выбрасывающую исключений.

  

- **Синтаксис:**
    
      
    
    C++
    
    ```
    void fast_operation() noexcept; // Гарантирует отсутствие исключений
    void conditional_func() noexcept(sizeof(int) == 4); // Условный noexcept
    ```
    
- **Зачем нужен `noexcept`:**
    
      
    1. **Оптимизация компилятора:** Компилятору не нужно генерировать таблицы разматывания стека для этой функции.
        
          
        
    2. **Оптимизация STL (Контейнеры):** `std::vector` при реалокации памяти проверяет, является ли move-конструктор элементов `noexcept` (через `std::is_nothrow_move_constructible`).
        
          
        - Если move-конструктор **`noexcept`** — вектор **перемещает** элементы (быстро).
            
              
            
        - Если move-конструктор **может выбросить исключение** — вектор вынужден **копировать** элементы, чтобы сохранить _Strong Exception Safety_.
            
              
            

### 3. Функциональные альтернативы исключениям

В современном C++ (Modern C++) исключения часто заменяют легкими функциональными типами-обертками из стандартной библиотеки, особенно в высоконагруженных системах (gamedev, low-latency, embedded), где накладные расходы на разматывание стека недопустимы.

|**Тип**|**C++ Стандарт**|**Назначение и суть**|
|---|---|---|
|`std::optional<T>`|C++17|Хранит либо значение типа `T`, либо ничего (`std::nullopt`). Заменяет возвращение `nullptr` или спец-значений (`-1`).|
|`std::variant<Ts...>`|C++17|Безопасное типобезопасное объединение (Type-safe union). Хранит одно значение из списка типов.|
|`std::expected<T, E>`|C++23|Хранит либо успешный результат `T`, либо объект ошибки `E` (`std::unexpected`). Прямой аналог `Result<T, E>` из Rust.|

#### Пример использования `std::optional` и `std::expected`

C++

```
#include <optional>
#include <expected>
#include <string>

// C++17: Optional для ситуаций "значение есть / значения нет"
std::optional<int> parse_int(const std::string& str) {
    if (str.empty()) return std::nullopt;
    return std::stoi(str);
}

// C++23: Expected для возврата детальной ошибки без бросания exceptions
enum class ParseError { EmptyInput, InvalidCharacter, Overflow };

std::expected<int, ParseError> parse_number(const std::string_view str) {
    if (str.empty()) {
        return std::unexpected(ParseError::EmptyInput);
    }
    // ... логика парсинга ...
    return 42; // Успех
}
```
