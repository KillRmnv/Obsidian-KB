### 1. Процесс сборки (Build Process)

Исходный код `.cpp` превращается в исполняемый файл в 3 ключевых этапа:

  

1. **Препроцессинг (Preprocessing)**
    
      
    - **Что делает:** Работает исключительно с текстом до запуска самого компилятора. Выполняет директивы, начинающиеся с `#`.
        
          
        
    - `#include <file>` / `#include "file"` — буквально вставляет содержимое файла в место вызова.
        
          
        
    - `#define MACRO value` — текстовая замена (макросы).
        
          
        
    - **Translation Unit (TU, Единица трансляции):** Это результат работы препроцессора над одним `.cpp` файлом (исходный файл + все включенные `#include`). Компилятор работает с каждым TU независимо!
        
          
        
    - `#pragma once` vs **Include Guards**:
        
          
        - `#pragma once` — современная директива, указывающая компилятору включать файл только единожды. Поддерживается всеми современными компиляторами.
            
              
            
        - Include Guards — классический способ защиты от повторного включения:
            
              
            
            C++
            
            ```
            #ifndef MY_HEADER_H
            #define MY_HEADER_H
            // код заголовочного файла
            #endif
            ```
            
2. **Компиляция (Compilation)**
    
      
    - **Что делает:** Преобразует каждый TU в объектный файл (машинный код с метками, `.o` или `.obj`).
        
          
        
    - Синтаксический и семантический анализ, оптимизации.
        
          
        
3. **Линковка (Linking)**
    
      
    - **Что делает:** Компонует все `.o` файлы и библиотеки в единый исполняемый файл или библиотеку (`.exe`, `.so`, `.dll`).
        
          
        
    - Разрешает внешние символы (ссылки на функции/переменные, объявленные в одном TU, но определенные в другом).
        
          
        
    - Ошибка `Undefined reference` происходит на этапе линковки, если функция объявлена, но не найдена её реализация.
        
          
        

### 2. Фундаментальные типы и квалификаторы

#### Основные типы

- **Целочисленные:** `char` (1 байт), `short` (≥2 байт), `int` (≥2 байт, обычно 4), `long` (≥4 байт), `long long` (≥8 байт). Могут быть `signed` / `unsigned`.
    
      
    
- **С плавающей точкой:** `float` (4 байта), `double` (8 байт), `long double`.
    
      
    
- **Логический и символьные:** `bool`, `wchar_t`, `char16_t`, `char32_t`, `char8_t` (C++20).
    
      
    

> Размер типов зависит от архитектуры и компилятора. Используйте `sizeof(T)` или типы с фиксированным размером из `<cstdint>` (`int32_t`, `uint64_t`), если размер критичен.
> 
>   

#### Квалификаторы

- `const` — объект не может быть изменен после инициализации. Вычисляется во время выполнения или компиляции.
    
      
    
- `volatile` — указывает компилятору, что значение переменной может измениться извне (hardware, другой поток, сигнал OS). Отключает оптимизации кэширования в регистрах. _Не является средством синхронизации потоков!_
    
      
    
- `constexpr` (C++11) — гарантирует, что значение или функция **может** быть вычислена на этапе компиляции.
    
      
    
- `consteval` (C++20) — "immediate function". Функция **обязана** вычисляться только на этапе компиляции.
    
      
    
- `constinit` (C++20) — гарантирует, что статическая переменная инициализируется на этапе компиляции (предотвращает _Static Initialization Order Fiasco_), но сама переменная остается изменяемой.
    
      
    

### 3. Указатели, ссылки и Value Categories

#### Указатели vs Ссылки

- **Указатель (`T*`):** Переменная, хранящая адрес памяти другого объекта. Может быть `nullptr`, перенаправляться на другие объекты, поддерживает указательную арифметику.
    
      
    
- **Lvalue-ссылка (`T&`):** Альтернативное имя (алиас) для существующего объекта. Должна быть инициализирована при создании, не может быть перенаправлена на другой объект, не бывает `nullptr`.
    
      
    

#### Value Categories (Категории значений)

- **lvalue (left value):** Объект, имеющий имя и идентифицируемый адрес в памяти. К нему можно применить оператор взял адреса `&`.
    
      
    
- **rvalue (right value):** Временное значение, не имеющее имени и собственного адреса (например, литералы `42`, результат вычисления `a + b`, возвращенное по значению временное значение функции).
    
      
    

#### Ссылки на rvalue (`T&&`) и Move-семантика

Позволяют забирать (перемещать) ресурсы у временных объектов вместо их дорогостоящего копирования.

  

C++

```
int a = 10;
int& lref = a;      // OK: lvalue-ссылка на lvalue
// int& lref2 = 10; // Ошибка: нельзя связать lvalue-ссылку с rvalue
const int& clref = 10; // OK: const lvalue-ссылка продлевает жизнь rvalue!

int&& rref = 20;    // OK: rvalue-ссылка на временное значение (rvalue)
```

### 4. Область видимости и преобразования типов

#### Namespaces

Предотвращают конфликты имен в крупных проектах.

  

C++

```
namespace Utils {
    void print() {}
}
// Вызов: Utils::print();
// Анонимные namespaces внутренне связывают символы с текущим TU (замена static для функций):
namespace {
    void localHelper() {} 
}
```

#### Cast-операторы в C++ (вместо C-style `(Type)val`)

|**Оператор**|**Назначение**|**Когда использовать**|
|---|---|---|
|`static_cast`|Безопасное приведение типов на этапе компиляции|Преобразование базовых типов (`int` -> `float`), пойнтеров вверх/вниз по иерархии (без проверки)|
|`dynamic_cast`|Приведение по иерархии наследования с проверкой типа в runtime (RTTI)|Работает только с полиморфными классами (где есть хотя бы одна `virtual` функция). Возвращает `nullptr` при неудаче с указателями|
|`const_cast`|Добавление или снятие `const` / `volatile` квалификаторов|Только для работы со старыми C-API, снимать `const` с изначально `const` объектов для записи — **Undefined Behavior**|
|`reinterpret_cast`|Низкоуровневая переинтерпретация битового представления|Приведение несвязанных указателей (`char*` в `int*`), поинтера в целое число|

### 5. Массивы (C-style) и C-strings

#### C-style массивы

- Непрерывный блок памяти фиксированного размера.
    
      
    
- Имя массива легко спадает (_decays_) в указатель на его первый элемент при передаче в функцию.
    
      
    
- Нет встроенного сохранения размера (размер нужно передавать отдельно).
    
      
    

C++

```
int arr[5] = {1, 2, 3, 4, 5};
int* ptr = arr; // Decay: arr преобразуется в int*
```

#### C-strings (`const char*`)

- Массив символов типа `char`, обязательно завершающийся нуль-терминатором `\0`.
    
      
    
- Отсутствие `\0` при работе со строковыми функциями C (`strlen`, `strcpy`) приводит к выходу за границы памяти (Undefined Behavior).
    
      
    
- Строковые литералы (например, `"Hello"`) хранятся в сегменте памяти только для чтения (Read-Only Data Section). Попытка изменить их ведет к сегфолту.
    

C++

```
const char* str = "Hello"; // Указывает на строковый литерал в RO памяти
char modifiableStr[] = "Hello"; // Копирует символы в стек, можно изменять
modifiableStr[0] = 'J'; // OK
```
