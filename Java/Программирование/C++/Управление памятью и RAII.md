### 1. RAII (Resource Acquisition Is Initialization)

**RAII** — фундаментальный идиоматический паттерн в C++, связывающий жизненный цикл ресурса (память, файл, сокет, мьютекс) со временем жизни объекта на стеке.

  

- **Принцип работы:**
    
      
    1. Захват ресурса происходит в **конструкторе**.
        
          
        
    2. Освобождение ресурса автоматически выполняется в **деструкторе**.
        
          
        
- **Главное преимущество:** Безопасность при исключениях (Exception Safety). При разматывании стека деструктор вызовется автоматически, что полностью исключает утечки ресурсов (memory leaks, resource leaks).
    
      
    

### 2. Ручное управление памятью: `new` / `delete`

#### Операторы управления памятью

- `new` — выделяет память в куче (Heap) и вызывает конструктор объекта.
    
      
    
- `delete` — вызывает деструктор и освобождает память.
    
      
    
- `new[]` и `delete[]` — обязательные парные операторы для массивов.
    
      
    - **Ошибка:** Вызов `delete` вместо `delete[]` для массива ведет к **Undefined Behavior** (деструкторы элементов, кроме первого, не вызовутся, а аллокатор разрушит структуру кучи).
        
          
        

#### Placement new

Позволяет сконструировать объект в заранее выделенном участке памяти (без повторного выделения памяти в куче):

  
```c++
alignas(alignof(MyClass)) char buffer[sizeof(MyClass)]; // Память на стеке
MyClass* obj = new (buffer) MyClass(args...);          // Placement new

obj->~MyClass(); // Важно: Деструктор вызывается ЯВНО! Память delete'ить нельзя.
```

### 3. Умные указатели (Smart Pointers)

Умные указатели — это RAII-обертки над сырыми указателями из библиотеки `<memory>`.

  

#### 1. `std::unique_ptr<T>`

- **Семантика:** **Строгое монопольное владение** объектом.
    
      
    
- **Особенности:**
    
      
    - Некопируемый (`copy constructor = delete`), но перемещаемый (`std::move`).
        
          
        
    - Нулевые накладные расходы по памяти и скорости по сравнению с сырым указателем (Zero-overhead abstraction).
        
          
        
    - Поддерживает кастомные делеторы (`Custom Deleters`).
        
          
        
- **Создание:** `std::make_unique<T>(args...)` (C++14).
    
      
    


```c++
auto ptr = std::make_unique<Data>(100);
// auto ptr2 = ptr;            // Ошибка компиляции! Копирование запрещено
std::unique_ptr<Data> ptr2 = std::move(ptr); // OK: Владение передано ptr2, ptr равен nullptr
```

#### 2. `std::shared_ptr<T>`

- **Семантика:** **Разделяемое владение** (Shared Ownership). Объект уничтожается, когда число владельцев становится равным 0.
    
      
    
- **Устройство:** Состоит из сырого указателя на объект и указателя на **Control Block** (управляющий блок).
    
      
    - **Control Block содержит:**
        
          
        1. Strong Reference Counter (Счетчик сильных ссылок).
            
              
            
        2. Weak Reference Counter (Счетчик слабых ссылок).
            
              
            
        3. Custom Deleter & Allocator.
            
              
            
- **Атомарность:** Изменение счетчиков внутри Control Block **атомарно** (безопасно для потоков), но доступ к самому объекту `T` не является потокобезопасным!
    
      
    
- **Создание:** `std::make_shared<T>(args...)` — выделяет память под объект и Control Block **одним непрерывным блоком**, что экономит 1 аллокацию и улучшает локальность кэша.
    
      
    

#### 3. `std::weak_ptr<T>`

- **Семантика:** Не владеющее ("слабое") наблюдение за объектом, принадлежащим `std::shared_ptr`.
    
      
    
- **Назначение:**
    
      
    1. Разрыв **циклических ссылок** (Cyclic Dependencies), приводящих к утечкам памяти.
        
          
        
    2. Кеширование и паттерн Observer.
        
          
        
- **Использование:** Не дает прямого доступа через `operator->`. Чтобы получить доступ, нужно вызвать `.lock()`, который возвращает `std::shared_ptr` (или `nullptr`, если объект уже уничтожен).
    
      
    

C++

```
std::shared_ptr<Data> shared = std::make_shared<Data>();
std::weak_ptr<Data> weak = shared;

if (auto locked = weak.lock()) { // Проверка, жив ли еще объект
    locked->doSomething();
}
```

### 4. Move-семантика и Perfect Forwarding

Move-семантика переносит внутренние ресурсы (указатели на динамическую память, дескрипторы) из одного объекта в другой без копирования.

  

#### `std::move`

Не перемещает ничего самостоятельно! `std::move` — это лишь **`static_cast<T&&>(val)`**, преобразующий lvalue в rvalue-ссылку, разрешая вызов move-конструктора или move-оператора присваивания.

  

#### Perfect Forwarding (Идеальное перенаправление) и `std::forward`

Применяется в универсальных ссылках (`T&&` в контексте вывода типов шаблона / forwarding reference), чтобы передать аргументы в другую функцию с сохранением их категории значения (lvalue остается lvalue, rvalue остается rvalue).

C++

```
template <typename T>
void wrapper(T&& arg) { // T&& здесь — Universal/Forwarding reference
    // std::forward восстанавливает исходную категорию значения:
    targetFunction(std::forward<T>(arg)); 
}
```

### Сравнительный анализ Умных указателей

|**Тип указателя**|**Накладные расходы (Overhead)**|**Копирование**|**Перемещение**|**Кастомный деструктор**|
|---|---|---|---|---|
|**`std::unique_ptr`**|0 байт (без deleter'a)|Нет|Да (`std::move`)|Изменяет тип указателя (`unique_ptr<T, Deleter>`)|
|**`std::shared_ptr`**|2x размера указателя + Control Block (16–24 байта)|Да (атомарный инкремент)|Да (без инкремента)|Стирание типа (Type Erasure), тип остается `shared_ptr<T>`|
|**`std::weak_ptr`**|2x размера указателя|Да|Да|Не управляет деструктором напрямую|
