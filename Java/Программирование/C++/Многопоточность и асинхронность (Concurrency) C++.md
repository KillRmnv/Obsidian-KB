### 1. Потоки исполнения (`std::thread` и `std::jthread`)

- **`std::thread` (C++11):**
    
      
    - Запускает новый поток ОС при создании.
        
          
        
    - **Критическое правило:** Экземпляр `std::thread` **обязан** быть либо присоединен (`.join()`), либо отсоединен (`.detach()`) до вызова своего деструктора. Если объект уничтожается в состоянии `joinable()`, вызывается `std::terminate()`.
        
          
        
- **`std::jthread` (C++20):**
    
      
    - RAII-обертка над потоком. В деструкторе автоматически запрашивает остановку и делает `.join()`.
        
          
        
    - Поддерживает встроенный токен отмены `std::stop_token`.
        
          
        

C++

```
#include <thread>

void worker(std::stop_token stoken) {
    while (!stoken.stop_requested()) {
        // Выполнение работы...
    }
}

int main() {
    std::jthread t(worker); // Автоматический join и stop при выходе из main
}
```

### 2. Синхронизация и блокировки

Для предотвращения **Data Race** (одновременная запись/чтение памяти из разных потоков без синхронизации — это **Undefined Behavior**) используются примитивы взаимного исключения.

  

#### Мьютексы

- `std::mutex` — базовый мьютекс.
    
      
    
- `std::recursive_mutex` — позволяет повторный захват одним и тем же потоком.
    
      
    
- `std::shared_mutex` (C++17) — оптимизация _Read-Write Lock_. Позволяет нескольким потокам читать одновременно (`lock_shared`), но писать только монопольно (`lock`).
    
      
    

#### RAII-обертки для мьютексов

- `std::lock_guard<std::mutex>` (C++11) — простая обертка, захватывает мьютекс в конструкторе, освобождает в деструкторе.
    
      
    
- `std::unique_lock<std::mutex>` (C++11) — гибкая обертка, поддерживает отложенный захват (`std::defer_lock`), ручную разблокировку и работу с `std::condition_variable`.
    
      
    
- `std::scoped_lock` (C++17) — **вариативная RAII-обертка для предотвращения Deadlock**. Позволяет захватить сразу несколько мьютексов без риска взаимной блокировки (использует алгоритм avoidance deadlock).
    
      
    

C++

```
std::mutex m1, m2;
// Безопасный одновременный захват двух мьютексов без дедлока:
std::scoped_lock lock(m1, m2); 
```

#### Условные переменные (`std::condition_variable`)

Используются для ожидания события от другого потока. Всегда работают в связке с `std::unique_lock` и пердикатом для защиты от **ложных пробуждений (Spurious Wakeups)**:

  

C++

```
std::condition_variable cv;
std::mutex cv_m;
bool ready = false;

// Поток-потребитель:
std::unique_lock<std::mutex> lk(cv_m);
cv.wait(lk, []{ return ready; }); // Ждет, пока предикат не вернет true
```

### 3. Атомарные операции и модель памяти (`std::atomic`)

`std::atomic<T>` предоставляет потокобезопасные операции над объектами без использования мьютексов (часто компилируется в атомарные инструкции процессора, lock-free).

  

- **Lock-free проверка:** `atom.is_lock_free()` показывает, использует ли компилятор атомарные инструкции CPU или внутренний мьютекс.
    
      
    
- **CAS-операции (Compare-And-Swap):** Фундамент lock-free алгоритмов:
    
    `compare_exchange_weak` / `compare_exchange_strong`.
    
      
    

#### Порядок работы с памятью (Memory Orders)

Инструкции процессора и компилятор могут переупорядочивать операции чтения/записи для оптимизации. Квалификаторы `std::memory_order` определяют границы этих оптимизаций.

  

1. **`std::memory_order_relaxed`:** Гарантирует только атомарность самой операции. Порядок относительно других операций чтения/записи не гарантируется (нет барьеров памяти).
    
      
    
2. **`std::memory_order_acquire` (для операций чтения):** Гарантирует, что ни одна операция чтения/записи из текущего потока, расположенная _после_ acquire-чтения, не может быть переупорядочена _до_ него.
    
      
    
3. **`std::memory_order_release` (для операций записи):** Гарантирует, что ни одна операция чтения/записи из текущего потока, расположенная _до_ release-записи, не может быть переупорядочена _после_ нее.
    
      
    
4. **`std::memory_order_acq_rel`:** Объединяет свойства `acquire` и `release` (для read-modify-write операций).
    
      
    
5. **`std::memory_order_seq_cst` (Sequentially Consistent):** **Режим по умолчанию**. Гарантирует строгий глобальный единый порядок всех атомарных операций во всех потоках. Самый безопасный, но самый дорогой по скорости.
    
      
    

### 4. Асинхронные задачи (Tasks)

Определены в заголовочном файле `<future>` для передачи результатов между потоками без ручной работы с мьютексами.

  

- **`std::promise<T>`:** Канал отправки результата. Один поток записывает значение через `.set_value()`.
    
      
    
- **`std::future<T>`:** Канал получения результата. Другой поток блокируется и ждет результат через `.get()`.
    
      
    
- **`std::packaged_task<R(Args...)>`:** Обертка над любой callable-функцией, которая автоматически связывает результат её выполнения с `std::future`.
    
      
    
- **`std::async`:** Высокоуровневый запуск асинхронной задачи.
    
      
    - `std::launch::async` — гарантированный запуск в отдельном новом потоке.
        
          
        
    - `std::launch::deferred` — отложенный (ленивый) вызов в текущем потоке при вызове `future.get()`.
        

C++

```
#include <future>

int compute() { return 42; }

int main() {
    // Запуск задачи в фоновом потоке
    std::future<int> fut = std::async(std::launch::async, compute);
    
    // Выполнение другой работы в главном потоке...
    
    int result = fut.get(); // Блокирует поток до получения результата (42)
}
```

### Проблемы многопоточности (Основные понятия)

|**Проблема**|**Суть явления**|
|---|---|
|**Data Race**|Два потока одновременно обращаются к одной памяти, хотя бы один выполняет запись, и нет синхронизации. **Undefined Behavior**.|
|**Race Condition**|Поведение программы зависит от случайной последовательности / времени выполнения потоков.|
|**Deadlock**|Взаимная блокировка: Поток A ждет мьютекс M2 (удерживая M1), а Поток B ждет M1 (удерживая M2).|
|**Livelock**|Потоки постоянно меняют свое состояние в ответ на действия друг друга, но не делают полезной работы.|
|**False Sharing**|Два потока модифицируют разные переменные, находящиеся в одной кэш-линии CPU (64 байта), выбивая кэш друг друга.|
