Раннее и позднее связывание описывают, **когда** и **как** JVM решает, какой именно метод будет вызван по данной ссылке.

## Раннее связывание (early / static binding)

Раннее связывание — это когда вызываемый метод однозначно определяется **на этапе компиляции** по типу ссылки, а не по реальному объекту в рантайме.javarush+2

Характерно для:

- статических методов;
    
- приватных методов;
    
- часто — финальных методов (для них возможны оптимизации, хотя вызываются через `invokevirtual`).[pr0java.blogspot](http://pr0java.blogspot.com/2015/07/blog-post_66.html)
    

Компилятор уже «знает», какой именно код будет вызван, и может подставить прямой адрес (или проинлайнить вызов). В байткоде это обычно `invokestatic` и `invokespecial`.qna.habr+2

Пример:

java

`class A {     static void foo() { System.out.println("static A.foo"); }    private void bar() { System.out.println("private A.bar"); }     void test() {        foo();   // связывание статического метода заранее        bar();   // приватный, тоже известно заранее    } }`

## Позднее связывание (late / dynamic binding)

Позднее связывание — это когда выбор реализации метода происходит **во время выполнения программы**, исходя из **фактического типа объекта**, на который указывает ссылка.stackoverflow+3

Это и есть основа **полиморфизма**: по ссылке типа родителя вызывается переопределённый метод подкласса.

Пример:

java

`class Parent {     void say() { System.out.println("parent"); } } class Child extends Parent {     @Override    void say() { System.out.println("child"); } } Parent p = new Child(); p.say();  // во время выполнения решается, что вызывать Child.say()`

Тип переменной `Parent`, но JVM в рантайме смотрит на реальный объект `Child` и через таблицу виртуальных методов выбирает нужную реализацию. В байткоде — `invokevirtual`.stackoverflow+2

## Кратко для собеса

- **Раннее (статическое) связывание** — метод известен на этапе компиляции, тип определяется по ссылке; применяется для статических, приватных и ряда не‑виртуальных вызовов.javarush+1
    
- **Позднее (динамическое) связывание** — метод выбирается в рантайме по реальному типу объекта; это то, как в Java работает полиморфизм и переопределение методов.garden.struchkov+2
