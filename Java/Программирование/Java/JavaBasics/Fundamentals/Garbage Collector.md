GC **обычно** не ограничивается голым mark–sweep. Есть три базовых стратегии (на уровне идей):

- **Чистое подметание (mark–sweep без compact)**: просто пометили мусор и освободили их блоки, не трогая живые объекты.[](https://softwarecats.dev/blog/upravlenie-pamyatyu-v-java)
    
    - Плюс: быстро.
        
    - Минус: жёсткая фрагментация, почти не используется в чистом виде в современных JVM.
        
- **Подметание с компакцией (mark–compact)**:
    
    - после удаления мусора оставшиеся живые объекты **сдвигают** так, чтобы они шли плотным блоком, а свободная память собиралась в большой непрерывный кусок;
        
    - затем GC обновляет все ссылки на эти объекты (корни и внутренние поля), чтобы они указывали на новые адреса.[](https://setka.ru/posts/019134f7-977f-4690-9b67-a887d35dd515)
        
    - Плюс: почти нет фрагментации.
        
    - Минус: нужно двигать объекты → более дорогие паузы.
        
- **Копирующий (copying GC)**:
    
    - разделяем память условно на “from-space” и “to-space”;
        
    - все живые объекты **копируем** в "чистую" область, старую целиком освобождаем;[](https://softwarecats.dev/blog/upravlenie-pamyatyu-v-java)
        
    - очень просто: нет сложных списков свободных блоков, молодое поколение чистится очень быстро.
        
    - Плюс: супер-быстрое allocate (просто двигаем указатель), хорошая локальность.
        
    - Минус: нужно держать дублирующую область → расход памяти.
        

В современном Java GC это всё комбинируется: где-то копирование (молодое поколение), где-то mark–compact, где-то более сложные алгоритмы с регионами (G1, ZGC, Shenandoah).
