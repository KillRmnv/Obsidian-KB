**Планировщик потоков (Thread Scheduler)** в Java — это часть JVM, которая решает, какой поток будет выполняться в каждый конкретный момент времени.

## Как работает

|Аспект|Описание|
|---|---|
|**Задача**|Выбирает поток из очереди готовых к выполнению и выделяет ему процессорное время[](https://www.examclouds.com/ru/java/java-core-russian/switch-thread)|
|**Приоритеты**|Использует приоритеты потоков (1–10) как подсказку, но не гарантирует порядок выполнения[](https://struchkov.dev/blog/ru/threads-in-java-thread-and-runnable/)|
|**Квант времени**|Выделяет небольшое временное окно (квант) для выполнения потока[](https://topjava.ru/blog/mnogopotochnost-v-java-chast-4)|
|**Недетерминированность**|Точный порядок выполнения потоков **непредсказуем** и зависит от JVM и ОС|

## Приоритеты потоков

java

`Thread thread = new Thread(() -> { /* код */ }); thread.setPriority(Thread.MAX_PRIORITY);    // 10 thread.setPriority(Thread.NORM_PRIORITY);   // 5 (по умолчанию) thread.setPriority(Thread.MIN_PRIORITY);    // 1`

Поток с более высоким приоритетом **чаще** выбирается планировщиком, но это не гарантия.

## Методы, влияющие на планировщик

|Метод|Действие|
|---|---|
|`Thread.yield()`|Подсказывает планировщику, что поток готов уступить процессор другим потокам того же приоритета[](https://www.examclouds.com/ru/java/java-core-russian/switch-thread)|
|`Thread.sleep(ms)`|Приостанавливает поток на время, после чего он возвращается в就绪 (ready) состояние|
|`thread.join()`|Ждёт завершения указанного потока[](https://www.examclouds.com/ru/java/java-core-russian/switch-thread)|

## Важные моменты

1. **Планировщик не гарантирует порядок** — даже если поток с приоритетом 10 создан позже потока с приоритетом 1, он может выполниться первым или одновременно[](https://struchkov.dev/blog/ru/threads-in-java-thread-and-runnable/)
    
2. **Зависит от ОС** — JVM делегирует часть логики планировщику операционной системы[](https://www.examclouds.com/ru/java/java-core-russian/switch-thread)
    
3. **Не используйте приоритеты для синхронизации** — для координации потоков используйте `synchronized`, `Lock`, `volatile`, `CountDownLatch` и т.д.
    

Планировщик работает автоматически — разработчик не может напрямую контролировать, какой поток запустится следующим
