Вот полный перечень методов классического (legacy) API управления потоками в Java (`java.lang.Thread`, `java.lang.Object`, `java.lang.ThreadGroup`). Без привязок к `java.util.concurrent`, только факты: сигнатуры, назначение, поведение и статус.

---

###  `java.lang.Thread` (управление потоком)

| Метод | Сигнатура | Что делает |
|-------|-----------|------------|
| `start()` | `void start()` | Запускает новый поток ОС, вызывает `run()`. Повторный вызов → `IllegalThreadStateException`. |
| `run()` | `void run()` | Точка входа задачи. Вызывается автоматически после `start()`. Прямой вызов выполняется в текущем потоке (без создания нового). |
| `sleep(long)` | `static void sleep(long millis) throws InterruptedException` | Приостанавливает **текущий** поток на указанное время. **Не отпускает** захваченные мониторы (`synchronized`). |
| `sleep(long, int)` | `static void sleep(long millis, int nanos) throws InterruptedException` | То же, что выше, с наносекундной точностью. |
| `yield()` | `static void yield()` | Подсказка планировщику: уступить процессорное время другим потокам. Не гарантирует переключения, не влияет на приоритеты, не отпускает мониторы. |
| `interrupt()` | `void interrupt()` | Устанавливает флаг прерывания потока. Если поток в `sleep()/wait()/join()`, немедленно выбрасывает `InterruptedException` и сбрасывает флаг. |
| `isInterrupted()` | `boolean isInterrupted()` | Проверяет флаг прерывания. **Не сбрасывает** его. |
| `interrupted()` | `static boolean interrupted()` | Проверяет флаг прерывания **текущего** потока и **сбрасывает** его в `false`. |
| `join()` | `void join() throws InterruptedException` | Текущий поток блокируется до завершения целевого потока (`thread.isAlive() == false`). |
| `join(long)` | `void join(long millis) throws InterruptedException` | Ждёт завершения не дольше `millis`. При `0` → аналог `join()` без таймаута. |
| `join(long, int)` | `void join(long millis, int nanos) throws InterruptedException` | То же, с наносекундной точностью. |
| `setDaemon(boolean)` | `final void setDaemon(boolean on)` | Делает поток демоном. Вызывается **до** `start()`. Демоны не мешают завершению JVM. |
| `isDaemon()` | `boolean isDaemon()` | Возвращает `true`, если поток демона. |
| `setPriority(int)` | `final void setPriority(int newPriority)` | Устанавливает приоритет (1 `MIN` ... 10 `MAX`, по умолчанию 5 `NORM`). Зависит от ОС-планировщика, не гарантирует порядок выполнения. |
| `getPriority()` | `int getPriority()` | Возвращает текущий приоритет. |
| `setName(String)` | `final void setName(String name)` | Задаёт имя потока (для отладки, логирования, профайлеров). |
| `getName()` | `String getName()` | Возвращает имя потока. |
| `getId()` | `long getId()` | Возвращает уникальный ID потока (монотонно растущий, не переиспользуется). |
| `currentThread()` | `static Thread currentThread()` | Возвращает ссылку на выполняющийся в данный момент поток. |
| `activeCount()` | `static int activeCount()` | Возвращает примерное количество активных потоков в текущей группе. |
| `enumerate(Thread[])` | `static int enumerate(Thread[] tarray)` | Записывает активные потоки в массив. Возвращает количество скопированных. |
| `holdsLock(Object)` | `static boolean holdsLock(Object obj)` | Возвращает `true`, если текущий поток владеет монитором `obj`. |
| `setUncaughtExceptionHandler()` | `void setUncaughtExceptionHandler(Thread.UncaughtExceptionHandler eh)` | Задаёт обработчик необработанных исключений в этом потоке. |
| `getUncaughtExceptionHandler()` | `Thread.UncaughtExceptionHandler getUncaughtExceptionHandler()` | Возвращает текущий обработчик. |

###  `java.lang.Thread` (методы, помеченные `@Deprecated`)
*Оставлены в JDK только для обратной совместимости. Их использование нарушает инварианты JVM и ведёт к неопределённому поведению.*

| Метод | Почему deprecated |
|-------|-------------------|
| `stop()` / `stop(Throwable)` | Принудительно завершает поток, **разрушая стек вызовов**. Освобождает все мониторы **без выполнения `finally`**. Объекты остаются в частично изменённом состоянии → data corruption. |
| `suspend()` | Приостанавливает поток **без освобождения мониторов**. Если приостановленный поток держал lock, другие потоки навсегда заблокируются → deadlock. |
| `resume()` | Возобновляет поток, приостановленный через `suspend()`. Бессмыслен без `suspend()`, унаследован из той же опасной модели. |
| `destroy()` | Никогда не был реализован. Вызов всегда бросает `NoSuchMethodError`. Оставлен только для сигнатурной совместимости. |
| `countStackFrames()` | Считает кадры в стеке потока. Требует предварительного `suspend()`. Унаследован от unsafe-модели. |

###  `java.lang.Object` (мониторные методы)
*Работают только внутри `synchronized(obj)` или синхронизированного метода.*

| Метод | Что делает |
|-------|------------|
| `wait()` | Отпускает монитор `obj`, переводит текущий поток в `WAITING`. Выходит при `notify()/notifyAll()`, прерывании или ложном пробуждении. |
| `wait(long timeout)` | То же, но автоматически выходит по таймауту (мс). `timeout ≤ 0` → бесконечное ожидание. |
| `wait(long timeout, int nanos)` | То же, с наносекундной точностью. Внутренне конвертирует в миллисекунды с учётом переполнения. |
| `notify()` | Переводит **один** произвольный поток из очереди ожидания `obj` в состояние `BLOCKED` (ожидание захвата монитора). Не отпускает монитор вызывающего потока. |
| `notifyAll()` | Переводит **все** ждущие потоки в состояние `BLOCKED`. Конкурируют за монитор. Проигравшие возвращаются в `WAITING`, если условие в `while` не выполнено. |

---

###  `java.lang.ThreadGroup` (групповое управление)
*Класс оставлен в JDK, но считается legacy. Большинство методов делегируют или дублируют логику `Thread`.*

| Метод | Что делает |
|-------|------------|
| `interrupt()` | Вызывает `interrupt()` на всех живых потоках группы. |
| `stop()` | Вызывает `stop()` на всех потоках группы.  `Deprecated` (те же риски, что у `Thread.stop()`). |
| `suspend()` / `resume()` | Приостанавливает/возобновляет все потоки группы.  `Deprecated`. |
| `destroy()` | Удаляет группу, если она пуста и не содержит подгрупп. Не останавливает потоки. |
| `list()` / `list(PrintStream, int)` | Выводит дерево потоков и подгрупп в консоль/стрим (для отладки). |
| `activeCount()` / `activeGroupCount()` | Возвращает число активных потоков/подгрупп в группе. |
| `enumerate(Thread[])` / `enumerate(ThreadGroup[])` | Заполняет массивы потоками/группами. |
| `getParent()` / `getName()` / `isDaemon()` / `setDaemon(boolean)` / `getMaxPriority()` / `setMaxPriority(int)` / `checkAccess()` | Управление свойствами группы, проверка прав доступа. |

###  Ключевые поведенные нюансы legacy API
1. `sleep()`, `yield()`, `interrupt()` **не работают с мониторами**. Они не отпускают и не захватывают `synchronized`-блоки.
2. `wait()` **обязательно** отпускает монитор перед переходом в ожидание и **обязательно** возвращает его перед выходом из метода.
3. `notify()/notifyAll()` **не отдают** монитор мгновенно. Разбуженный поток встаёт в очередь на захват и продолжит выполнение только после выхода вызывающего потока из `synchronized`.
4. `stop()/suspend()` **нарушают atomicity**. JVM не может гарантировать консистентность heap-объектов при их использовании. Поэтому они помечены `@Deprecated` и запрещены в secure-конфигурациях.
5. `yield()` — **подсказка**, а не гарантия. На одноядерных CPU или при агрессивных планировщиках ОС может не давать эффекта.

Если нужен разбор конкретных пограничных случаев (например, как `wait()` ведёт себя при `ThreadDeath`, как `interrupt()` взаимодействует с нативными вызовами, или как `notifyAll()` работает при реентерабельных `synchronized`-блоках) — скажи, распишу чисто по спецификации JVM.
