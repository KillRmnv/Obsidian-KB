# Java SE — Шпаргалка: ООП (теория + подводные камни собесов)

***

## 1. Классы, объекты, конструкторы

### Класс vs Объект

**Класс** — шаблон (blueprint), описывающий состояние (поля) и поведение (методы). **Объект** — конкретный экземпляр класса, созданный в Heap через `new`. Каждый объект имеет собственную копию нестатических полей, но разделяет статические поля и методы со всеми объектами класса.[1]

### Конструкторы

Конструктор — специальный метод инициализации объекта. Технически это не метод: у него нет возвращаемого типа (даже `void`), его имя совпадает с именем класса. Конструктор **не наследуется**, но вызывается через цепочку `super()`.[2][3]

Если явно не определить ни одного конструктора — компилятор автоматически добавляет **дефолтный конструктор** (без параметров). Как только написан хоть один конструктор — дефолтный перестаёт генерироваться.

**Constructor chaining:** `this()` — вызов другого конструктора этого же класса; `super()` — вызов конструктора родителя. Оба должны быть **первой строкой** конструктора. Из-за этого нельзя использовать `this()` и `super()` в одном конструкторе одновременно.[3]

###  Подводные камни

**Можно ли создать объект абстрактного класса?** Нет, напрямую — нельзя. Но абстрактный класс **имеет конструктор**, который вызывается неявно при создании объекта дочернего класса через `super()`.[2]

**Конструктор может бросать исключение** — checked exception при этом нужно объявить через `throws`.

## 2. Четыре принципа ООП

### Инкапсуляция

Инкапсуляция — **сокрытие внутреннего состояния** объекта и предоставление контролируемого доступа через публичный интерфейс (геттеры/сеттеры). Реализуется через модификаторы доступа: `private`, `protected`, `package-private`, `public`.[4][1]

Главная цель — не просто скрыть поля, а **гарантировать инварианты объекта**: логику валидации, ограничения на значения, атомарность изменений. Без сеттера никто не установит возраст `-5` или `null` там, где это недопустимо.

### Наследование

Наследование (`extends`) — механизм, при котором дочерний класс получает поля и методы родительского. Java поддерживает только **одиночное наследование** (один `extends`), но множественное — через интерфейсы (`implements`).[5][6]

Все классы в Java неявно наследуют `Object` — корень иерархии. Это даёт каждому классу методы `equals()`, `hashCode()`, `toString()`, `getClass()`, `clone()`, `wait()`, `notify()`.[6]

**IS-A vs HAS-A:** наследование выражает отношение "является" (IS-A), агрегация/композиция — "содержит" (HAS-A). Принцип Liskov (LSP): дочерний класс должен быть подставляемым вместо родительского без нарушения корректности программы.[5]

### Полиморфизм[4][1][5]

Полиморфизм существует в двух формах:

- **Compile-time (статический)** — перегрузка методов (overloading): одно имя, разные параметры. Решается компилятором на этапе компиляции по сигнатуре.
- **Runtime (динамический)** — переопределение методов (overriding): дочерний класс заменяет реализацию родителя. Решается JVM в момент вызова по **реальному типу объекта**, а не по типу ссылки.

Ключевой механизм runtime полиморфизма — **Virtual Method Table (vtable)**: JVM ведёт таблицу методов для каждого класса и ищет реализацию снизу вверх по иерархии.

### Абстракция

Абстракция — скрытие деталей реализации, предоставление только необходимого интерфейса. Реализуется через **abstract классы** и **интерфейсы**.[7][1]

## 3. Abstract классы vs Интерфейсы

Это один из самых частых вопросов на собесе.[8][9]

| Характеристика | Abstract класс | Интерфейс |
|---|---|---|
| Наследование | Один (`extends`) | Несколько (`implements`) |
| Конструктор |  есть |  нет |
| Поля | Любые (instance, static) | Только `public static final` (константы) |
| Методы | Абстрактные + конкретные | До Java 8: только абстрактные. С Java 8: + `default`, `static`. С Java 9: + `private`. |
| Модификаторы методов | Любые | Методы `public` по умолчанию |
| Состояние (state) |  может хранить |  не хранит (нет instance-полей) |
| Отношение | IS-A ("является") | CAN-DO ("умеет делать") |

**Когда абстрактный класс:** нужно разделить общее состояние и базовое поведение между родственными классами (Template Method Pattern).[10][7]

**Когда интерфейс:** нужно определить контракт для несвязанных классов, либо нужно множественное наследование поведения.[7][10]

###  Подводные камни

**Diamond Problem с default методами (Java 8+).** Если класс реализует два интерфейса с одинаковым `default` методом — **ошибка компиляции**. Обязательно переопределить метод в классе. Если нужно вызвать конкретную реализацию: `InterfaceName.super.method()`.[11][12][13][14][15]

**Приоритет при конфликте:** класс (или суперкласс) > более конкретный интерфейс > менее конкретный.[12][14]

**Abstract класс может не реализовывать все методы интерфейса** — оставляет нереализованные методы абстрактными, перекладывая реализацию на конкретный подкласс.[2]

**Интерфейс не может иметь конструктор** — поэтому у него нет состояния. Поля интерфейса неявно `public static final`. Написать `int x = 5` в интерфейсе — это константа, не instance-поле.[7]

## 4. Ключевые слова: static, final, this, super

### static[16][17]

`static` означает принадлежность **классу**, а не экземпляру.

- **static поле** — одно на весь класс, разделяется всеми объектами. Инициализируется при загрузке класса.
- **static метод** — вызывается через имя класса, не имеет доступа к `this` и нестатическим членам. Не может быть переопределён (overriding невозможен) — только **скрыт (hiding)** в дочернем классе.
- **static блок** — выполняется однократно при загрузке класса, до любого конструктора.
- **static nested class** — вложенный класс, не имеющий ссылки на внешний. В отличие от inner class, можно создать без экземпляра внешнего.

### final[18][17]

- **final переменная** — нельзя переприсвоить после инициализации. Для ссылочного типа: ссылка фиксирована, но объект может изменяться внутри.
- **final метод** — нельзя переопределить в дочернем классе.
- **final класс** — нельзя унаследоваться. `String`, `Integer`, все wrapper-классы — `final`.
- **final поле объекта** — обязано быть инициализировано либо при объявлении, либо в конструкторе.

### this[17][18][3]

`this` — ссылка на **текущий объект**. Используется для:
1. Разрешения конфликта имён между полями и параметрами.
2. Передачи текущего объекта как аргумента.
3. Вызова другого конструктора этого класса: `this(args)` — должен быть первой строкой.
4. Возврата текущего объекта (паттерн Builder).

`this` **недоступен** в static методах — статический метод не привязан к объекту.

### super[19][18][3]

`super` — ссылка на **родительский класс**. Используется для:
1. Доступа к полям родителя, если они скрыты полями дочернего класса.
2. Вызова метода родителя: `super.method()`.
3. Вызова конструктора родителя: `super(args)` — обязан быть первой строкой конструктора.

Если конструктор дочернего класса не вызывает `super(...)` явно — компилятор автоматически вставляет `super()` (без аргументов). Если у родителя нет конструктора без параметров — **ошибка компиляции**.

###  Подводные камни

**"Можно ли вызвать `this()` и `super()` в одном конструкторе?"** — Нет. Оба требуют быть первой строкой — нельзя одновременно.[3]

**"Можно ли переопределить static метод?"** — Нет. При объявлении метода с той же сигнатурой в дочернем классе происходит **method hiding**, а не overriding. Вызываемый метод зависит от **типа ссылки**, а не типа объекта.[16]

**Ковариантный возвращаемый тип (с Java 5):** при override можно сузить тип возвращаемого значения до подкласса.[20][21][22][23]

**Можно ли override метод с менее строгим access modifier?** — Да (расширить доступ можно). Сузить — нельзя.[24]

## 5. Блоки инициализации

### Static блок

Выполняется **один раз** при первой загрузке класса JVM. Используется для инициализации статических полей со сложной логикой, которую нельзя уместить в одно выражение. Классов может быть несколько статических блоков — они выполняются **сверху вниз** в порядке появления в коде.[25][26]

### Instance (нестатический) блок

Выполняется **каждый раз** при создании объекта, **до конструктора**. Фактически компилятор вставляет содержимое instance-блока в начало **каждого** конструктора. Полезен для общей инициализационной логики, которую не хочется дублировать в каждом конструкторе.[25]

### Полный порядок инициализации при создании объекта с наследованием[27][28][26]

1. Статические поля и static-блоки **родителя** (в порядке появления в коде, однократно)
2. Статические поля и static-блоки **дочернего класса** (однократно)
3. Instance-поля и instance-блоки **родителя** (в порядке появления)
4. Конструктор **родителя**
5. Instance-поля и instance-блоки **дочернего класса**
6. Конструктор **дочернего класса**

###  Подводные камни

**Порядок важен:** если статический блок стоит после объявления статического поля — он видит уже инициализированное значение. Если до — значение ещё дефолтное (0, null).

**Instance-блок выполняется до конструктора** — не после. Это часто путают.

**При вызове `super()` в дочернем конструкторе:** сначала полностью инициализируется родитель (включая его instance-блоки и конструктор), только потом — дочерний.

## 6. Вложенные, анонимные, внутренние классы

### Типы вложенных классов[29][30][31]

| Тип | static? | Доступ к outer | Создание |
|---|---|---|---|
| **Static nested class** |  | Только static члены outer | `new Outer.Inner()` |
| **Inner class (нестатический)** |  | Все члены outer, включая private | `outer.new Inner()` |
| **Local class** |  | Члены outer + effectively final локальные переменные | Внутри метода |
| **Anonymous class** |  | Члены outer + effectively final переменные | `new Interface() {...}` |

### Static Nested Class

Не хранит ссылку на внешний класс. Ведёт себя как обычный top-level класс, просто вложен для логической группировки. Может содержать static и instance члены.[30][31]

### Inner Class (нестатический вложенный)

Неявно хранит ссылку на экземпляр внешнего класса. Не может содержать static члены (кроме constnat `static final`). Имеет доступ ко всем членам внешнего класса, включая `private`.[29][30]

### Anonymous Class[32][33]

Определяется и инстанциируется в одном выражении. Может либо **расширять класс**, либо **реализовывать интерфейс** — но не то и другое одновременно. Не может реализовывать несколько интерфейсов. Не может иметь явных конструкторов (нет имени). До Java 8 активно использовался для Runnable, Comparator, callback'ов — сейчас заменён лямбдами.

###  Подводные камни

**Утечка памяти через Inner class:** нестатический inner class держит ссылку на экземпляр outer class. Если inner передаётся за пределы outer и живёт долго — GC не может собрать outer, даже если он больше не нужен. Решение: использовать static nested class там, где не нужен доступ к outer.[31]

**Anonymous class не может быть повторно использован** — каждое место создания порождает отдельный `.class` файл (`Outer$1.class`, `Outer$2.class`).

**Локальные переменные в anonymous/local class** должны быть effectively final (с Java 8). До этого требовался явный `final`.

## 7. Enums

### Теория

`enum` в Java — это специальный класс, неявно расширяющий `java.lang.Enum`. Каждая константа — `public static final` экземпляр этого класса. Enums **не могут** расширять другие классы (уже расширяют `Enum`), но могут **реализовывать интерфейсы**.[34][35]

Enum автоматически предоставляет:
- `values()` — массив всех констант в порядке объявления
- `valueOf(String)` — константа по имени (чувствительно к регистру)
- `name()` — имя константы как строка
- `ordinal()` — порядковый номер (0-based)

Enum **безопасен для Singleton паттерна** — JVM гарантирует единственность каждой константы. Enum-синглтон защищён от рефлексии и десериализации.

### Enum с методами и абстрактными методами[36][37][34]

Enum может содержать поля, конструкторы (всегда `private` или `package-private`) и методы. Каждая константа может иметь **собственную реализацию** метода через constant-specific class body — это аналог Strategy Pattern. Enum может объявить `abstract` метод — тогда каждая константа обязана его реализовать.

###  Подводные камни

**`ordinal()` — хрупкое решение.** Порядковый номер зависит от порядка объявления. Если добавить константу посередине — все ordinal'ы смещаются. Никогда не храни ordinal в БД или конфигах. Используй явное поле с кодом/идентификатором.[34]

**`valueOf()` чувствителен к регистру** и бросает `IllegalArgumentException` при несовпадении — не `null`.

**Enum нельзя создать через `new`** — только JVM создаёт константы. Рефлексивное создание запрещено явно.

**Enum можно использовать в `switch`** — и это один из рекомендуемых use case'ов.

## 8. Records (Java 16+)

### Теория[38][39][40][41]

**Record** — специальная форма класса, предназначенная для **неизменяемых data-carrier объектов** (DTO, value objects). Компилятор автоматически генерирует:
- `private final` поля для каждого компонента
- Канонический конструктор (со всеми компонентами)
- Accessor-методы с именем компонента (не `getX()`, а `x()`)
- `equals()` и `hashCode()` на основе всех компонентов
- `toString()` со всеми компонентами

### Ограничения records

- Нельзя `extends` другой класс (неявно extends `java.lang.Record`)
- Нельзя объявить нестатические instance-поля, кроме компонентов
- Нельзя быть `abstract`
- Все поля-компоненты неявно `private final`

Record **может**: реализовывать интерфейсы, иметь static поля и методы, иметь дополнительные instance-методы, иметь несколько конструкторов (включая compact constructor).

### Компактный конструктор (Compact Constructor)

Специальный синтаксис для валидации/преобразования без явного присваивания полей — компилятор сам добавит `this.x = x` после тела компактного конструктора.[41][38]

###  Подводные камни

**Records — shallow immutable, не deep immutable.** Если компонент — изменяемый объект (например, `List`), его содержимое можно изменить. `record Person(List<String> names)` — список внутри изменяем.[41]

**Records нельзя использовать как JPA/Hibernate сущности.** JPA требует: наличие конструктора без параметров, изменяемые поля, возможность проксирования. Всё это противоречит природе record.[39][40][41]

**Accessor-методы называются `x()`, не `getX()`** — несовместимо с JavaBeans-конвенцией. Библиотеки, рассчитывающие на `getX()` (Jackson без конфигурации, некоторые фреймворки), могут работать некорректно.

**Record — `final` класс.** Нельзя унаследоваться от record.

**`equals()` у records сравнивает структурно** — два record с одинаковыми значениями компонентов равны, даже если это разные объекты. Это отличается от поведения обычного класса по умолчанию.
