# Java SE — Шпаргалка: Collections Framework (теория + подводные камни собесов)

***

## 1. Иерархия Collections Framework

```
Iterable
└── Collection
    ├── List             (упорядоченные, с дубликатами)
    │   ├── ArrayList
    │   ├── LinkedList
    │   └── Vector → Stack
    ├── Set              (уникальные элементы)
    │   ├── HashSet
    │   ├── LinkedHashSet
    │   └── SortedSet → NavigableSet → TreeSet
    └── Queue            (очередь FIFO)
        ├── PriorityQueue
        └── Deque → ArrayDeque, LinkedList

Map                      (НЕ наследует Collection!)
├── HashMap
├── LinkedHashMap
├── Hashtable
└── SortedMap → NavigableMap → TreeMap
```

**Важно:** `Map` — **не** часть иерархии `Collection`. Это отдельная иерархия, потому что Map хранит пары ключ-значение, а не отдельные элементы — принципиально другая абстракция.[1][2]

**Iterable** — корневой интерфейс, даёт возможность использовать `for-each`. Единственный метод — `iterator()`.[3]

**Collection** — расширяет `Iterable`, добавляет `add()`, `remove()`, `contains()`, `size()`, `clear()`. Не имеет прямых реализаций — все реализации через `List`, `Set`, `Queue`.[4][3]

## 2. List — упорядоченные коллекции с дубликатами

### ArrayList[5][6][7][8]

**Внутренняя структура:** динамический массив (`Object[]`). Начальная ёмкость — **16** (с Java 8 при первом добавлении), по умолчанию конструктор без аргументов создаёт пустой массив. При переполнении — рост на **50%**: `newCapacity = oldCapacity + (oldCapacity >> 1)`.

| Операция | Сложность |
|---|---|
| `get(index)` | O(1) — случайный доступ по индексу |
| `add()` в конец | O(1) амортизированно |
| `add(index, ...)` в середину | O(n) — сдвиг элементов |
| `remove(index)` из середины | O(n) — сдвиг элементов |
| `contains()` | O(n) — линейный поиск |

Идеален для частого чтения и доступа по индексу. Элементы в памяти расположены **контигуально** — хорошая cache locality.

### LinkedList[7][9][8][5]

**Внутренняя структура:** двусвязный список (каждый узел хранит ссылки на prev и next + данные). Реализует и `List`, и `Deque`.

| Операция | Сложность |
|---|---|
| `get(index)` | O(n) — обход от начала или конца |
| `add()`/`remove()` в начало/конец | O(1) |
| `add(index, ...)`/`remove(index)` в середину | O(n) — поиск + O(1) вставка |

**На практике LinkedList почти всегда медленнее ArrayList**, даже для вставок в середину — из-за плохой cache locality (узлы разбросаны по Heap). Оправдан только как `Deque` (очередь/стек).[5][7]

### ⚠️ Подводные камни

**ArrayList.remove(int) vs remove(Object).** `list.remove(1)` — удалить по **индексу**. `list.remove(Integer.valueOf(1))` — удалить по **значению**. Для `List<Integer>` вызов `list.remove(1)` удалит элемент с индексом 1, а не число 1.[4]

**ArrayList не синхронизирован.** Параллельный доступ — `ConcurrentModificationException` или data corruption. Потокобезопасные альтернативы: `CopyOnWriteArrayList`, `Collections.synchronizedList()`.

## 3. Map — структуры ключ-значение

### HashMap — внутреннее устройство (главная тема на собесах)[10][11][12][13][14]

**Структура:** массив "бакетов" (`Node<K,V>[] table`). Каждый бакет — цепочка из `Node` объектов (до Java 8 — LinkedList, Java 8+ — LinkedList или Red-Black Tree).

**Алгоритм `put(key, value)`:**
1. Вычисляется `hashCode()` ключа
2. Применяется дополнительное хэширование: `hash ^ (hash >>> 16)` — это "spreading" для лучшего распределения
3. Вычисляется индекс бакета: `(table.length - 1) & hash` — работает через битовую маску (поэтому ёмкость всегда **степень двойки**)
4. Если бакет пуст — вставляется новый `Node`
5. Если коллизия — добавляется в цепочку: сравнивается `hash` и затем `equals()` для поиска дубликата ключа

**Treeification (Java 8+):** если в одном бакете накапливается более **8 элементов** — цепочка превращается в Red-Black Tree. Обратная конвертация в список — при уменьшении до **6 элементов**. Это улучшает worst-case с O(n) до **O(log n)**.[11][13]

**Load Factor и Resize:** дефолтный load factor = **0.75**. Когда `size > capacity * 0.75` — происходит **rehashing**: создаётся новый массив вдвое больше, все элементы перераспределяются. Это дорогая операция — O(n).[12][13][10]

| Операция | Average | Worst Case (Java 8+) |
|---|---|---|
| `get()` / `put()` | O(1) | O(log n) с деревьями |
| `containsKey()` | O(1) | O(log n) |

**Null в HashMap:** допускает **один** `null` ключ (помещается в бакет 0) и любое количество `null` значений.[11][4]

### LinkedHashMap[10]

Расширяет `HashMap`, добавляет двусвязный список через все Entry — сохраняет **порядок вставки** (или порядок доступа в LRU-режиме). Немного медленнее HashMap из-за поддержки списка. Используется для LRU-кэшей: конструктор `LinkedHashMap(capacity, loadFactor, accessOrder=true)` плюс override `removeEldestEntry()`.

### TreeMap[15][16]

**Внутренняя структура:** Red-Black Tree (самобалансирующееся бинарное дерево поиска). Все операции — O(log n). Хранит ключи в **отсортированном порядке** (натуральный порядок или `Comparator`). Предоставляет методы `firstKey()`, `lastKey()`, `headMap()`, `tailMap()`, `floorKey()`, `ceilingKey()`.

`null` ключи **не допускаются** — при сортировке `null` вызовет `NullPointerException`.[15]

### ⚠️ Подводные камни HashMap

**Изменяемый ключ — главная ловушка.** Если изменить объект, используемый как ключ, после вставки в `HashMap` — его `hashCode()` изменится. При поиске JVM вычислит новый индекс бакета и не найдёт запись. Элемент "пропадёт". Всегда использовать **immutable объекты** как ключи (`String`, `Integer`, etc.).[13][14][10]

**Плохой `hashCode()` уничтожает производительность.** Если все ключи дают один хэш — всё попадёт в один бакет. До Java 8: O(n) для каждой операции. Java 8+: O(log n) благодаря treeification, но всё равно плохо.[11]

**`HashMap` не потокобезопасен.** При конкурентном доступе — data race и бесконечные циклы (в Java 7 при resize). Для многопоточности: `ConcurrentHashMap`.

## 4. Set — уникальные элементы

### HashSet

Реализован как `HashMap` с dummy-значением `PRESENT` (static final Object). `add(e)` внутри вызывает `map.put(e, PRESENT)`. Уникальность гарантируется через `hashCode()` + `equals()`.[11]

**Порядок не гарантируется** и может меняться при resize. Допускает `null`.[4]

### LinkedHashSet

Реализован через `LinkedHashMap`. Сохраняет **порядок вставки**. Немного медленнее `HashSet`.

### TreeSet[16][17][18]

Реализован через `TreeMap`. Хранит уникальные элементы в **отсортированном порядке**. Все операции — O(log n). Элементы должны быть `Comparable` или нужно передать `Comparator` в конструктор. `null` не допускается.

### ⚠️ Подводные камни Set

**`HashSet` уникальность зависит от `hashCode()` и `equals()`.** Если не переопределить оба метода в пользовательском классе — `HashSet` будет считать все объекты разными (сравнение по ссылке).

**TreeSet сортирует через `compareTo()`/`compare()`, а не через `equals()`.** Если `compareTo()` возвращает 0 — TreeSet считает объекты одинаковыми и не добавит. Несогласованность `compareTo()` и `equals()` нарушит контракт `Set`.

## 5. Queue и Deque

**Queue** — FIFO. Методы: `offer()` (добавить), `poll()` (извлечь и удалить), `peek()` (только посмотреть). Методы `add()`/`remove()`/`element()` — аналоги, но бросают исключения вместо возврата `null`.

**PriorityQueue** — min-heap (минимальный элемент достаётся первым). Упорядочивание через `Comparable` или `Comparator`. Не гарантирует порядок при итерации — только при `poll()`. `null` не допускается.

**Deque (Double-Ended Queue)** — двусторонняя очередь. Реализации: `ArrayDeque` (на массиве) и `LinkedList` (на списке). `ArrayDeque` рекомендуется как Stack вместо устаревшего `Stack`.[4]

## 6. Comparable vs Comparator[19][20][21][22][23]

| Характеристика | Comparable | Comparator |
|---|---|---|
| Пакет | `java.lang` | `java.util` |
| Метод | `compareTo(T o)` — 1 аргумент | `compare(T o1, T o2)` — 2 аргумента |
| Где реализуется | Внутри самого класса | Отдельный класс или лямбда |
| Сортировок | Одна (естественная) | Сколько угодно |
| Модификация класса | Требуется | Не требуется |
| Functional interface | ❌ | ✅ (Java 8+, можно лямбды) |
| Использование | `Collections.sort(list)` без аргументов | `Collections.sort(list, comparator)` |

**Comparable** — "natural ordering": класс сам знает, как сравниваться. `String`, `Integer`, `Date` уже реализуют `Comparable`.[22][19]

**Comparator** — "custom ordering": логика вынесена наружу. Можно создать несколько компараторов для одного класса. С Java 8 — цепочки: `Comparator.comparing(...).thenComparing(...)`.[20][22]

### ⚠️ Подводные камни

**Контракт `compareTo()`:** должен быть антисимметричным (`a.compareTo(b)` и `b.compareTo(a)` имеют противоположные знаки), транзитивным, согласованным с `equals()`. Нарушение контракта ломает сортировку и TreeSet/TreeMap.[21]

**Integer overflow при реализации через вычитание.** Классическая ошибка: `return a - b` в `compareTo()` — при больших числах возможен overflow и неправильный знак результата. Правильно: `Integer.compare(a, b)`.

## 7. Iterator и ListIterator[24][25][26][27][11]

### Iterator

Базовый интерфейс для обхода коллекций. Три метода: `hasNext()`, `next()`, `remove()` (удаляет последний возвращённый элемент).

**Fail-Fast** итераторы (ArrayList, HashMap, HashSet...) — при **структурном изменении** коллекции во время итерации бросают `ConcurrentModificationException`. Работает через счётчик `modCount`: при каждом изменении коллекции инкрементируется, при каждом `next()` проверяется.

**Безопасное удаление при итерации** — только через `iterator.remove()`, а не через `collection.remove()`.[25]

### ListIterator

Расширяет `Iterator`, добавляет:
- Двунаправленный обход: `hasPrevious()`, `previous()`
- `add()` — вставка в текущую позицию
- `set()` — замена последнего возвращённого элемента
- `nextIndex()`, `previousIndex()`

Доступен только у `List` реализаций (не у `Set`).[11]

### Fail-Fast vs Weakly Consistent (Fail-Safe)[26][27][24][25]

| | Fail-Fast | Weakly Consistent |
|---|---|---|
| При изменении | `ConcurrentModificationException` | Продолжает работу |
| Работает на | Оригинальной коллекции | Снимке или допускает изменения |
| Примеры | `ArrayList`, `HashMap`, `HashSet` | `CopyOnWriteArrayList`, `ConcurrentHashMap` |
| Гарантии видимости изменений | — | Могут быть видны или нет (weakly consistent) |

**Замечание:** термин "fail-safe" технически некорректен — Java-документация использует термин **"weakly consistent"** для итераторов из `java.util.concurrent`.[26]

### ⚠️ Подводные камни Iterator

**`ConcurrentModificationException` не гарантирован.** Это best-effort механизм. В однопоточном коде он срабатывает надёжно, но в многопоточном — нет. Нельзя использовать его как синхронизационный механизм.

**`remove()` без предшествующего `next()`** бросает `IllegalStateException`.

**`for-each` использует Iterator под капотом**, поэтому модификация коллекции в for-each тоже вызывает `ConcurrentModificationException`.

## 8. Итоговая таблица: выбор реализации

| Задача                                         | Реализация             |
| ---------------------------------------------- | ---------------------- |
| Частый доступ по индексу                       | `ArrayList`            |
| Частое добавление/удаление в начало            | `ArrayDeque`           |

| Уникальные элементы, сохранить порядок вставки | `LinkedHashSet`        |
| Уникальные элементы, сортировка                | `TreeSet`              |
| Key-value, порядок неважен                     | `HashMap`              |
| Key-value, сохранить порядок вставки / LRU-кэш | `LinkedHashMap`        |
| Key-value, сортировка по ключу, range queries  | `TreeMap`              |
| Приоритетная очередь                           | `PriorityQueue`        |
| Stack / Deque                                  | `ArrayDeque`           |
| Потокобезопасный Map                           | `ConcurrentHashMap`    |
| Потокобезопасный List с редкими записями       | `CopyOnWriteArrayList` |
