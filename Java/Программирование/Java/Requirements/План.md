  - **O** — Open/Closed
  - **L** — Liskov Substitution
  - **I** — Interface Segregation
  - **D** — Dependency Inversion

### 1.2 `equals()` и `hashCode()`

**Контракт `equals()`:**
1. Рефлексивность: `x.equals(x) == true`
2. Симметричность: `x.equals(y) == y.equals(x)`
3. Транзитивность: если `x.equals(y)` и `y.equals(z)`, то `x.equals(z)`
4. Консистентность: при неизменных данных результат не меняется
5. `x.equals(null) == false`

**Контракт `hashCode()`:**
- Если `x.equals(y)` → `x.hashCode() == y.hashCode()`
- Обратное **не обязательно** (коллизии допустимы)
- При переопределении `equals` **обязательно** переопределять `hashCode`

**Зачем это важно для коллекций:**
- `HashMap`, `HashSet` используют `hashCode()` для определения бакета, затем `equals()` для точного совпадения
- Если не переопределить `hashCode` — объекты с одинаковыми полями попадут в разные бакеты → `contains()` вернёт `false`

```java
@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof Person)) return false;
    Person p = (Person) o;
    return age == p.age && Objects.equals(name, p.name);
}

@Override
public int hashCode() {
    return Objects.hash(name, age);
}
```

### 1.3 Строки (`String`, `StringBuilder`, `StringBuffer`)

| | `String` | `StringBuilder` | `StringBuffer` |
|---|---|---|---|
| Изменяемость |  immutable |  mutable |  mutable |
| Thread-safe |  (неизменна) |  |  (synchronized) |
| Производительность | Медленно при конкатенации | Быстро | Медленнее SB |

**String Pool:**
- Литералы (`"hello"`) помещаются в пул в heap — повторные литералы используют тот же объект
- `new String("hello")` — всегда создаёт новый объект вне пула
- `intern()` — принудительно помещает в пул и возвращает ссылку из пула

**Частые вопросы:**
- `"a" == "a"` → `true` (один объект из пула)
- `new String("a") == new String("a")` → `false`
- `new String("a").equals(new String("a"))` → `true`
- Почему `String` immutable? → безопасность, кэширование hashCode, thread-safety, String Pool

### 1.4 Исключения

**Иерархия:**
```
Throwable
 Error           (OutOfMemoryError, StackOverflowError) — не ловить
 Exception
     RuntimeException (unchecked) — NPE, AIOOBE, ClassCastException
     Checked exceptions — IOException, SQLException
```

**Checked vs Unchecked:**
- **Checked** — компилятор требует обработки (`try/catch` или `throws`)
- **Unchecked** (`RuntimeException`) — не требуют обязательной обработки

**try-with-resources:**
```java
try (InputStream is = new FileInputStream("file.txt")) {
    // AutoCloseable — close() вызовется автоматически
} catch (IOException e) {
    e.printStackTrace();
}
```

**Важные нюансы:**
- `finally` выполняется всегда (кроме `System.exit()` и краша JVM)
- В `finally` не стоит делать `return` — перекрывает return из `try`
- `throw` бросает исключение, `throws` — объявляет в сигнатуре метода

##  Блок 2 — Коллекции

### 2.1 Общие принципы

**Иерархия Collections Framework:**
```
Iterable
 Collection
     List  (ArrayList, LinkedList, Vector)
     Set   (HashSet, LinkedHashSet, TreeSet)
     Queue (LinkedList, PriorityQueue, ArrayDeque)

Map (отдельно)
 HashMap, LinkedHashMap, TreeMap
```

**Когда что использовать:**
| Структура | Когда использовать |
|---|---|
| `ArrayList` | Частый доступ по индексу, редкая вставка в середину |
| `LinkedList` | Частая вставка/удаление в начало/середину |
| `HashSet` | Уникальность, O(1) поиск, порядок не важен |
| `TreeSet` | Уникальность + сортировка |
| `HashMap` | Ключ-значение, O(1) get/put |
| `TreeMap` | Ключ-значение + сортировка по ключу |

***

### 2.2 `List`: `ArrayList` vs `LinkedList`

| | `ArrayList` | `LinkedList` |
|---|---|---|
| Внутренняя структура | Динамический массив | Двусвязный список |
| `get(i)` | O(1) | O(n) |
| `add` в конец | O(1) амортизировано | O(1) |
| `add`/`remove` в середину | O(n) | O(n) поиск + O(1) вставка |
| Память | Меньше | Больше (ссылки prev/next) |

**Рост `ArrayList`:** при переполнении создаётся новый массив размером `oldCapacity * 1.5`, данные копируются.

***

### 2.3 `Map`: `HashMap` внутри

**Устройство (Java 8+):**
- Массив бакетов (`Node[] table`), дефолтный размер = 16
- Индекс бакета: `(n-1) & hash(key)`
- Коллизии → **связный список** в бакете
- Если в бакете > 8 элементов и таблица > 64 → список превращается в **красно-чёрное дерево** (O(log n) вместо O(n))

**Load factor (0.75):** при заполнении 75% таблица **rehash** — удваивается

**`HashMap` vs `LinkedHashMap` vs `TreeMap`:**
| | Порядок | Сложность |
|---|---|---|
| `HashMap` | Не гарантирован | O(1) среднее |
| `LinkedHashMap` | Порядок вставки (или LRU) | O(1) среднее |
| `TreeMap` | Натуральная сортировка ключей | O(log n) |

**`null` ключи:**
- `HashMap` — допускает 1 `null` ключ
- `TreeMap` — НЕ допускает `null` ключ (NPE при сравнении)
- `Hashtable` — не допускает ни null-ключ, ни null-значение

### 2.4 Сравнение и сортировка

**`Comparable` vs `Comparator`:**

```java
// Comparable — "естественный" порядок, реализуется самим классом
class Person implements Comparable<Person> {
    @Override
    public int compareTo(Person o) {
        return Integer.compare(this.age, o.age);
    }
}

// Comparator — внешняя логика сортировки
Comparator<Person> byName = Comparator.comparing(Person::getName);
list.sort(byName);
// или цепочка
list.sort(Comparator.comparing(Person::getName).thenComparing(Person::getAge));
```

**`Collections.sort()` vs `Stream.sorted()`:**
- `Collections.sort()` — изменяет список на месте
- `stream().sorted()` — возвращает новый отсортированный stream, исходный список не меняет

**Алгоритм сортировки:** `Arrays.sort` для примитивов — Dual-Pivot Quicksort; для объектов — TimSort (стабильный)

##  Блок 3 — Web

### 3.1 Сервлеты

**Жизненный цикл сервлета:**
1. `init()` — вызывается один раз при загрузке контейнером
2. `service()` → диспетчеризирует в `doGet()`, `doPost()`, `doPut()`, `doDelete()`
3. `destroy()` — вызывается один раз при выгрузке

```java
@WebServlet("/hello")
public class HelloServlet extends HttpServlet {
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        resp.setContentType("text/html");
        resp.getWriter().write("<h1>Hello, World!</h1>");
    }
}
```

**`HttpServletRequest` / `HttpServletResponse`:**
- `req.getParameter("name")` — параметры запроса
- `req.getSession()` — получить/создать сессию
- `req.setAttribute()` / `req.getAttribute()` — scope запроса
- `resp.setStatus(200)`, `resp.sendRedirect("/path")`

**`RequestDispatcher` — Forward vs Redirect:**
```java
// Forward — сервер передаёт запрос, URL не меняется
req.getRequestDispatcher("/another").forward(req, resp);

// Redirect — клиент получает 302, делает новый запрос, URL меняется
resp.sendRedirect("/another");
```

**Фильтры (`Filter`):**
```java
@WebFilter("/*")
public class LoggingFilter implements Filter {
    public void doFilter(ServletRequest req, ServletResponse resp, FilterChain chain)
            throws IOException, ServletException {
        System.out.println("Before servlet");
        chain.doFilter(req, resp);
        System.out.println("After servlet");
    }
}
```

**Области видимости (Scopes):**
| Scope | Объект | Время жизни |
|---|---|---|
| Request | `HttpServletRequest` | Один запрос |
| Session | `HttpSession` | Сессия пользователя |
| Application | `ServletContext` | Жизнь приложения |

### 3.2 Spring (базовые знания)

#### IoC и DI

**IoC (Inversion of Control):** управление созданием и связыванием объектов передаётся контейнеру (Spring).

**DI (Dependency Injection):** контейнер **внедряет** зависимости в объект, а не объект создаёт их сам.

**Три способа DI:**
```java
// 1. Constructor injection (рекомендуется — явные зависимости, легко тестировать)
@Service
public class OrderService {
    private final UserRepository userRepository;
    public OrderService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }
}

// 2. Setter injection
@Autowired
public void setRepo(UserRepository repo) { this.repo = repo; }

// 3. Field injection (не рекомендуется — сложно тестировать)
@Autowired
private UserRepository userRepository;
```

#### Bean и его жизненный цикл

1. Чтение конфигурации (XML / аннотации / `@Configuration`)
2. Создание экземпляра
3. Внедрение зависимостей
4. `@PostConstruct` / `afterPropertiesSet()`
5. Bean готов к использованию
6. `@PreDestroy` / `destroy()` при завершении контекста

**Scope бинов:**
| Scope | Описание |
|---|---|
| `singleton` (default) | Один экземпляр на контекст |
| `prototype` | Новый экземпляр при каждом `getBean()` |
| `request` | Один экземпляр на HTTP-запрос |
| `session` | Один экземпляр на HTTP-сессию |

#### Ключевые аннотации

| Аннотация | Назначение |
|---|---|
| `@Component` | Объявить класс бином |
| `@Service` | Бизнес-логика (специализация `@Component`) |
| `@Repository` | Слой данных + трансляция исключений БД |
| `@Controller` | MVC-контроллер |
| `@RestController` | `@Controller` + `@ResponseBody` |
| `@Autowired` | Внедрить зависимость |
| `@Qualifier("name")` | Выбрать конкретный бин при нескольких кандидатах |
| `@Value("${prop}")` | Внедрить значение из `application.properties` |
| `@Configuration` | Класс конфигурации |
| `@Bean` | Объявить фабричный метод как бин |
| `@Transactional` | Обернуть метод в транзакцию |

#### Spring MVC — обработка запроса

```
Browser → DispatcherServlet → HandlerMapping → Controller → ViewResolver → View → Browser
```

```java
@RestController
@RequestMapping("/api/users")
public class UserController {

    @GetMapping("/{id}")
    public ResponseEntity<User> getUser(@PathVariable Long id) {
        return ResponseEntity.ok(userService.findById(id));
    }

    @PostMapping
    public ResponseEntity<User> createUser(@RequestBody @Valid UserDto dto) {
        return ResponseEntity.status(201).body(userService.create(dto));
    }
}
```

**`@RequestParam` vs `@PathVariable`:**
- `@PathVariable` — из пути: `/users/{id}`
- `@RequestParam` — из query string: `/users?page=2`

#### Spring Boot

- `@SpringBootApplication` = `@Configuration` + `@EnableAutoConfiguration` + `@ComponentScan`
- **Auto-configuration** — Spring Boot сам настраивает бины на основе classpath
- `application.properties` / `application.yml` — внешняя конфигурация
- **Embedded server** — Tomcat/Jetty/Undertow встроен, не нужен внешний контейнер
