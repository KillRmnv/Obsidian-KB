# 📐 Типы связей в JPA/Hibernate: примеры и правила

В JPA есть 4 базовых типа отношений. Каждый из них имеет **владеющую сторону** (upholding/owning side, где физически лежит `@JoinColumn` или `@JoinTable`) и **обратную сторону** (`mappedBy`). Понимание этого различия критично для корректных `INSERT`/`UPDATE`/`DELETE`.

---

## 1️⃣ `@OneToOne` (Один к одному)
**Суть:** Каждая запись таблицы A строго связана с одной записью таблицы B.  
**БД:** Внешний ключ в одной из таблиц (или общий Primary Key).

```java
@Entity
public class User {
    @Id @GeneratedValue
    private Long id;

    // Обратная сторона: mappedBy указывает на поле в UserProfile
    @OneToOne(mappedBy = "user", cascade = CascadeType.ALL, fetch = FetchType.LAZY)
    private UserProfile profile;
}

@Entity
public class UserProfile {
    @Id @GeneratedValue
    private Long id;

    // Владеющая сторона: здесь физически создаётся FK user_id
    @OneToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "user_id", unique = true)
    private User user;
}
```
⚠️ **Нюансы:**
- `@OneToOne` по умолчанию `EAGER`. Чтобы работал `LAZY`, добавьте `optional = false` или `@LazyToOne(LazyToOneOption.NO_PROXY)` (требуется байткод-инструментация в Hibernate).
- Каскадирование `ALL` безопасно, только если профиль не существует без пользователя.
- Удалять нужно **только через владеющую сторону** или через каскад.

---

## 2️⃣ `@ManyToOne` (Многие к одному)
**Суть:** Несколько записей ссылаются на одну общую.  
**БД:** Внешний ключ в таблице "многих".

```java
@Entity
public class OrderItem {
    @Id @GeneratedValue
    private Long id;

    // Владеющая сторона. Всегда LAZY!
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "order_id")
    private Order order;
}
```
⚠️ **Нюансы:**
- **Никогда не делайте `EAGER`** → при загрузке 1000 товаров сделает 1000 `JOIN` или отдельных запросов.
- Каскадирование `PERSIST`/`REMOVE` обычно **не нужно**: удаление `OrderItem` не должно удалять `Order`.
- Это самая частая связь в реляционных моделях.

---

## 3️⃣ `@OneToMany` (Один ко многим)
**Суть:** Одна сущность владеет коллекцией дочерних.  
**БД:** Либо FK в таблице "многих" (рекомендуется), либо join-таблица (редко).

```java
@Entity
public class Order {
    @Id @GeneratedValue
    private Long id;

    // Обратная сторона: mappedBy = "order" (имя поля в OrderItem)
    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<OrderItem> items = new ArrayList<>();

    // Утилитарный метод для синхронизации двусторонней связи
    public void addItem(OrderItem item) {
        items.add(item);
        item.setOrder(this);
    }
}
```
⚠️ **Нюансы:**
- По умолчанию `LAZY` ✅
- `orphanRemoval = true` удаляет `OrderItem` из БД, если он исчез из коллекции `items`. Работает **только** с `@OneToMany`/`@OneToOne`.
- Всегда используйте утилитарные методы (`addItem`/`removeItem`), иначе граф объектов рассинхронизируется.
- Не используйте `Set` если важен порядок вставки; `List` + `@OrderColumn` или индексы в БД.

---

## 4️⃣ `@ManyToMany` (Многие ко многим)
**Суть:** Связь через промежуточную таблицу.  
**БД:** Таблица-мост с двумя внешними ключами.

```java
@Entity
public class Student {
    @Id @GeneratedValue
    private Long id;

    // Владеющая сторона: определяет структуру join-таблицы
    @ManyToMany
    @JoinTable(
        name = "student_course",
        joinColumns = @JoinColumn(name = "student_id"),
        inverseJoinColumns = @JoinColumn(name = "course_id")
    )
    private Set<Course> courses = new HashSet<>();
}

@Entity
public class Course {
    @Id @GeneratedValue
    private Long id;

    // Обратная сторона
    @ManyToMany(mappedBy = "courses")
    private Set<Student> students = new HashSet<>();
}
```

⚠️ **Нюансы:**
- По умолчанию `LAZY` ✅
- **Никогда не используйте `CascadeType.REMOVE`** → удаление `Course` удалит его у **всех** студентов, а не только разорвёт связь.
- Если нужны доп. атрибуты в связи (дата зачисления, оценка, статус) → `@ManyToMany` не подходит. Делайте явную сущность `Enrollment` с двумя `@ManyToOne`.
- Для модификации связи используйте `student.getCourses().add(course)` **на владеющей стороне**.

## 📊 Сводная таблица

| Аннотация | Default Fetch | Где лежит FK / JoinTable | Каскад `REMOVE` | `orphanRemoval` | Когда использовать |
|-----------|---------------|--------------------------|-----------------|-----------------|---------------------|
| `@OneToOne` | `EAGER` ⚠️ | На обратной стороне (`@JoinColumn`) | Опасно, но допустимо | ✅ Да | Профиль, настройки, адрес |
| `@ManyToOne` | `EAGER` ⚠️ | На этой стороне | ❌ Не нужно | ❌ Нет | Товар → Категория, Строка заказа → Заказ |
| `@OneToMany` | `LAZY` ✅ | На стороне `@ManyToOne` | ✅ Да (часто) | ✅ Да | Заказ → Строки заказа, Пост → Комментарии |
| `@ManyToMany` | `LAZY` ✅ | На этой стороне (`@JoinTable`) | ❌ Категорически нет | ❌ Нет | Студент ↔ Курс, Тег ↔ Статья |

---

## 🛠 Практические правила

1. **Всегда делайте связи `LAZY` явно**, кроме `@OneToMany`/`@ManyToMany` (там это default).
2. **Владеющая сторона = та, где `@JoinColumn` или `@JoinTable`**. Только она пишет FK в БД.
3. **Двусторонние связи синхронизируйте вручную** через helper-методы, иначе Hibernate не увидит изменений в коллекции.
4. **Для `equals/hashCode` никогда не включайте связи** → рекурсия, `LazyInitializationException`, потеря элементов в `Set`.
5. **Если связь требует доп. полей** → замените `@ManyToMany` на сущность-связку с двумя `@ManyToOne`.
