Опишу именно смысл и поведение аннотаций, без привязки к конкретному коду.

---

## @EnableCaching

Включает механизм кэширования в приложении.

- Вешаешь на конфигурационный класс (`@Configuration`).
    
- После этого Spring оборачивает бины прокси, которые перехватывают вызовы методов с `@Cacheable/@CachePut/@CacheEvict`.
    
- Без этой аннотации остальные кэш-аннотации просто игнорируются.
    

---

## @Cacheable

Кэширует результат метода и при следующих вызовах может **вообще не выполнять метод**, а вернуть значение из кэша.

Поведение:

1. При первом вызове:
    
    - строится ключ (по умолчанию из аргументов метода или по `key` в аннотации);
        
    - Spring смотрит в кэш по этому ключу;
        
    - если там ничего нет — метод реально выполняется, результат кладётся в кэш.
        
2. При следующих вызовах с тем же ключом:
    
    - Spring опять смотрит в кэш;
        
    - если запись есть — метод **не вызывается**, сразу возвращается объект из кэша.
        

Фишки:

- `cacheNames` / `value` — имя(а) кэша.
    
- `key` — как считать ключ (SpEL: `#id`, `#filter.title`, и т.д.).
    
- `condition` — кэшировать только если условие true (например, `condition = "#id > 0"`).
    
- `unless` — уже после выполнения (видит `#result`), можно не класть результат в кэш, если условие true.
    

---

## @CachePut

Тоже кладёт данные в кэш, но **метод всегда выполняется**.

Поведение:

- Сначала всегда вызывается метод.
    
- Потом его результат кладётся/обновляется в кэше по вычисленному ключу.
    
- Нигде не происходит “прочитать из кэша вместо вызова”.
    

Обычно используют:

- на методах обновления (`updateXxx`), чтобы после изменения сразу обновить запись в кэше;
    
- в паре с `@Cacheable`: `getXxx()` — `@Cacheable`, `updateXxx()` — `@CachePut`.
    

---

## @CacheEvict

Удаляет данные из кэша.

Поведение:

- По умолчанию вызывается **после** успешного выполнения метода (можно поменять через `beforeInvocation = true`).
    
- Если указать `key`, удалится конкретная запись.
    
- Если указать `allEntries = true`, очистится весь кэш с таким именем.
    

Применение:

- на методах удаления (`deleteXxx`) — удалять объект из кэша по ключу;
    
- на методах массовых изменений — очищать весь кэш (`allEntries = true`), чтобы не держать старые данные.

## @Caching

Группирует несколько кэш-операций на одном методе.

Примерно такой смысл:

- можно одновременно:
    
    - `put` в один кэш,
        
    - `evict` из другого,
        
    - и т.д.
        

Структура:

- `cacheable` — массив `@Cacheable`;
    
- `put` — массив `@CachePut`;
    
- `evict` — массив `@CacheEvict`.
    

Нужно, когда:

- метод меняет состояние так, что надо:
    
    - и обновить кэш по id,
        
    - и сбросить кэш поиска,
        
    - и, возможно, очистить ещё что-то.
        

---

## @CacheConfig

Задаёт общие настройки кэширования на уровне класса.

Типичные поля:

- `cacheNames` — дефолтные имена кэшей для всех методов;
    
- `keyGenerator`, `cacheManager` — общий генератор ключей и менеджер кэша для всех методов.
    

Полезна, чтобы не дублировать `cacheNames = "xxx"` в каждой аннотации.

---

## Как это всё работает вместе (логика)

Можно запомнить так:

- `@Cacheable` — “если в кэше есть, метод не трогаем, просто верни; если нет — вызови и положи”.
    
- `@CachePut` — “всегда вызови метод и обнови кэш этим результатом”.
    
- `@CacheEvict` — “после (или до) выполнения метода выкинь что-то из кэша”.
    
- `@Caching` — “сделай несколько таких операций сразу на одном методе”.
    
- `@CacheConfig` — “общие настройки кэша для всех методов этого сервиса”.
    
- `@EnableCaching` — “вообще включи всё это поведение в приложении”.
    

Дальше ты уже сам можешь решить, что именно кэшировать (по id, по фильтрам, по email и т.д.) и как инвалидировать.
