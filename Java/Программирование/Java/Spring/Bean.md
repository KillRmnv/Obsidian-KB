# Spring Bean — что это такое

## Простое определение

**Bean** — это объект, жизненным циклом которого управляет **Spring Container** (контейнер Спринга). Вместо того чтобы создавать объекты через `new`, вы делегируете это Spring, и он сам создаёт, настраивает и управляет этими объектами.

---

## Аналогия из жизни

Представьте ресторан:

| Без Spring (ручное управление) | С Spring (Bean'ы) |
|-------------------------------|-------------------|
| Вы сами идёте на рынок, покупаете продукты, готовите | Есть шеф-повар (Spring), который сам заказывает продукты, готовит и подаёт |
| Вы управляете всем вручную | Контейнер управляет всем за вас |

## Как создаются Bean'ы (3 способа)

### Способ 1: @Component (автоматическое обнаружение)

```java
import org.springframework.stereotype.Component;

// Spring автоматически найдёт и создаст этот Bean
@Component
public class СервисОплаты {
    
    public void обработатьПлатеж(double сумма) {
        System.out.println("Обработан платёж: " + сумма + " ₽");
    }
}
```

**Другие стереотипные аннотации:**
```java
@Component        // Универсальная
@Service          // Бизнес-логика (семантически = @Component)
@Repository       // Доступ к данным (семантически = @Component)
@Controller       // Web-контроллер (семантически = @Component)
@RestController   // REST API контроллер (@Controller + @ResponseBody)
```

---

### Способ 2: @Bean (ручное создание в конфигурации)

```java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration  // Класс конфигурации — тоже Bean!
public class КонфигурацияБанка {
    
    // Spring создаст Bean вручную через этот метод
    @Bean
    public БанковскийСчёт банковскийСчёт() {
        БанковскийСчёт счёт = new БанковскийСчёт();
        счёт.setВалюта("RUB");
        счёт.setБаланс(0.0);
        return счёт;
    }
    
    // Bean с именем (по умолчанию имя = название метода)
    @Bean(name = "основнойКлиент")
    public Клиент клиент() {
        return new Клиент("Иван Иванов", "ivan@mail.ru");
    }
}
```

---

### Способ 3: XML (устаревший способ, но иногда встречается)

```xml
<!-- application-context.xml -->
<bean id="сервис" class="com.example.СервисОплаты"/>
```

## Жизненный цикл Bean

```
1. Создание (Instantiate)     → вызов конструктора
2. Настройка свойств           → @Value, @Autowired
3. Инициализация               → @PostConstruct
4. Работа                      → использование в приложении
5. Уничтожение                 → @PreDestroy
```

```java
import jakarta.annotation.PostConstruct;
import jakarta.annotation.PreDestroy;
import org.springframework.stereotype.Service;

@Service
public class СервисОтчётов {
    
    // Вызывается ПОСЛЕ создания и внедрения зависимостей
    @PostConstruct
    public void инициализация() {
        System.out.println("Сервис отчётов готов к работе!");
        // Например: загрузка кеша, подключение к БД
    }
    
    // Вызывается ПЕРЕД уничтожением Bean
    @PreDestroy
    public void очистка() {
        System.out.println("Сервис отчётов завершает работу...");
        // Например: закрытие соединений, сохранение данных
    }
}
```

## Внедрение зависимостей (Dependency Injection)

Bean'ы могут использовать другие Bean'ы — Spring сам их "подставляет":

```java
import org.springframework.stereotype.Service;

@Service
public class СервисЗаказов {
    
    // Вариант 1: Через поле (просто, но не рекомендуется)
    @Autowired
    private СервисОплаты сервисОплаты;
    
    // Вариант 2: Через сеттер (редко используется)
    private СервисДоставки сервисДоставки;
    
    @Autowired
    public void setСервисДоставки(СервисДоставки сервис) {
        this.сервисДоставки = сервис;
    }
}
```

### ✅ Рекомендуемый способ — через конструктор:

```java
import org.springframework.stereotype.Service;

@Service
public class СервисЗаказов {
    
    private final СервисОплаты сервисОплаты;
    private final СервисДоставки сервисДоставки;
    private final РепозиторийЗаказов репозиторий;
    
    // Spring автоматически подставит все нужные Bean'ы
    public СервисЗаказов(
            СервисОплаты сервисОплаты,
            СервисДоставки сервисДоставки,
            РепозиторийЗаказов репозиторий) {
        this.сервисОплаты = сервисОплаты;
        this.сервисДоставки = сервисДоставки;
        this.репозиторий = репозиторий;
    }
    
    public void создатьЗаказ(Заказ заказ) {
        // Используем внедрённые сервисы
        репозиторий.сохранить(заказ);
        сервисОплаты.обработатьПлатеж(заказ.getСумма());
        сервисДоставки.оформитьДоставку(заказ);
    }
}
```

**Преимущества конструкторного внедрения:**
- Невозможно создать объект без нужных зависимостей
- `final` поля — иммутабельность
- Легко тестировать (можно передать mock'и)
- Не нужен `@Autowired` (начиная с Spring 4.3)

## Область видимости (Scope) Bean

```java
import org.springframework.context.annotation.Scope;
import org.springframework.stereotype.Component;

@Component
@Scope("singleton")      // ОДИН экземпляр на всё приложение (по умолчанию)
public class КешНастроек {
    // Создаётся 1 раз при старте
}

@Component
@Scope("prototype")      // НОВЫЙ экземпляр при каждом запросе
public class ГенераторОтчётов {
    // Создаётся каждый раз, когда нужен
}

@Component
@Scope("request")        // ОДИН на HTTP-запрос (только для web)
public class ДанныеСессии {
    // Живёт в течение одного HTTP-запроса
}
```

| Scope | Когда создаётся | Когда уничтожается |
|-------|----------------|-------------------|
| `singleton` | При старте приложения | При остановке приложения |
| `prototype` | При каждом запросе | Сборщиком мусора |
| `request` | При HTTP-запросе | После обработки запроса |
| `session` | При создании сессии | При истечении сессии |

## Полный пример: как это работает вместе

```java
// === МОДЕЛЬ ===
public record Книга(String название, String автор, double цена) {}

// === РЕПОЗИТОРИЙ (Bean) ===
@Repository
public class Библиотека {
    private final List<Книга> книги = new ArrayList<>();
    
    public void добавить(Книга книга) {
        книги.add(книга);
    }
    
    public List<Книга> найтиВсе() {
        return Collections.unmodifiableList(книги);
    }
}

// === СЕРВИС (Bean, использует репозиторий) ===
@Service
public class СервисКниг {
    
    private final Библиотека библиотека;
    private final СервисСкидок сервисСкидок;  // ещё один Bean
    
    public СервисКниг(Библиотека библиотека, СервисСкидок сервисСкидок) {
        this.библиотека = библиотека;
        this.сервисСкидок = сервисСкидок;
    }
    
    public void добавитьКнигу(Книга книга) {
        Книга книгаСоСкидкой = сервисСкидок.применитьСкидку(книга);
        библиотека.добавить(книгаСоСкидкой);
    }
}

// === КОНТРОЛЛЕР (Bean, использует сервис) ===
@RestController
@RequestMapping("/книги")
public class КонтроллерКниг {
    
    private final СервисКниг сервисКниг;
    
    public КонтроллерКниг(СервисКниг сервисКниг) {
        this.сервисКниг = сервисКниг;
    }
    
    @PostMapping
    public void добавить(@RequestBody Книга книга) {
        сервисКниг.добавитьКнигу(книга);
    }
}
```

**Что делает Spring:**
1. Сканирует пакеты, находит `@Component`, `@Service`, `@Repository`, `@Controller`
2. Создаёт Bean'ы в правильном порядке (сначала `Библиотека`, потом `СервисКниг`, потом `КонтроллерКниг`)
3. Внедряет зависимости через конструкторы
4. Вызывает `@PostConstruct`
5. При остановке — `@PreDestroy`

## Итог: зачем нужны Bean'ы

| Без Spring | С Spring Bean'ами |
|-----------|-------------------|
| `new Сервис()` везде | Один централизованный объект |
| Ручное управление зависимостями | Автоматическое внедрение |
| Сложно тестировать | Легко мокировать |
| Жёсткая связанность | Слабая связанность (IoC) |
| Сам управляешь жизненным циклом | Spring управляет за тебя |

**Bean = объект, которым управляет Spring Container**
