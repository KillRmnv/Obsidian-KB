Расширенные примеры демонстрируют **разные области видимости (scope)**, а также использование непустого класса конфигурации с явными `@Bean`-методами и внедрением зависимостей.

---

## Пример 1. Контекст через аннотации: `@Configuration`, `@Bean`, различные `@Scope`

### 1.1. Сервисы

```java
package com.example;

import org.springframework.stereotype.Component;

// Бин с областью по умолчанию — singleton
@Component
public class GreetingService {
    public String greet(String name) {
        return "Hello, " + name + "!";
    }
}
```

```java
package com.example;

// Простой класс-счётчик, не является Spring-бином сам по себе
public class Counter {
    private int count = 0;

    public int increment() {
        return ++count;
    }
}
```

### 1.2. Класс конфигурации (непустой, содержит `@Bean`-методы)

```java
package com.example;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.ComponentScan;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.Scope;

@Configuration
@ComponentScan(basePackages = "com.example")  // подхватывает @Component-бины
public class AppConfig {

    // Явное создание бина типа Counter, scope = singleton (по умолчанию)
    @Bean
    public Counter singletonCounter() {
        return new Counter();
    }

    // Явное создание бина, scope = prototype — новый экземпляр при каждом запросе
    @Bean
    @Scope("prototype")
    public Counter prototypeCounter() {
        return new Counter();
    }
}
```

### 1.3. Главный класс

```java
package com.example;

import org.springframework.context.annotation.AnnotationConfigApplicationContext;

public class AnnotationApp {
    public static void main(String[] args) {
        var context = new AnnotationConfigApplicationContext(AppConfig.class);

        // 1. Singleton-бин GreetingService (аннотация @Component)
        GreetingService service1 = context.getBean(GreetingService.class);
        GreetingService service2 = context.getBean(GreetingService.class);
        System.out.println("GreetingService singleton? " + (service1 == service2)); // true

        // 2. Singleton-бин Counter, определённый через @Bean
        Counter singCounter1 = context.getBean("singletonCounter", Counter.class);
        Counter singCounter2 = context.getBean("singletonCounter", Counter.class);
        System.out.println("singletonCounter: " + singCounter1.increment()); // 1
        System.out.println("singletonCounter: " + singCounter2.increment()); // 2
        System.out.println("same instance? " + (singCounter1 == singCounter2)); // true

        // 3. Prototype-бин Counter, определённый через @Bean и @Scope("prototype")
        Counter protoCounter1 = context.getBean("prototypeCounter", Counter.class);
        Counter protoCounter2 = context.getBean("prototypeCounter", Counter.class);
        System.out.println("prototypeCounter 1: " + protoCounter1.increment()); // 1
        System.out.println("prototypeCounter 2: " + protoCounter2.increment()); // 1 (новый экземпляр)
        System.out.println("same instance? " + (protoCounter1 == protoCounter2)); // false

        context.close();
    }
}
```

**Вывод (хэш-коды и значения):**
```
GreetingService singleton? true
singletonCounter: 1
singletonCounter: 2
same instance? true
prototypeCounter 1: 1
prototypeCounter 2: 1
same instance? false
```

**Пояснения:**
- `GreetingService` подхвачен благодаря `@ComponentScan`.
- `singletonCounter` – один объект на весь контейнер, счётчик увеличивается при каждом вызове.
- `prototypeCounter` – каждый `getBean()` создаёт новый объект, счётчик начинается с 1.

## Пример 2. Контекст через XML: различные `scope`, внедрение зависимостей

### 2.1. Классы (обычные POJO)

```java
package com.example;

public class GreetingService {
    public String greet(String name) {
        return "Hello, " + name + "!";
    }
}
```

```java
package com.example;

public class Counter {
    private int count = 0;

    public int increment() {
        return ++count;
    }
}
```

```java
package com.example;

public class ReportGenerator {
    private GreetingService greetingService;

    // Внедрение через конструктор
    public ReportGenerator(GreetingService greetingService) {
        this.greetingService = greetingService;
    }

    public String generateReport(String user) {
        String greeting = greetingService.greet(user);
        return "Report: " + greeting + " Your stats are ready.";
    }
}
```

### 2.2. Конфигурация `applicationContext.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="http://www.springframework.org/schema/beans
           http://www.springframework.org/schema/beans/spring-beans.xsd">

    <!-- Singleton по умолчанию -->
    <bean id="greetingService" class="com.example.GreetingService" />

    <!-- Singleton Counter (scope="singleton" можно не указывать, это по умолчанию) -->
    <bean id="singletonCounter" class="com.example.Counter" scope="singleton" />

    <!-- Prototype Counter -->
    <bean id="prototypeCounter" class="com.example.Counter" scope="prototype" />

    <!-- Бин с внедрением через конструктор (constructor-arg) -->
    <bean id="reportGenerator" class="com.example.ReportGenerator">
        <constructor-arg ref="greetingService" />
    </bean>
</beans>
```

### 2.3. Главный класс

```java
package com.example;

import org.springframework.context.support.ClassPathXmlApplicationContext;

public class XmlApp {
    public static void main(String[] args) {
        var context = new ClassPathXmlApplicationContext("applicationContext.xml");

        // Singleton-бины
        GreetingService greet1 = context.getBean(GreetingService.class);
        GreetingService greet2 = context.getBean(GreetingService.class);
        System.out.println("GreetingService singleton? " + (greet1 == greet2)); // true

        Counter sing1 = context.getBean("singletonCounter", Counter.class);
        Counter sing2 = context.getBean("singletonCounter", Counter.class);
        System.out.println("singletonCounter: " + sing1.increment()); // 1
        System.out.println("singletonCounter: " + sing2.increment()); // 2
        System.out.println("same instance? " + (sing1 == sing2)); // true

        // Prototype-бин
        Counter proto1 = context.getBean("prototypeCounter", Counter.class);
        Counter proto2 = context.getBean("prototypeCounter", Counter.class);
        System.out.println("prototypeCounter 1: " + proto1.increment()); // 1
        System.out.println("prototypeCounter 2: " + proto2.increment()); // 1 (новый объект)
        System.out.println("same instance? " + (proto1 == proto2)); // false

        // Бин с внедрённой зависимостью
        ReportGenerator generator = context.getBean(ReportGenerator.class);
        System.out.println(generator.generateReport("Мария"));

        context.close();
    }
}
```

**Вывод:**
```
GreetingService singleton? true
singletonCounter: 1
singletonCounter: 2
same instance? true
prototypeCounter 1: 1
prototypeCounter 2: 1
same instance? false
Report: Hello, Мария! Your stats are ready.
```

## Краткий итог дополнительных возможностей

| Возможность | Аннотации (Java Config) | XML |
|-------------|--------------------------|-----|
| Явное создание бина | `@Bean` в классе с `@Configuration` | `<bean>` |
| Область видимости | `@Scope("prototype")` на методе | `scope="prototype"` в `<bean>` |
| Внедрение зависимости | Через аргументы метода `@Bean` или `@Autowired` | `<constructor-arg ref="..."/>` |
| Сканирование компонентов | `@ComponentScan` | `<context:component-scan>` (не использовалось) |

Оба подхода позволяют гибко управлять временем жизни бинов и их зависимостями, и их можно комбинировать в одном проекте.
