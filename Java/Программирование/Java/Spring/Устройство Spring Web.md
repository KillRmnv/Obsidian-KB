## Устройство Spring Web (Spring MVC)

Spring Web MVC — это оригинальный веб-фреймворк, построенный на Servlet API и включенный в Spring Framework с самого начала [[9]]. Архитектура следует паттерну Model-View-Controller (MVC), который разделяет приложение на три основных компонента: Model, View и Controller [[14]].

### Основные компоненты архитектуры

#### 1. **DispatcherServlet**
Центральный компонент Spring MVC, выполняющий роль Front Controller [[8]]. Он является первой точкой контакта для всех входящих HTTP-запросов и координирует работу всех остальных компонентов [[2]].

#### 2. **HandlerMapping**
Отвечает за выбор подходящего контроллера на основе URL запроса [[7]]. Обычно используется `RequestMappingHandlerMapping`, который считывает аннотацию `@RequestMapping` из контроллеров и сопоставляет методы контроллера с URL [[7]].

#### 3. **HandlerAdapter**
Выполняет бизнес-логику выбранного контроллера [[7]]. Класс `RequestMappingHandlerAdapter` вызывает метод обработчика (контроллера), выбранного HandlerMapping [[7]].

#### 4. **Controller**
Обрабатывает пользовательский ввод, взаимодействует с моделью и подготавливает данные для представления [[5]]. Контроллер выполняет бизнес-логику, устанавливает результат обработки в Model и возвращает логическое имя view [[7]].

#### 5. **Model**
Содержит бизнес-логику и данные приложения, взаимодействует с базой данных и подготавливает информацию для отображения [[5]].

#### 6. **ViewResolver**
Преобразует логическое имя view, возвращаемое контроллером, в конкретное представление (например, JSP страницу или HTML файл) [[5]]. Для JSP обычно используется `InternalResourceViewResolver`, а для других шаблонизаторов могут применяться специализированные resolver'ы [[7]].

#### 7. **View**
Финальный компонент, который рендерит данные модели и возвращает ответ пользователю в формате HTML, JSON или другом [[5]].

### Поток обработки запроса

Процесс обработки запроса в Spring MVC происходит следующим образом [[7]]:

1. **DispatcherServlet** получает HTTP-запрос
2. **DispatcherServlet** делегирует задачу выбора контроллера компоненту **HandlerMapping**, который возвращает соответствующий handler
3. **DispatcherServlet** передает выполнение бизнес-логики **HandlerAdapter**
4. **HandlerAdapter** вызывает метод контроллера
5. **Controller** выполняет бизнес-логику, сохраняет результат в **Model** и возвращает логическое имя view
6. **DispatcherServlet** использует **ViewResolver** для преобразования логического имени в конкретное представление
7. **DispatcherServlet** передает управление найденному **View**
8. **View** рендерит данные модели и формирует финальный ответ

### Дополнительные возможности

Spring Web MVC также поддерживает:
- Фильтры (Filters)
- Конвертацию HTTP сообщений (HTTP Message Conversion)
- Аннотированные контроллеры (Annotated Controllers)
- Функциональные эндпоинты (Functional Endpoints)
- Асинхронные запросы (Asynchronous Requests)
- CORS
- Версионирование API
- Обработку ошибок
- Веб-безопасность
- Кэширование HTTP
- Различные технологии представлений (View Technologies) [[9]]

Архитектура Spring MVC обеспечивает гибкость и слабую связанность компонентов, что делает фреймворк мощным инструментом для создания масштабируемых веб-приложений на Java [[10]].
