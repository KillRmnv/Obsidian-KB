# 48. Иерархические агломеративные методы кластерного анализа

Иерархические агломеративные методы (Hierarchical Agglomerative Clustering, HAC) — класс алгоритмов кластеризации, последовательно объединяющих объекты и группы объектов в более крупные кластеры по принципу «снизу вверх» (bottom-up). Альтернативный подход — дивизивные методы, работающие «сверху вниз» (от одного большого кластера к мелким), на практике используются реже из-за высокой вычислительной сложности. Общий алгоритм агломеративной кластеризации. 1) Инициализация: каждый из n объектов считается отдельным кластером, имеется n кластеров. 2) Расчёт матрицы попарных расстояний между всеми кластерами (n×n). 3) Поиск пары кластеров с минимальным расстоянием между ними. 4) Объединение этой пары в новый кластер; общее число кластеров уменьшается на 1. 5) Пересчёт матрицы расстояний: обновление расстояний от нового кластера до всех остальных в соответствии с выбранным методом межкластерного расстояния. 6) Повторение шагов 3–5 до тех пор, пока не останется один кластер, содержащий все объекты, или не будет достигнут заданный порог. Конкретный алгоритм определяется выбором метода расстояния между кластерами: single linkage (ближайший сосед), complete linkage (дальний сосед), average linkage (среднее), centroid linkage (центроидный), Ward (минимум прироста дисперсии), median linkage. Универсальная формула Ланса-Уильямса позволяет единообразно вычислять расстояния при объединении кластеров для всех этих методов. Результат алгоритма — иерархия вложенных разбиений, наглядно представляемая в виде дендрограммы. Для получения конкретного плоского разбиения дендрограмма «обрезается» на выбранном уровне, число кластеров определяется визуально или по эвристикам (наибольший «прыжок» в расстояниях, индекс силуэта). Достоинства: не требует заранее задавать число кластеров, выдаёт полную иерархию (можно рассмотреть разные уровни детализации), интерпретируемость через дендрограмму, работает с разными метриками расстояния. Недостатки: высокая вычислительная сложность O(n²log n) или O(n³) — плохо масштабируется на большие выборки (тысячи и более объектов), решения «жадные» — невозможно исправить раннее ошибочное объединение, чувствительность к шуму и выбросам. Применяется в биоинформатике (филогенетические деревья), таксономии, анализе экспрессии генов, сегментации потребителей, организации документов.
