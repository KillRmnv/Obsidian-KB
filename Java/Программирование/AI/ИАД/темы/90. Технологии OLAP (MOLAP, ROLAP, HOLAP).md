# 90. Технологии OLAP (MOLAP, ROLAP, HOLAP)

Существуют три основные архитектурные технологии реализации OLAP, различающиеся способом физического хранения и обработки многомерных данных; выбор определяет производительность, объём данных и гибкость системы. 1) MOLAP (Multidimensional OLAP) — данные хранятся в специализированных многомерных структурах (массивах, multidimensional arrays), оптимизированных для аналитических запросов; куб полностью или частично предвычисляется и материализуется на этапе загрузки. Преимущества: максимальная скорость аналитических запросов (доступ к ячейке куба — прямая индексация), эффективное хранение разреженных данных (с компрессией), мощная поддержка сложных вычислений и иерархий, оптимизированные алгоритмы агрегации. Недостатки: ограниченный объём данных (обычно гигабайты, не петабайты), длительное время загрузки и обновления (требуется пересчёт кубов), избыточность хранения при многих агрегатах (data explosion), необходимость специализированной системы. Примеры: Microsoft Analysis Services (MOLAP-режим), Oracle Essbase, Cognos PowerCubes, Apache Kylin. Подходит для среднеразмерных задач с интенсивной аналитикой. 2) ROLAP (Relational OLAP) — данные хранятся в обычных реляционных базах данных (схема «звезда» или «снежинка» с таблицами фактов и измерений), OLAP-запросы транслируются в SQL, агрегаты вычисляются «на лету» или предвычисляются как материализованные представления. Преимущества: способность работать с очень большими объёмами данных (до петабайт), легче масштабируется, использует существующую инфраструктуру реляционных СУБД, гибкость структуры данных, поддержка обновлений в реальном времени, не требует отдельной системы. Недостатки: более медленные запросы по сравнению с MOLAP (особенно сложные многомерные вычисления), производительность сильно зависит от качества SQL-оптимизатора и индексов, ограниченные возможности для сложных аналитических функций. Примеры: Microsoft Analysis Services (ROLAP-режим), Oracle OLAP, Pentaho Mondrian, MicroStrategy, современные облачные хранилища Snowflake, BigQuery, Redshift с BI-инструментами. Стандарт для больших данных. 3) HOLAP (Hybrid OLAP) — гибридный подход, объединяющий MOLAP и ROLAP: агрегированные данные и часто используемые предвычисления хранятся в многомерных структурах для быстрых запросов, а детальные данные — в реляционной базе для эффективного использования места и доступа к деталям. Преимущества: компромисс между скоростью MOLAP и масштабируемостью ROLAP, гибкость в зависимости от типа запроса, drill-through к первичным данным. Недостатки: сложность реализации и администрирования, необходимость управления двумя хранилищами, потенциальная несогласованность. Примеры: SAP BW, Microsoft Analysis Services с гибридным режимом. Сравнение и выбор. Объём данных: MOLAP — до гигабайт, HOLAP — до сотен гигабайт, ROLAP — петабайты. Скорость запросов: MOLAP > HOLAP > ROLAP. Гибкость и обновления: ROLAP > HOLAP > MOLAP. Современные тенденции: с развитием колоночных СУБД (ClickHouse, Vertica, Snowflake), in-memory вычислений и MPP-архитектур граница между технологиями размывается; многие современные системы (Apache Druid, ClickHouse, Apache Pinot) сочетают принципы всех трёх подходов, обеспечивая суб-секундные аналитические запросы на огромных объёмах данных в реальном времени.
