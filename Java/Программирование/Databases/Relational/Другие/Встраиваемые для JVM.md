# Встраиваемые для JVM

## Если знаешь PostgreSQL (TL;DR)

1. **База живёт в JVM-процессе**, а не в отдельном сервере. Нет `pg_hba.conf`, сокетов и `pg_stat_activity` — только API.
2. **Режимы совместимости** (`MODE=PostgreSQL`, `MODE=MySQL`, `MODE=Oracle`) — синтаксис подделывается, но семантика и планировщик свои.
3. **Данные — файл или память**, MVCC упрощённый, блокировки грубее (часто одна БД = одна транзакция за раз).
4. **Нет `VACUUM`**: MVStore/H2 сам компактит; долгие транзакции могут блокировать очистку.
5. **Ниша — тесты и демо**, а не прод: H2 в проде бывает, но это осознанный компромисс.

## Ниша

Юнит- и интеграционные тесты (быстрый старт, in-memory), демо-стенды, desktop/embedded в Java-приложениях, иногда — небольшие внутренние сервисы. В проде чаще встречается H2 (простота) и SQLite через JDBC (надёжность).

## H2

| | PostgreSQL | H2 |
|---|---|---|
| Режим работы | сервер + клиенты | embedded / server / mixed |
| Хранение | heap + WAL | MVStore (B-tree + log-structured) |
| Режимы | — | `MODE=PostgreSQL`, `MODE=MySQL`, `MODE=Oracle`, `MODE=MSSQLServer`, `MODE=DB2`, `MODE=Derby`, `MODE=HSQLDB` |
| Кэш | `shared_buffers` | `CACHE_SIZE` (КБ) |
| Транзакции | MVCC | MVCC (MVStore) |
| Изоляция | RC/RR/Serializable | `READ COMMITTED`, `REPEATABLE READ`, `SERIALIZABLE` (упрощённо) |
| Очистка | `VACUUM` | автоматическая компакция MVStore |

Ключевое:

- **`MODE=PostgreSQL`** — не эмулятор PG! Он включает часть синтаксиса (`::`, `SERIAL`, `ON CONFLICT` в новых версиях), но не поведение (типы, функции, ошибки, планировщик).
- **`jdbc:h2:mem:test;DB_CLOSE_DELAY=-1`** — держать БД в памяти между соединениями.
- **`jdbc:h2:file:./data/test`** — файловая БД.
- **`RUNSCRIPT FROM 'schema.sql'`** — накатить схему.
- `INFORMATION_SCHEMA` — неполный, многих `pg_catalog`-запросов нет.

```sql
-- H2
CREATE TABLE orders (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id BIGINT NOT NULL,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT now()
);

EXPLAIN SELECT * FROM orders WHERE user_id = 42;
-- Простой текстовый план, без cost/actual rows
```

## HSQLDB

- Старейшая Java-embedded СУБД (Hypersonic).
- Режимы: `mem:`, `file:`, `res:`, `hsql:` (server).
- `SET DATABASE SQL SYNTAX PGS TRUE;` — совместимость с PostgreSQL (частичная).
- MVCC опционален (`SET DATABASE TRANSACTION CONTROL MVCC`); по умолчанию — locks.
- Слабее H2 по экосистеме, но стабильнее в некоторых legacy.

## Apache Derby

- Бывший Cloudscape/IBM Derby; встроен в Java DB (удалён из JDK 11+).
- Строгая схема, `SYSCS_UTIL` для обслуживания, `SYSCS_DIAG` для диагностики.
- **Нет MVCC**: блокировки строк/таблиц; изоляция `READ COMMITTED` по умолчанию.
- Компакция: `CALL SYSCS_UTIL.SYSCS_COMPRESS_TABLE('APP', 'ORDERS', 1);` — аналог `VACUUM FULL`.

## SQLite через JDBC

- `org.xerial:sqlite-jdbc` — самый предсказуемый вариант для тестов, если не нужен именно SQL-диалект PG.
- Один файл, WAL, `PRAGMA`-настройки — см. [[Другие/SQLite]].
- В тестах: `jdbc:sqlite::memory:` (у каждого соединения своя БД!) или временный файл.

## Тесты: чем подменять PostgreSQL

| Подход | Плюсы | Минусы |
|---|---|---|
| **H2 `MODE=PostgreSQL`** | быстро, in-memory, знакомо | не та семантика; тесты «зелёные», прод «красный» |
| **Testcontainers (PostgreSQL)** | настоящий PG, точная семантика | Docker, медленнее старт |
| **Embedded PostgreSQL** (zonky, opentable) | без Docker, реальный PG | платформенно-зависимо, версии |
| **SQLite** | один файл, быстро | другой диалект |

Правило: **если в коде есть PG-специфика (jsonb, arrays, `ON CONFLICT`, оконные, `RETURNING`, триггеры) — H2 не подходит**, нужен Testcontainers.

```java
// Testcontainers
@Container
static PostgreSQLContainer<?> pg = new PostgreSQLContainer<>("postgres:18");

// H2 в режиме PG (только для простых запросов)
String url = "jdbc:h2:mem:test;MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE;DEFAULT_NULL_ORDERING=HIGH";
```

## Грабли для приходящего с PG

1. **`MODE=PostgreSQL` — это не PG.** Различия в типах (`jsonb` → `JSON`/`CLOB`), функциях, ошибках, `NULLS FIRST/LAST`, collation.
2. **H2-`EXPLAIN` не показывает cost/actual rows** — оптимизировать по нему нельзя.
3. **`jdbc:h2:mem:` без `DB_CLOSE_DELAY=-1`** — БД исчезает после закрытия последнего соединения.
4. **`jdbc:sqlite::memory:`** — у каждого соединения **своя** in-memory БД; пул соединений ломает тесты.
5. **Идентификаторы**: H2 по умолчанию upper-case (`DATABASE_TO_LOWER=TRUE` меняет).
6. **`SERIAL` в H2** — не настоящий sequence с теми же правами.
7. **Транзакции в H2** упрощены: `SERIALIZABLE` не даёт SSI-гарантий.
8. **Derby не поддерживает MVCC** — читатели ждут писателей.
9. **Тесты на H2 не ловят ошибки миграций** (типы, индексы, ограничения) — только Testcontainers.

## Что проверить руками

```sql
-- H2
SELECT H2VERSION();
SELECT SETTING_NAME, SETTING_VALUE FROM INFORMATION_SCHEMA.SETTINGS;
EXPLAIN SELECT * FROM orders WHERE user_id = 42;

-- HSQLDB
SELECT * FROM INFORMATION_SCHEMA.SYSTEM_PROPERTIES;
SET DATABASE SQL SYNTAX PGS TRUE;

-- Derby
VALUES SYSCS_UTIL.SYSCS_CHECK_TABLE('APP', 'ORDERS');
```
