# Планировщик и диагностика

## Зачем это нужно

Планы запросов выглядят похоже, но **инструменты** и **рычаги влияния** различаются радикально. В PG вы правите статистику и запрос; в Oracle — hints и baselines; в SQL Server — Query Store; в MySQL — индексы и `optimizer_switch`. Если искать «`pg_stat_statements`» в Oracle, ничего не выйдет.

## Как устроен оптимизатор

| | PostgreSQL | MySQL | SQL Server | Oracle |
|---|---|---|---|---|
| Тип | cost-based, dynamic programming | cost-based, heuristic + cost | cost-based | cost-based |
| Статистика | `pg_statistic`/`pg_stats`, extended stats | `mysql.innodb_table_stats`, histograms 8.0 | auto stats + filtered stats | `DBMS_STATS` |
| Гистограммы | да (`default_statistics_target`) | да (8.0) | да | да |
| Extended statistics | `CREATE STATISTICS` | нет (multi-column в 8.0?) | нет | да (column groups) |
| Управление планом | `enable_*`, `pg_hint_plan` | hints, `optimizer_switch`, `INDEX` hints | Query Store forcing, hints | hints, SPM baselines, profiles |
| Параллелизм | workers | parallel query 8.0 | MAXDOP | parallel execution |

## Основной инструмент: «EXPLAIN»

| Задача | PostgreSQL | MySQL | SQL Server | Oracle |
|---|---|---|---|---|
| План без выполнения | `EXPLAIN` | `EXPLAIN` | estimated plan | `EXPLAIN PLAN FOR` |
| План с выполнением | `EXPLAIN (ANALYZE, BUFFERS)` | `EXPLAIN ANALYZE` (8.0.18+) | actual plan + `SET STATISTICS IO, TIME ON` | `DBMS_XPLAN.DISPLAY_CURSOR(..., 'ALLSTATS LAST')` |
| Детали | `BUFFERS`, `SETTINGS`, `WAL` | `FORMAT=JSON`, `FORMAT=TREE` | XML/showplan | `ALLSTATS`, `ADVANCED` |
| Визуализация | pev2, explain.depesz | MySQL Workbench | SSMS, SentryOne | SQL Developer, OEM |

## Топ запросов

| | PostgreSQL | MySQL | SQL Server | Oracle |
|---|---|---|---|---|
| Штатное | `pg_stat_statements` | `performance_schema.events_statements_summary_by_digest` | Query Store | AWR / ASH |
| Медленные | `log_min_duration_statement` | slow query log | Extended Events | `SQL_TRACE`, `DBMS_MONITOR` |
| Планы | `auto_explain` | `performance_schema` (нет планов) | Query Store (планы) | AWR (`DBA_HIST_SQL_PLAN`) |
| Ожидания | `pg_stat_activity.wait_event` | `performance_schema.events_waits_*` | `sys.dm_os_wait_stats` | `V$SESSION.event`, ASH |

## Активность и блокировки

| | PostgreSQL | MySQL | SQL Server | Oracle |
|---|---|---|---|---|
| Сессии | `pg_stat_activity` | `SHOW PROCESSLIST`, `performance_schema.threads` | `sys.dm_exec_requests`, `sys.dm_exec_sessions` | `V$SESSION` |
| Блокировки | `pg_locks`, `pg_blocking_pids` | `performance_schema.data_locks`, `sys.innodb_lock_waits` | `sys.dm_tran_locks` | `V$LOCK`, `DBA_WAITERS` |
| Убить | `pg_terminate_backend` | `KILL <id>` | `KILL <spid>` | `ALTER SYSTEM KILL SESSION` |
| Deadlock | лог `deadlock detected` | `SHOW ENGINE INNODB STATUS` (LATEST DETECTED) | system_health XE | alert log / `V$DEADLOCK` |

## Рычаги влияния: что реально меняет план

### PostgreSQL

```sql
-- Статистика
ALTER TABLE t ALTER COLUMN c SET STATISTICS 1000;
ANALYZE t;
CREATE STATISTICS st (dependencies, mcv) ON a, b FROM t;

-- Стоимость
SET random_page_cost = 1.1;      -- SSD
SET effective_cache_size = '12GB';

-- Только для диагностики
SET enable_seqscan = off;
SET enable_nestloop = off;
```

### MySQL

```sql
ANALYZE TABLE t UPDATE HISTOGRAM ON c WITH 100 BUCKETS;   -- 8.0
SET optimizer_switch = '...';
SELECT /*+ INDEX(t idx) */ ...;                            -- hints 8.0
EXPLAIN FORMAT=JSON SELECT ...;                            -- стоимость и переписанный запрос
```

### SQL Server

```sql
-- Query Store: зафиксировать план
EXEC sp_query_store_force_plan @query_id = 1, @plan_id = 2;

SET STATISTICS IO, TIME ON;
SELECT * FROM sys.dm_exec_query_stats ORDER BY total_worker_time DESC;

-- Parameter sniffing
OPTION (RECOMPILE), OPTION (OPTIMIZE FOR (@p = 1))
```

### Oracle

```sql
-- SPM baseline
EXEC DBMS_SPM.LOAD_PLANS_FROM_CURSOR_CACHE(sql_id => 'abc123');

-- Hint
SELECT /*+ INDEX(t idx) USE_NL(t) */ ... FROM t;

EXEC DBMS_STATS.GATHER_TABLE_STATS('APP','T');
```

## Что общего

1. **Cost-based** везде (кроме эвристик MySQL).
2. **Статистика решает** — расхождение `rows` vs `actual rows` ищется везде.
3. **`EXPLAIN` есть везде**, но опции и формат разные.
4. **Топ запросов** — отдельное расширение/модуль, не встроено «в ядро».
5. **Hints — крайняя мера** (но в Oracle — часть культуры).

## Грабли и мифы

1. **`cost` в PG и Oracle — разные единицы**, сравнивать между СУБД нельзя.
2. **MySQL долго не имел `EXPLAIN ANALYZE`** (до 8.0.18) — старые статьи вводят в заблуждение.
3. **SQL Server `actual plan` показывает реальные строки**, но при `SET STATISTICS` есть overhead.
4. **Oracle hints могут игнорироваться**, если противоречат друг другу; baseline надёжнее.
5. **`pg_stat_statements` требует `shared_preload_libraries`** + рестарт.
6. **Query Store в SQL Server** нужно включить явно (`ALTER DATABASE ... SET QUERY_STORE = ON`).
7. **AWR в Oracle — платная опция** (Diagnostics Pack); без неё — `V$`-вьюхи и statspack.
8. **`EXPLAIN` без `ANALYZE`** — оценка, а не реальность; везде.
