## Матрица «одной строкой»

| СУБД | Хранение | MVCC / очистка | Журнал | Изоляция по умолчанию | Диагностика |
|---|---|---|---|---|---|
| **PostgreSQL** | heap + отдельные индексы, 8 КБ | версии в heap, `VACUUM` | WAL + checkpoint | Read Committed | `EXPLAIN`, `pg_stat_statements` |
| **MySQL/InnoDB** | clustered PK, 16 КБ | undo + purge | redo + doublewrite + binlog | Repeatable Read | `EXPLAIN ANALYZE`, `performance_schema` |
| **SQL Server** | heap или clustered, 8 КБ | блокировки; RCSI → tempdb | txn log + VLF | Read Committed | Query Store, DMV |
| **Oracle** | heap/IOT, блоки 8 КБ | undo + SCN | redo + archive | Read Committed | AWR/ASH, `DBMS_XPLAN` |
| **Db2** | tablespace + buffer pool | локи / currently committed | circular/archival log | Cursor Stability | `db2exfmt`, `MON_GET_*` |
| **SQLite** | B-tree в одном файле | WAL/rollback journal | journal / WAL | Serializable (один писатель) | `EXPLAIN QUERY PLAN` |
| **Firebird** | MGA, версии в файле | sweep | нет отдельного WAL | Snapshot | `EXPLAIN`, trace |
| **HANA** | in-memory column store | delta/merge | redo + savepoint | Read Committed | `EXPLAIN`, plan cache |
| **CockroachDB** | Raft-диапазоны | MVCC-таймстампы + GC | Raft log | Serializable | `EXPLAIN (DIST)` |
| **Spanner** | Paxos-сплиты | TrueTime + MVCC | Paxos log | Serializable (external) | query plan |
| **Aurora** | PG/MySQL + отделённое хранилище | как в PG/MySQL | redo в storage | как в PG/MySQL | как в PG/MySQL |
| **Redshift** | колоночный MPP | нет OLTP-транзакций | WAL сегментов | Serializable | `EXPLAIN`, SVL/SVV |
| **Snowflake** | micro-partitions | время + MVCC файлов | метаданные | Read Committed | Query Profile |
| **DuckDB** | колоночный in-process | один писатель | WAL | Serializable | `EXPLAIN ANALYZE` |

## Что общего у всех

1. **Страничная организация** (кроме in-memory): чтение и запись блоками 4–32 КБ.
2. **B-tree как основной индекс** (кроме колоночных MPP).
3. **Журнал упреждающей записи** или его аналог для durability.
4. **Cost-based optimizer** со статистикой; почти везде есть аналоги `EXPLAIN`.
5. **MVCC или блокировки** для конкурентности; разница — где хранятся старые версии.
6. **Репликация через журнал изменений** (redo, binlog, Raft log).

## Главные оси различий

| Ось | Варианты |
|---|---|
| Где живут данные | heap + индексы (PG) ↔ clustered index (MySQL, SQL Server) ↔ колоночные партиции (MPP) |
| Где живут старые версии | heap (PG) ↔ undo (InnoDB, Oracle) ↔ tempdb (SQL Server RCSI) ↔ файл (Firebird) |
| Кто чистит мусор | `VACUUM` (PG) ↔ purge (InnoDB) ↔ undo retention (Oracle) ↔ ghost cleanup (SQL Server) ↔ sweep (Firebird) |
| Как достигается сериализуемость | SSI (PG) ↔ gap locks (MySQL RR) ↔ snapshot + ошибка (Oracle) ↔ range locks (SQL Server) |
| Чем управляют DBA | параметры + статистика (PG) ↔ hints и baselines (Oracle) ↔ Query Store (SQL Server) |
