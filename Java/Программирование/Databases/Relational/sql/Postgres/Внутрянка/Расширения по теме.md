# Расширения по теме

## Зачем это нужно

Встроенных средств PostgreSQL хватает не на всё: планы запросов, ожидания, bloat, триграммы, геометрия, векторы. Расширения — штатный способ добавить функциональность без форка. Здесь — те, что реально нужны при работе с производительностью, и как их ставить.

## Как устроено

### Установка

```sql
CREATE EXTENSION pg_stat_statements;         -- в БД
SELECT * FROM pg_available_extensions;       -- что доступно в системе
```

Часть расширений требует `shared_preload_libraries` (только в `postgresql.conf` + **рестарт**):

```conf
shared_preload_libraries = 'pg_stat_statements,auto_explain,pg_stat_kcache,pg_wait_sampling,pg_qualstats'
```

Остальные — просто `CREATE EXTENSION` (нужны права суперпользователя или установленный пакет ОС).

Наборы:

```bash
# Debian/Ubuntu
apt install postgresql-18-postgresql-contrib
# или отдельные: postgresql-18-pg-stat-statements и т.д.
```

## Что видно в psql

### Диагностика запросов

| Расширение | Что даёт | Preload |
|---|---|---|
| **pg_stat_statements** | агрегированная статистика запросов: время, вызовы, буферы, WAL | да |
| **auto_explain** | автоматический `EXPLAIN ANALYZE` в лог для медленных запросов | да |
| **pg_stat_kcache** | CPU (user/system) и реальный I/O по запросам | да |
| **pg_wait_sampling** | сэмплирование `wait_event` по бэкендам | да |
| **pg_qualstats** | какие условия (`WHERE`) выполняются чаще всего | да |
| **pg_store_plans** | сохранение планов запросов | да |
| **hypopg** | «гипотетические» индексы: проверить план без создания | нет |
| **pg_hint_plan** | хинты в SQL (крайняя мера) | да |

`hypopg` — недооценённый инструмент:

```sql
CREATE EXTENSION hypopg;

SELECT * FROM hypopg_create_index('CREATE INDEX ON orders (user_id, created_at DESC)');
EXPLAIN SELECT * FROM orders WHERE user_id = 42 ORDER BY created_at DESC LIMIT 10;
-- план уже с гипотетическим индексом, реального индекса нет
SELECT hypopg_drop_index(indexrelid) FROM hypopg_list_indexes;
-- или сразу все:
SELECT hypopg_reset();
```

Позволяет проверить гипотезу «поможет ли индекс» без 20-минутного `CREATE INDEX CONCURRENTLY`.

### Внутренности и диагностика хранения

| Расширение | Что даёт |
|---|---|
| **pageinspect** | сырые страницы: `heap_page_items`, `bt_page_stats`, `page_header` |
| **pgstattuple** | точный bloat: `pgstattuple`, `pgstattuple_approx`, `pgstatindex` |
| **pg_visibility** | карта видимости: какие страницы all-visible/all-frozen |
| **amcheck** | проверка целостности B-tree (`bt_index_check`, `bt_index_parent_check`) |
| **pg_walinspect** (PG15+) | чтение содержимого WAL |
| **pg_buffercache** | что лежит в `shared_buffers` |
| **pg_prewarm** | прогрев кэша после рестарта |

```sql
CREATE EXTENSION pgstattuple;
SELECT * FROM pgstattuple_approx('orders');
-- table_len, scanned_percent, approx_tuple_count, dead_tuple_count, free_percent

CREATE EXTENSION amcheck;
SELECT bt_index_check('orders_pkey', true);   -- проверка структуры
```

### Текстовый поиск и нечёткий поиск

| Расширение | Что даёт |
|---|---|
| **pg_trgm** | триграммы: `LIKE '%…%'`, `%similarity%`, GIN/GiST |
| **unaccent** | удаление диакритики |
| **fuzzystrmatch** | `levenshtein`, `soundex`, `metaphone` |
| **pg_catalog.ru** / **hunspell** | словари для `tsvector` |

```sql
CREATE EXTENSION pg_trgm;
CREATE INDEX ON users USING gin (name gin_trgm_ops);
SELECT * FROM users WHERE name ILIKE '%иван%';   -- теперь по индексу
```

### Данные и типы

| Расширение | Что даёт |
|---|---|
| **pgcrypto** | хэши, шифрование; `gen_random_uuid()` встроен с PG13 |
| **uuid-ossp** | `uuid_generate_v4()` (устаревает в пользу встроенного) |
| **hstore** | key-value в одной колонке (до `jsonb` был основным) |
| **ltree** | иерархические пути (`a.b.c`) с GiST |
| **cube**, **earthdistance** | многомерные кубы, расстояния |
| **PostGIS** | геоданные: типы, индексы GiST/SP-GiST, функции |
| **pgvector** | векторы и ANN-поиск (эмбеддинги) |
| **TimescaleDB** | гипертаблицы, сжатие, continuous aggregates |
| **Citus** | шардирование и распределённые запросы |
| **pg_partman** | автоматическое управление партициями (создание/удаление) |

### Обслуживание

| Расширение | Что даёт |
|---|---|
| **pg_repack** | онлайн-удаление bloat (вместо `VACUUM FULL`) |
| **pg_squeeze** | альтернатива pg_repack |
| **pg_cron** | планировщик задач внутри БД (`VACUUM`, `ANALYZE`, отчёты) |
| **pgaudit** | аудит запросов (compliance) |
| **postgres_fdw** | доступ к внешним PostgreSQL |
| **dblink** | старый способ межбазовых запросов |
| **oracle_fdw / mysql_fdw** | федерация к другим СУБД |

```sql
-- pg_cron: ежедневный VACUUM в 3:00
SELECT cron.schedule('nightly-vacuum', '0 3 * * *', 'VACUUM (ANALYZE) big_table');
```

### Мониторинг-стек

- **postgres_exporter** — не расширение, а отдельный процесс, отдаёт `pg_stat_*` в Prometheus.
- **pgwatch2 / pgwatch** — готовый мониторинг.
- **pg_profile / pg_stat_monitor** (Percona) — альтернативы `pg_stat_statements`.

## Грабли и мифы

1. **`CREATE EXTENSION` не работает без пакета в ОС** — сначала `apt install postgresql-18-…-contrib`.
2. **`shared_preload_libraries` требует рестарта**, `CREATE EXTENSION` — нет (но расширение должно быть в списке).
3. **`pg_stat_statements.max`** (default 5000) ограничивает число отслеживаемых запросов; при переполнении старые вытесняются.
4. **`pg_stat_statements.track = all`** добавляет накладные расходы на вложенные запросы (функции/триггеры).
5. **`hypopg` не заменяет реальный индекс**: он не учитывает стоимость записи и bloat.
6. **`pg_hint_plan` — крайняя мера.** Если план плохой, сначала поправь статистику/запрос; хинты ломаются при изменении данных.
7. **`pg_repack` требует свободного места** ≈ размер таблицы и не работает с таблицами без PK/unique.
8. **`pg_trgm` GIN-индекс дорог на запись**; для больших текстов ищи баланс с GiST или `tsvector`.

## Эксперимент

```sql
-- 1. Проверить, что загружено
SHOW shared_preload_libraries;
SELECT name, default_version, installed_version
FROM pg_available_extensions
WHERE name IN ('pg_stat_statements','pgstattuple','pg_trgm','hypopg','pg_repack');

-- 2. pgstattuple: реальный bloat
CREATE EXTENSION IF NOT EXISTS pgstattuple;
SELECT table_len, dead_tuple_count, dead_tuple_len, free_percent
FROM pgstattuple_approx('bloat_demo');

-- 3. pg_trgm: ускорить LIKE '%…%'
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE INDEX trgm_idx ON users USING gin (name gin_trgm_ops);
EXPLAIN (ANALYZE, BUFFERS) SELECT * FROM users WHERE name ILIKE '%иван%';

-- 4. hypopg: проверить индекс без создания
CREATE EXTENSION IF NOT EXISTS hypopg;
SELECT * FROM hypopg_create_index('CREATE INDEX ON orders (status)');
EXPLAIN SELECT * FROM orders WHERE status = 'paid';
```
