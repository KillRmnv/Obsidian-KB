# Медленный запрос — 10 шагов

Короткий чек-лист на один экран. Подробности — в [[Оптимизация/Методика разбора медленного запроса]].

---

## 1. Убедись, что проблема в БД, а не в приложении

- запрос долгий в `pg_stat_activity` или только в APM?
- нет ли N+1 (тысячи одинаковых запросов)?
- нет ли ожидания соединения из пула?

```sql
SELECT pid, state, wait_event_type, wait_event, now() - query_start AS q_age, left(query, 80)
FROM pg_stat_activity WHERE state = 'active' ORDER BY q_age DESC;
```

## 2. Найди запрос

```sql
SELECT queryid, calls, round(total_exec_time::numeric,1) total_ms,
       round(mean_exec_time::numeric,2) mean_ms, rows, left(query, 100)
FROM pg_stat_statements ORDER BY total_exec_time DESC LIMIT 10;
```

## 3. Сними план

```sql
EXPLAIN (ANALYZE, BUFFERS, SETTINGS) <запрос>;
```

## 4. Сравни оценку и реальность

Ищи `rows=` (оценка) vs `actual rows=`. Расхождение > 10× — почти всегда причина.

## 5. Найди самый дорогой узел

`actual time × loops`. Не смотри только на верхнюю строку.

## 6. Проверь I/O

`Buffers: read` большой? `track_io_timing=on` покажет время. `pg_stat_io` — кто читает.

## 7. Проверь память

- `Sort Method: external merge` → мало `work_mem`;
- `Hash ... Batches: >1` → хэш не влез;
- `temp_blks_written` в `pg_stat_statements`.

## 8. Проверь блокировки

```sql
SELECT pid, pg_blocking_pids(pid), wait_event, left(query, 60)
FROM pg_stat_activity WHERE cardinality(pg_blocking_pids(pid)) > 0;
```

## 9. Проверь статистику и индекс

```sql
SELECT attname, n_distinct, correlation FROM pg_stats WHERE tablename = '...';
SELECT indexrelname, idx_scan FROM pg_stat_user_indexes WHERE relname = '...';
ANALYZE <таблица>;
```

Индекс не работает? → [[Шпаргалки/Индекс не работает — 12 причин]].

## 10. Проверь гипотезу и закрепи

- одна правка за раз;
- `SET LOCAL work_mem` / `enable_seqscan=off` — только для проверки;
- после — миграция с индексом/статистикой, метрика, запись в заметку.

---

## Быстрые решения по симптому

| Симптом в плане | Что делать |
|---|---|
| `Seq Scan` на большой таблице с селективным фильтром | индекс / sargable-условие / `ANALYZE` |
| `Nested Loop` с `loops` > 10000 | hash join (индекс/статистика/переписать) |
| `rows=1`, `actual rows=100000` | `ANALYZE`, `CREATE STATISTICS` |
| `Sort Method: external merge` | `work_mem` локально или индекс под `ORDER BY` |
| `Hash ... Batches: 4` | `work_mem` или меньший build side |
| `Rows Removed by Filter: 999000` | индекс под фильтр или partial index |
| `Heap Fetches: 100000` | `VACUUM` (VM) или `INCLUDE` |
| `CTE Scan` на большом CTE | `NOT MATERIALIZED` / переписать |
| `JIT` с большим `Timing` | `SET jit = off` для OLTP |
| `Lock` wait | [[Внутрянка/Конкурентность на практике]] |
