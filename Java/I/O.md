## Байтовые и символьные потоки

**Байтовые потоки** — работают с сырыми байтами (`8` бит). Базовые абстракции:

- `InputStream` — источник байт
    
- `OutputStream` — приёмник байт
    

Их используют для:

- бинарных форматов (изображения, PDF, ZIP);
    
- сетевых сокетов;
    
- низкоуровневого I/O.
    

**Символьные потоки** — работают с `char`/`String` (UTF-16 в Java). Базовые абстракции:

- `Reader` — источник символов
    
- `Writer` — приёмник символов
    

Они поверх байтовых, добавляют **декодирование/кодирование** по charset.

Типичные пары-"мосты":

- `InputStreamReader` — `InputStream` → `Reader` (байты → символы с учётом кодировки);
    
- `OutputStreamWriter` — `Writer` → `OutputStream` (символы → байты).
    

Подводка для собеса:

- Символьные API удобнее для текстов (лог-файлы, JSON, CSV), но всегда помни про **кодировку**: по умолчанию платформа (может отличаться на разных серверах). Явно задавай `StandardCharsets.UTF_8`.

## InputStream / OutputStream, Reader / Writer

## InputStream / OutputStream

Основные подклассы:

- `FileInputStream`, `FileOutputStream` — работа с файлами на уровне байтов;
    
- `BufferedInputStream`, `BufferedOutputStream` — буферизация для снижения количества системных вызовов;
    
- `ByteArrayInputStream`, `ByteArrayOutputStream` — I/O в памяти;
    
- `DataInputStream`, `DataOutputStream` — читают/пишут примитивы в бинарном формате;
    
- `ObjectInputStream`, `ObjectOutputStream` — для сериализации объектов.
    

Ключевые методы:

- `read()` / `read(byte[])` / `read(byte[], off, len)` — возвращает количество прочитанных байт или `-1` при конце;
    
- `write(int b)` / `write(byte[])` / `write(byte[], off, len)`;
    
- `flush()` — сброс буфера в реальный поток.
    

Основной практический момент: **всегда** оборачивать неблокирующие или дорогие источники/приёмники в буферизацию (`Buffered...`), иначе будет много мелких системных вызовов.

## Reader / Writer

Основные подклассы:

- `FileReader`, `FileWriter` — текстовые файлы (но лучше `InputStreamReader`/`OutputStreamWriter` с явной кодировкой);
    
- `BufferedReader`, `BufferedWriter` — буфер + удобные методы (`readLine()`, `newLine()`);
    
- `CharArrayReader`, `CharArrayWriter`;
    
- `StringReader`, `StringWriter`.
    

Подводные камни:

- `FileReader`/`FileWriter` используют _дефолтную_ кодировку платформы — на бэкенде лучше всегда указывать `Charset`, чтобы не ловить сюрпризы при переносе.
    
- Никогда не забывай `flush()` перед `close()` у `Writer`/`OutputStream`, если пишешь в сети/файлы (хотя `close()` обычно сам вызывает `flush()`).

## NIO / NIO.2: Path, Files, Channels

## Зачем вообще NIO

NIO (New I/O) добавляет:

- **буфер + канал** (Channel/Buffer) вместо потоков (stream);
    
- неблокирующий и мультиплексированный I/O;
    
- более удобную работу с файловой системой (NIO.2).
    

Философия:

- IO (старый) — "поток ориентирован" (stream-oriented);
    
- NIO — "буфер ориентирован" (buffer-oriented).
    

## Path и Files (NIO.2)

NIO.2 (Java 7+):

- `Path` — замена `java.io.File` как абстракция пути;
    
- `Paths.get(...)` / `Path.of(...)` — создание;
    
- `Files` — утилитарный класс c **статическими методами** для работы с файлами/директориями.
    

Примеры задач:

- проверка/создание:
    
    - существует ли файл/директория (`Files.exists`, `isDirectory`, `isRegularFile`);
        
    - создать (`createFile`, `createDirectories`);
        
- копирование/перемещение/удаление (`copy`, `move`, `delete`);
    
- чтение/запись:
    
    - весь файл в память (`readAllBytes`, `readAllLines`);
        
    - потоками (`newBufferedReader`, `newBufferedWriter`, `newInputStream`).
        

Особенность:

- `Path` инкапсулирует особенности ОС (разделители, корни пути);
    
- `Files.walk`, `Files.list` дают стримы путей — удобно для рекурсивных обходов.
    

## Channels и Buffers

- `Channel` — двунаправленный канал к ресурсу (файл, сокет): `FileChannel`, `SocketChannel`, `DatagramChannel`.
    
- `ByteBuffer` и его родственники — контейнеры для чтения/записи фиксированных блоков байт.
    

Идиома: `channel.read(buffer)` → обработать `buffer` → `buffer.clear()`/`flip()` для следующего цикла.

Преимущества:

- Возможность неблокирующего I/O (`SelectableChannel + Selector`);
    
- zero-copy (`FileChannel.transferTo/transferFrom`).
    

На собесах обычно достаточно:

- понимать разницу stream vs channel (байт за байтом vs блоками через Buffer);
    
- знать, что NIO.2 (`Path`, `Files`) заменяет многие операции `File`.

## Сериализация: Serializable и transient

## Serializable

Интерфейс-маркер `Serializable`:

- без методов;
    
- сигнализирует JVM, что объект можно сериализовать стандартным механизмом Java-объектов (`ObjectOutputStream`/`ObjectInputStream`).
    

Как работает:

- при сериализации пишется класс + состояние (поля);
    
- при десериализации создаётся объект **без вызова обычных конструкторов** (обходит их с помощью низкоуровневых механизмов).
    

Можно кастомизировать:

- `private void writeObject(ObjectOutputStream oos)` и `private void readObject(ObjectInputStream ois)` — для ручного контроля;
    
- `serialVersionUID` — версия класса для совместимости (если она меняется, а `serialVersionUID` нет — возможны `InvalidClassException` или наоборот, несовместимые классы проходят).
    

Важно: сериализация сохраняет **граф объектов** (включая все доступные по ссылкам, если те тоже `Serializable`), с защитой от циклов.

## transient

`transient` помечает поля, которые **не должны сериализоваться**:

- пароли, секретные ключи;
    
- кэши, вычисляемые поля;
    
- небезопасные для сохранения ресурсы (сокеты, потоки, пуллы).
    

При десериализации `transient` поля получают значения по умолчанию (`null`/`0`/`false`) или то, что ты им задашь в `readObject`.

## Подводные камни сериализации

- **Security**: десериализация произвольных данных может создать объекты с опасным состоянием → RCE/DoS (классический вектор атак). В проде часто запрещают нативную Java-сериализацию и используют JSON/Protobuf/Avro.
    
- **Хрупкость к изменениям классов**: добавление/удаление полей ломает бинарную совместимость, если `serialVersionUID` не контролировать.
    
- **Производительность**: стандартная сериализация довольно тяжёлая и шумная для GC.
