`assert` в Java — это ключевое слово для **проверки внутренних предположений в коде во время разработки**. Оно проверяет логическое выражение, и если оно ложно, выбрасывает `AssertionError` и, как правило, аварийно завершает программу или тест.itsobes+3

## Как работает assert

Синтаксис:

java

`assert condition; assert condition : message;`

- `condition` — выражение типа `boolean`.
    
- Если `condition == false`, JVM выбрасывает `java.lang.AssertionError`.
    
- Вторая форма передаёт `message` (любой объект, чаще строку) в конструктор `AssertionError`:ievetrov+2
    

java

`int x = computeValue(); assert x > 0 : "x must be positive, got " + x;`

По сути, это сокращённая форма:

java

`if (!condition) {     throw new AssertionError(message); }`

## Включение и отключение assert

По умолчанию проверки `assert` **выключены** для сохранения обратной совместимости со старым кодом. Логика работы программы никогда не должна на них опираться.itsobes+2

Чтобы включить:

bash

`java -ea MyApp              # то же, что -enableassertions java -ea:com.example...     # включить для пакета java -da:com.example...     # отключить для пакета (-disableassertions)`

Если запустить без `-ea`, даже `assert false;` ничего не сделает — код с ассертами просто игнорируется.habr+2

## Для чего применять assert

Ассерты используют главным образом для **поиска ошибок программиста**, а не для проверки пользовательского ввода:habr+2

- проверка инвариантов класса (состояние объекта, которое "всегда должно быть верным");
    
- проверка "невозможных" веток кода (например, `default` в `switch`, который не должен достигаться);
    
- внутренние дополнительные проверки в приватных методах, при работе с собственным кодом.reddit+2
    

Ошибки `AssertionError` трактуются как баги в коде, а не как валидируемые бизнес‑ошибки.hexlet+2
