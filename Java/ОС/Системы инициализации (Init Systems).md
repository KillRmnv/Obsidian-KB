## Что такое система инициализации

**Init** (сокращение от initialization) — это первая программа, которая запускается ядром после загрузки. Она является "прародителем" всех остальных процессов в системе (ее PID всегда равен 1).

Основные задачи системы инициализации:
- Запуск системных служб (демонов) на этапе загрузки
- Управление службами (запуск, остановка, перезапуск, мониторинг)
- Обработка сигналов и перезапуск упавших служб
- Логирование и контроль состояния системы

---

## Сравнение основных систем инициализации

| Характеристика | sysvinit | OpenRC | runit | systemd |
|----------------|----------|--------|-------|---------|
| **Архитектура** | Монолитная (последовательный запуск) | Модульная | Минималистичная (на основе каталогов) | Монолитная с модулями |
| **Скорость загрузки** | Низкая | Высокая | Высокая | Высокая |
| **Сложность** | Низкая | Средняя | Низкая | Высокая |
| **Настраиваемость** | Средняя | Высокая | Высокая | Ограниченная (сложная) |
| **Логирование** | Отсутствует (syslog) | Отсутствует (syslog) | Встроенное (runsvdir) | Встроенное (journald) |
| **Мониторинг служб** | Нет | Нет | Да (автоматический перезапуск) | Да (Restart=) |
| **Зависимости** | Статические (runlevel) | Статические (rc-update) | Динамические (каталоги) | Декларативные (unit files) |
| **Сессии пользователей** | Нет | Нет | Нет | Да (logind) |
| **Таймеры** | Нет (cron) | Нет (cron) | Нет (cron) | Да (systemd timers) |
| **Параллелизм** | Нет | Да | Да | Да |

## 1. sysvinit (System V init)

Классическая система инициализации, основанная на UNIX System V.

### Особенности
- **Последовательный запуск**: службы запускаются одна за другой
- **Runlevels**: предопределенные состояния системы (0-6)
- **Скрипты** в `/etc/init.d/` (bash-скрипты)
- Каждый скрипт отвечает за запуск/остановку одной службы

### Символические ссылки
В `/etc/rc<runlevel>.d/` хранятся ссылки на скрипты:
- `S##<имя>` — запуск службы (старт)
- `K##<имя>` — остановка службы (стоп)
- `##` — порядок запуска (числовой)

### Команды
| Команда | Назначение |
|---------|------------|
| `service <имя> start/stop/restart` | Управление службой |
| `/etc/init.d/<имя> start/stop` | Альтернативный синтаксис |
| `update-rc.d <имя> enable/disable` | Включение/отключение автозагрузки |

### Плюсы
- Простая и понятная архитектура
- Широко распространена (исторически)
- Минималистичная

### Минусы
- Очень медленная загрузка
- Нет параллельного запуска
- Сложное управление зависимостями
- Много дублирования в скриптах
- Не перезапускает службы при падении

### Где используется
- Debian/Ubuntu до версии 6 (заменен на systemd)
- Встроенные системы (BusyBox)
- Некоторые минималистичные дистрибутивы

## 2. OpenRC

Система инициализации, разработанная в рамках проекта Gentoo.

### Особенности
- **Параллельный запуск** служб (если позволяют зависимости)
- **Зависимости** описываются в скриптах (`need`, `use`, `after`, `before`)
- **Скрипты** в `/etc/init.d/` (совместимы с sysvinit)
- Модульная архитектура (можно использовать только части)

### Файл службы
```bash
#!/sbin/openrc-run

description="Моя служба"

command="/usr/bin/my-daemon"
command_args="--daemon"

depend() {
    need net
    use dns
}
```

### Команды
| Команда | Назначение |
|---------|------------|
| `rc-service <имя> start/stop/restart` | Управление службой |
| `rc-update add <имя> <runlevel>` | Добавить в автозагрузку |
| `rc-update del <имя> <runlevel>` | Убрать из автозагрузки |
| `rc-update show` | Показать все службы в автозагрузке |
| `openrc` | Перезапустить OpenRC |

### Плюсы
- Быстрее, чем sysvinit
- Поддерживает параллельный запуск
- Простые и читаемые скрипты
- Не зависит от systemd
- Работает на различных платформах
- Хорошее разрешение зависимостей

### Минусы
- Скрипты всё ещё сложные для новичков
- Нет встроенного логирования
- Нет мониторинга служб (автоматического перезапуска)
- Меньше функциональности, чем у systemd

### Где используется
- Gentoo (по умолчанию)
- Alpine Linux (по умолчанию)
- Artix Linux (опционально)
- Void Linux (до перехода на runit)

## 3. runit

Минималистичная система инициализации от разработчика daemontools.

### Особенности
- **Максимальная простота**: работает через каталоги
- **Автоматический перезапуск** упавших служб (по умолчанию)
- **Нет скриптов** — используются исполняемые файлы `run`
- **Каждый сервис** хранится в отдельном каталоге `/etc/sv/<имя>/`
- **Включённые службы** ссылаются из `/var/service/` (или `/run/service/`)

### Структура сервиса
```
/etc/sv/my-service/
├── run          # исполняемый файл (должен быть +x)
├── finish       # (опционально) выполняется при остановке
├── check        # (опционально) проверка состояния
├── log/         # (опционально) каталог для логирования
│   └── run      # (опционально) для обработки логов
└── supervise/   # создаётся автоматически (состояние процесса)
```

### Пример файла `run`
```bash
#!/bin/sh
exec /usr/bin/my-daemon --foreground
```

### Команды
| Команда | Назначение |
|---------|------------|
| `sv status <имя>` | Статус службы |
| `sv start <имя>` | Запустить службу |
| `sv stop <имя>` | Остановить службу |
| `sv restart <имя>` | Перезапустить службу (выполнить finish, затем run) |
| `sv reload <имя>` | Послать SIGHUP (перезагрузить конфиг) |
| `sv enable <имя>` | Добавить в автозагрузку |
| `sv disable <имя>` | Убрать из автозагрузки |
| `runsvdir <каталог>` | Мониторинг всех служб в каталоге |
| `runsvchdir` | Сменить каталог со службами (для смены runlevel) |

### Плюсы
- **Исключительно прост** и понятен
- **Надёжен** — службы перезапускаются при падении
- **Минималистичный** — делает только своё дело
- **Легко отлаживать** — всё видно в логах
- **Не зависит от других компонентов** (как systemd)
- **Быстрая загрузка**

### Минусы
- Меньше функциональности, чем у systemd (нет таймеров, сессий)
- Требует привыкания к другому подходу
- Меньше документации по сравнению с systemd
- Нет встроенного логирования (используются внешние программы)

### Где используется
- **Void Linux** (по умолчанию) — это основная причина его известности
- Artix Linux (опционально)
- Alpine Linux (опционально)
- Встроенные системы

## 4. systemd

Современная система инициализации и управления системой.

### Особенности
- **Декларативные unit-файлы** (конфигурация, не скрипты)
- **Параллельный запуск** служб
- **Встроенное логирование** (journald)
- **Мониторинг и перезапуск** служб (Restart=)
- **Таймеры** (замена cron)
- **Управление сессиями** (logind)
- **Сетевое управление** (networkd, resolved)
- **Монтирование** файловых систем (mount units)

### Файл службы (.service)
```ini
[Unit]
Description=Моя служба
After=network.target
Requires=network.target

[Service]
ExecStart=/usr/bin/my-daemon --daemon
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

### Типы unit-файлов
| Расширение | Назначение |
|------------|------------|
| `.service` | Системные службы |
| `.socket` | Сокеты для активации по запросу |
| `.timer` | Таймеры (замена cron) |
| `.mount` | Точки монтирования |
| `.target` | Группы целей (аналог runlevel) |
| `.path` | Активация по файловым событиям |
| `.slice` | Группы управления ресурсами |
| `.scope` | Внешние процессы |

### Команды
| Команда | Назначение |
|---------|------------|
| `systemctl start <имя>` | Запустить службу |
| `systemctl stop <имя>` | Остановить службу |
| `systemctl restart <имя>` | Перезапустить службу |
| `systemctl reload <имя>` | Перезагрузить конфигурацию |
| `systemctl status <имя>` | Статус службы |
| `systemctl enable <имя>` | Добавить в автозагрузку |
| `systemctl disable <имя>` | Убрать из автозагрузки |
| `systemctl daemon-reload` | Перечитать unit-файлы |
| `systemctl list-units` | Список активных юнитов |
| `systemctl list-unit-files` | Список всех юнитов |
| `systemctl isolate <target>` | Переключиться на target |
| `systemctl get-default` | Текущий target по умолчанию |
| `systemctl set-default <target>` | Установить target по умолчанию |

### Плюсы
- **Мощный и функциональный**
- **Быстрая загрузка** (параллелизм)
- **Встроенное логирование** (журнал централизован)
- **Единый интерфейс** для управления всем
- **Автоматический перезапуск** и восстановление
- **Мониторинг и контроль** ресурсов (cgroups)
- **Таймеры** — замена cron с большими возможностями
- **Активация по сокетам** и событиям (socket, path)
- **Управление зависимостями** (After/Before, Requires)

### Минусы
- **Сложный и монолитный** — делает слишком много
- **Нарушает принцип KISS** (Keep It Simple, Stupid)
- **Агрессивная интеграция** — сложно заменить отдельные части
- **Меньше переносимости** (привязан к Linux)
- **Сложная конфигурация** для новичков
- **Создаёт vendor lock-in** (незаметно заменяет другие компоненты)
- **Дискуссионный** — вызывает споры в сообществе

### Где используется
- **Большинство современных дистрибутивов**: Fedora, RHEL, Debian, Ubuntu, Arch Linux, openSUSE, SUSE Linux Enterprise
- **Везде** в корпоративной среде (стандарт де-факто)

## Сравнение подходов

| Аспект | sysvinit | OpenRC | runit | systemd |
|--------|----------|--------|-------|---------|
| **Ментальная модель** | Последовательный запуск | Зависимости и параллелизм | Процессы и каталоги | Декларативные юниты |
| **Конфигурация** | Bash-скрипты | Bash-скрипты (с зависимостями) | Исполняемые файлы | INI-файлы |
| **Сложность для пользователя** | Средняя | Средняя | Низкая | Высокая |
| **Сложность для разработчика** | Высокая | Средняя | Низкая | Высокая |
| **Количество строк кода** | Несколько тысяч | Несколько десятков тысяч | Несколько тысяч | Миллионы |
| **Философия** | Традиционная UNIX | Гибкость и модульность | Минимализм | Всё в одном |

## Философский спор

Существует острое противостояние между сторонниками **systemd** и **минималистичных init-систем** (runit, OpenRC, s6). Основные аргументы:

### За systemd
- Современный стандарт
- Решает реальные проблемы
- Активно развивается
- Широко поддерживается разработчиками ПО
- Упрощает управление сложными системами

### Против systemd
- Нарушает принцип "одна программа — одна задача"
- Слишком сложный и раздутый
- Пытается заменить существующие утилиты (cron, syslog, network)
- Создаёт привязку к экосистеме systemd
- Трудно заменить или модифицировать отдельные части
